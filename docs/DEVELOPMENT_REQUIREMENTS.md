# 개발 요구사항 통합 기록

기준: 2026-11-16 대화 전체와 2026-11-17 상권 매출 기간 확장 요구. 사용자 요구를 찾는 색인이며, 반복 적용할 구현·검수 규칙의 정본은 [DASHBOARD_DEVELOPMENT_RULES.md](DASHBOARD_DEVELOPMENT_RULES.md)이다. 이 문서의 `REQ-*`는 추적용 ID이며 기존 `R01–R20`을 대체하지 않는다. 요구사항 수록은 구현·검수 완료를 의미하지 않는다. [11/16 세션 기록](SESSION-WRAPUP-2026-11-16.md)은 당시 상태이며, 새 데이터·UI·공개 배포의 판정은 해당 변경 실행 기록과 독립 원문 검증으로 별도 확인한다.

## 제품 범위와 두 사용 트랙

현재 주목표는 서울 구·동 인구 분석과 상권 분석이다. 이용자는 광고업체의 실무 분석자와 광고주 현장 협의 참여자다. 미래의 수도권·지하철역·부동산 확장은 고려하되, 화면 재구성보다 현재 공간·가독성·동작 개선이 우선이다.

| 트랙 | 사용자가 하려는 일 | 성공 기준 | 공통 기반 |
|---|---|---|---|
| 실무 분석 | 조건을 바꾸고 분포·변화·구성을 비교하며 근거 확인 | 조회→결과→상세→다른 조건→지도 복귀가 이어짐 | 같은 자료·계산·조회 상태·상세 전환 |
| 광고주 현장 협의 | 현장에서 지역·시간·타깃·후보를 비교하고 결론 형성 | 큰 주정보와 필요한 상세를 자유롭게 왕복 | 분석용에서 파생, 별도 고정 발표 순서 강제 금지 |

사용자가 확정한 시연의 목적은 “광고주와 현장에서 비교하며 결론을 만드는 것이 중심”이다. 저장된 발표자료 제작·공동 편집·새 인증 서버는 이 요구만으로 확정하지 않는다.

## 화면 목적과 데이터 계약

| 자료 | 판단 질문 / 주정보 | 유용한 보조 표현 | 혼동 금지 |
|---|---|---|---|
| 생활인구 | 어느 지역에 어떤 대상이 언제 머무는가 / 구·동 분포 | 시간 추이, 두 시점, 연령·성별, 요일·월초/중/말 | 시점 추계 인원≠일 고유 방문자≠광고 노출 |
| 생활이동 | 어느 지역에서 언제 유입·유출되는가 | 상대 지역, 출발/도착 기준, 시간·누적 구분 | 이동 건수≠거주지 전입·전출; 반복 이동 가능 |
| 거주지 이동 | 거주 기반이 장기적으로 늘거나 줄었는가 | 전입·전출·순이동, 연도·지원 집단 비교 | 연간 자료를 일중 유입처럼 표현 금지 |
| 상권 인구·매출 | 어느 상권의 머무름·소비 수요가 큰가 | 분기 추이, 지원 업종·시간·성별·연령·요일 | 분기 지표를 일 방문객으로 임의 환산 금지 |

실제 지원 차원을 먼저 확인한다. 연령과 성별이 각각 존재해도 결합표가 없으면 교차 분석을 만들지 않는다. 직업·국내외 관광·출발 거주지 등의 관심 요구는 자료 확보·정의 확인 후 별도 지원 판단한다. 자료 없음·비공개·경계 불일치는 0과 구분한다.

## 개발 시 유의점

- 스크린샷 한 곳만 고치지 말고 공통 컴포넌트의 소비 화면을 추적한다. 모든 화면에 같은 UI를 강제하는 것과 같은 규칙을 적용하는 것은 다르다.
- 일반 지도 SVG와 버튼 아이콘 SVG를 구분한다. 광범위한 `svg` 크기 규칙은 거대 아이콘과 축 잘림을 만들었다.
- 고정 높이는 제목·조건 바 줄바꿈을 고려한 실제 잔여 높이로 계산한다. `height:100%`, native `details`, flex 축소, 포털의 조합은 실제 화면에서 확인한다.
- 포털 호스트 이동은 자식 상태 유지와 팝오버/초점 복귀를 함께 확인한다. ref 연결 시점·동일 속성 반복 쓰기 관찰 루프에 주의한다.
- 상단 기본 조회 바의 선택형 플로팅/우측 도킹은 같은 호스트의 이동이다. 새로 복제하거나 배치 변경을 조회 초기화로 취급하지 않는다. 지도540px를 남길 수 없으면 플로팅으로 유지하고 명확한 상단 복원 경로를 제공한다.
- 상권 조회 이동은 일반4자료의 동일 호스트 구조와 상권 정보 패널·상세/본문·우측 도킹이 충돌하는지 먼저 검토한다. 상권에서 실제 검수한 범위만 지원 완료로 표시하며, 구현 중인 기능을 전면 지원으로 보고하지 않는다.
- 공통 헤더를 한 행으로 줄일 때 상단 메뉴·자료4개·모드·상세 콤보의 발견성을 보존한다. 좁은 화면에서 한 행 형식만 맞추려고 글자를 줄이지 않는다.
- 설명을 툴팁으로 옮기는 것은 해석을 삭제하는 작업이 아니다. 생활이동 집계 선택과 설명 내용이 함께 바뀌는지, 출처·방법을 키보드로 읽고 결과로 복귀하는지 확인한다.
- 숨겨둔 지도/입력을 현재 활성 입력처럼 다루지 않는다. 닫힌 창의 중복 DOM/ID와 검색 팝오버 가림을 점검한다.
- 시연만 예전 CSS로 가리는 방식은 공통 상세 기능을 다시 끊을 수 있다. 모드 전환이 조건·상세를 초기화하지 않는지 검사한다.
- 빌드·단위시험 성공은 UI 품질 통과가 아니다. 독립 디자이너 검토와 현재 버전의 실제 조작 증거가 필요하다.

## 최신 변경의 판정 경계

조회 배치·설명 압축·헤더 요구는 REQ-04/05/16의 구체화와 REQ-20으로 추적한다. 이전의 ‘상단 기본 조회 바는 이동 대상이 아니다’라는 전제는 사용자 선택형 배치 요구로 대체한다. 상단 기본값과 단일 입력 원칙은 유지한다. 소스 수정 여부·실제 UI·공개 배포는 별도의 실행 보고로 확인하며 이 문서만으로 완료를 주장하지 않는다.

### 2026-11-17 상권 매출 기간 확장 관문

REQ-21은 공식2026년1·2분기 매출을 확보·검증해 기존2025 시계열에 추가하는 요구다. 현재 확보 수치·연결 범위·로컬/공개 판정은 [실행 기록](market-sales-2026-execution.md)과 [독립 원문 감사](market-sales-2026-audit.md)를 따른다. 메뉴에2026을 추가하거나 준비 파일을 생성한 사실만으로 실제 데이터 확보와 기능 완료를 판정하지 않는다.

1. **원문·기존값 보존:** 공식 다운로드 원문과 출처 URL·기준기간·수집시각·파일 식별 정보를 기록한다. 독립 검토자는 정제 결과와 별도로 원문에서 대표 코드·업종·분기·합계·결측을 확인한다. 기존2025 파일/레코드/합계/지원 차원은 비교 근거를 남기고 회귀 확인하며, 새 자료를 맞추기 위해 바꾸지 않는다.
2. **기간·소비자 연결:** 실제 확보된2026Q1/Q2만 지원 기간 목록에 포함한다. 상권 단위와 행정구역 단위 매출의 지원 기간은 각각 확인하며 한쪽 확장을 다른 쪽 지원으로 대체하지 않는다. 동일한 기간·자료·상권·업종·분석 기준이 입력·지도·정보·그래프·CSV·후보에 전달되어야 한다. 전년동기는 기준2025Q2→선택2026Q2를 명시하고, 직전 분기 비교와 혼동하지 않는다. null 또는 기준0의 비율/지수는 기존 정책대로 계산 불가를 설명한다.
3. **공간·해석 구분:**2026 매출 코드가 로컬 상권 경계 코드에 연결되는지와2023년 경계가2026 통계의 동일 형상인지는 별개다.2026-07-03 공식 공지의 원문·적용 범위·변경 설명을 확인하되, 공지일이나 코드 일치를 형상 동일성의 증거로 대체하지 않는다. 형상 동일성을 검증하지 못하면 그 한계를 결과·출처 설명에 남긴다.
4. **가공·캐시 검증:** null/비공개/미연결을0으로 대체하지 않고 성별·연령·요일·시간의 주변분포 합계가 총계와 다를 때 원문 차이를 기록한다. 총계에 맞추기 위한 임의 배분·스케일 조정은 금지한다. manifest의 지원 기간·파일/버전과 캐시 키를 함께 갱신하고, 이전 응답이 새 분기 제목 아래 남지 않게 한다.
5. **현재 실행·공개 판정:** 빌드/자료 검사와 독립 원문 대조, 현재 Chrome의 분석·시연 두 모드에서 기간 변경·전년동기·지도/추이/후보·CSV·복귀를 나누어 확인한다. Pages 배포 후 공개 목록·자산 버전·실제 값도 별도로 검수한다. 과거2025 실행 보고는 보존하며 새 기간의 검수로 소급하지 않는다.
