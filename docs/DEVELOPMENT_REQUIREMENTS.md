# 개발 요구사항 통합 기록

기준: 2026-11-16 대화 전체. 사용자 요구를 찾는 색인이며, 반복 적용할 구현·검수 규칙의 정본은 [DASHBOARD_DEVELOPMENT_RULES.md](DASHBOARD_DEVELOPMENT_RULES.md)이다. 이 문서의 `REQ-*`는 추적용 ID이며 기존 `R01–R20`을 대체하지 않는다. 요구사항 수록은 구현·검수 완료를 의미하지 않는다. 현재 진행 상태는 [세션 기록](SESSION-WRAPUP-2026-11-16.md)을 따른다.

## 제품 범위와 두 사용 트랙

현재 주목표는 서울 구·동 인구 분석과 상권 분석이다. 이용자는 광고업체의 실무 분석자와 광고주 현장 협의 참여자다. 미래의 수도권·지하철역·부동산 확장은 고려하되, 화면 재구성보다 현재 공간·가독성·동작 개선이 우선이다.

| 트랙 | 사용자가 하려는 일 | 성공 기준 | 공통 기반 |
|---|---|---|---|
| 실무 분석 | 조건을 바꾸고 분포·변화·구성을 비교하며 근거 확인 | 조회→결과→상세→다른 조건→지도 복귀가 이어짐 | 같은 자료·계산·조회 상태·상세 전환 |
| 광고주 현장 협의 | 현장에서 지역·시간·타깃·후보를 비교하고 결론 형성 | 큰 주정보와 필요한 상세를 자유롭게 왕복 | 분석용에서 파생, 별도 고정 발표 순서 강제 금지 |

사용자가 확정한 시연의 목적은 “광고주와 현장에서 비교하며 결론을 만드는 것이 중심”이다. 저장된 발표자료 제작·공동 편집·새 인증 서버는 이 요구만으로 확정하지 않는다.

## 화면 목적과 데이터 계약

| 자료 | 판단 질문 / 주정보 | 유용한 보조 표현 | 혼동 금지 |
|---|---|---|---|
| 생활인구 | 어느 지역에 어떤 대상이 언제 머무는가 / 구·동 분포 | 시간 추이, 두 시점, 연령·성별, 요일·월초/중/말 | 시점 추계 인원≠일 고유 방문자≠광고 노출 |
| 생활이동 | 어느 지역에서 언제 유입·유출되는가 | 상대 지역, 출발/도착 기준, 시간·누적 구분 | 이동 건수≠거주지 전입·전출; 반복 이동 가능 |
| 거주지 이동 | 거주 기반이 장기적으로 늘거나 줄었는가 | 전입·전출·순이동, 연도·지원 집단 비교 | 연간 자료를 일중 유입처럼 표현 금지 |
| 상권 인구·매출 | 어느 상권의 머무름·소비 수요가 큰가 | 분기 추이, 지원 업종·시간·성별·연령·요일 | 분기 지표를 일 방문객으로 임의 환산 금지 |

실제 지원 차원을 먼저 확인한다. 연령과 성별이 각각 존재해도 결합표가 없으면 교차 분석을 만들지 않는다. 직업·국내외 관광·출발 거주지 등의 관심 요구는 자료 확보·정의 확인 후 별도 지원 판단한다. 자료 없음·비공개·경계 불일치는 0과 구분한다.

## 개발 시 유의점

- 스크린샷 한 곳만 고치지 말고 공통 컴포넌트의 소비 화면을 추적한다. 모든 화면에 같은 UI를 강제하는 것과 같은 규칙을 적용하는 것은 다르다.
- 일반 지도 SVG와 버튼 아이콘 SVG를 구분한다. 광범위한 `svg` 크기 규칙은 거대 아이콘과 축 잘림을 만들었다.
- 고정 높이는 제목·조건 바 줄바꿈을 고려한 실제 잔여 높이로 계산한다. `height:100%`, native `details`, flex 축소, 포털의 조합은 실제 화면에서 확인한다.
- 포털 호스트 이동은 자식 상태 유지와 팝오버/초점 복귀를 함께 확인한다. ref 연결 시점·동일 속성 반복 쓰기 관찰 루프에 주의한다.
- 숨겨둔 지도/입력을 현재 활성 입력처럼 다루지 않는다. 닫힌 창의 중복 DOM/ID와 검색 팝오버 가림을 점검한다.
- 시연만 예전 CSS로 가리는 방식은 공통 상세 기능을 다시 끊을 수 있다. 모드 전환이 조건·상세를 초기화하지 않는지 검사한다.
- 빌드·단위시험 성공은 UI 품질 통과가 아니다. 독립 디자이너 검토와 현재 버전의 실제 조작 증거가 필요하다.
