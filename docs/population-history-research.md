# 생활인구 과거 자료 확보

2026-11-15 · R18/R20 · 원자료 수집·형식 조사 기록. 화면 구현·공개 반영 결과와 별도다.

## 한 달 제한 여부

한 달만 제공하는 자료가 아니다. 현재 대시보드에 준비된 일별 상세 파일이2026년10월31일치였던 것이다.

- 현재 화면과 같은 **[OA-23016 내국인 행정동별 서울 생활인구(250m)](https://data.seoul.go.kr/dataList/OA-23016/F/1/datasetView.do)**의 실제 파일 목록에서 **2023년1월–2026년10월46개월**의 월별 ZIP을 확인했다. 조회 화면/API는 최근2개월이라는 안내와 과거 파일 제공을 구분한다.
- **[구 OA-14991 행정동 단위 서울 생활인구(내국인)](https://data.seoul.go.kr/dataList/OA-14991/S/1/datasetView.do)**는2017년 상·하반기 파일부터 존재한다. 구 자료에는250m 국가표준격자로 전환하면서 기존 생산이2026년7월31일 이후 종료된다는 안내가 있다.
- 같은 서비스의 과거 월별 파일과 구 서비스의 장기 자료를 혼동하지 않는다. 현행·구 방식, 행정동 코드·경계, 통계 정의·재산출 여부를 확인하지 않은 채 긴 선 하나로 연결하지 않는다. 이번에는 현행 OA-23016의2026년1–10월을 확보했다.46개월 전체나 구2017년 이후 전체를 내려받았다고 주장하지 않는다.

공식 HTML의 내려받기 항목(파일명/seq)을 읽어 목록을 확인했으며 원본 HTML은 `data/raw/population-history/OA-23016-source-page.html`에 보존했다. 원본 목록의 수정일과 실제 수집일을 구분한다.

## 형식 차이와 처리 원칙

- 공통 인코딩은CP949.32열은 일자/시간/행정동코드/생활인구합계와 남녀 연령별28열이다. 성별×연령은 실제 원본 교차 열에서 합산할 수 있다.
-2026년1–6월은 **월 전체 CSV 한 개**,7월부터는 **일별 CSV 묶음**이다. ZIP 멤버 이름이 항상8자리 날짜를 담는다고 가정하면1–6월을 누락한다.
- 모든 헤더는 쉼표지만 **데이터 구분자는 월·CSV 멤버별로 다르다.** 전행 검사에서1–6월은쉼표,7·8·10월은쉼표/세미콜론이같은월안에혼재,9월은세미콜론이었다. 첫 멤버의 구분자를 월 전체에 재사용하지 않는다. CSV마다헤더와 첫 데이터 행을 별도로 읽어 구분자를 판정한다. 단일 쉼표 파서는 일부 파일을32열이아닌1열로 읽는다.
- 행정동 코드 뒤 공백은 제거하고 코드 문자열을 유지한다. `*`, 빈 값, `\N` 같은 비공개·결측값은0으로 바꾸지 않는다. 한 구·성연령 합계의 일부가 비공개라면 그 시점의 합계도 결측으로 유지하는 정책을 적용한다.
- 요일·월초/월말 비교는 날짜 수가 다른 집단의 단순 합산이 아니라 같은 시간대의 **유효 날짜당 평균**을 사용하고 포함 날짜 수를 제시한다. 하루24시간을 더한 값을 고유 방문자 수로 부르지 않는다. 공휴일·월별 계절성은 별도 분석 조건이다.

## 재현과 검증

수집: `python3 scripts/collect-population-history.py 202609 202608 202607 202606 202605 202604 202603 202602 202601 202610`. 기본 요청은2026년1–10월이며 명시 기간은 공식 파일 목록에 있는지 먼저 확인한다.3개 동시 요청,부분 다운로드파일을 완성 ZIP으로 바꾼 뒤 목록·첫 헤더/데이터·해시를 검사한다.

검증: `python3 scripts/validate-population-history.py`. 모든 CSV 행의32열,날짜/시간/동 코드,중복키,월별 전체 날짜,날짜별24시간 완결성,멤버 전체읽기를 통한ZIP CRC를 별도 [전행 검증 기록](../data/population-history-validation.json)에 남긴다. 숫자 셀 의미·코호트 합계·요일 집계는 후속 준비 스크립트가 별도로 검증해야 한다.

전행 검증 완료:10개월 모두통과,304일×24시간×427동=3,115,392행. 모든날짜의427동·24시간격자가완결됐고날짜/시간/동중복0개,32열구조와ZIP CRC읽기도통과했다. 숫자값의합계·타깃별분모까지이검사가대신하지는않는다.

검증을 강화하는 도중 ‘모든 월이 일별CSV이며 데이터가쉼표’라는 잘못된 가정 때문에 정상 파일을 잠시실패로 분류한 적이 있다.파일은 삭제하지 않았고,월별/일별·구분자 차이를 확인해 수집 명세를 복구했다.수집 성공과 검증기 오류를 구분한다. 현재 수집 명세10개 모두 `downloaded`다.

## 아직 완료로 간주하지 않는 것

원자료 확보가 화면 반영이나 모든 코호트 숫자의 검증을 뜻하지 않는다.요일·월내기간 보조 분석용 준비 파일과 화면,자료 제공기간의 제목·주의문은 별도 구현/검수가 필요하다. 구 서비스와의연속 비교,2017–2025 전체 다운로드,2026년11월 일자료 추가는 이번 확보 범위에 포함하지 않았다.
