# 조회 옵션 전면 감사와 재설계 방향

2026-11-15 · 상태: **감사 결과 / 개편안. 새 구조의 구현·공개 배포 승인 기준 통과 전.**

## 판정

현재 문제는 옵션 크기만이 아니다. 조회값, 지도 탐색, 표현 기준, 창 배치가 한 편집 흐름에 섞여 있다. 작은 버튼으로 바꾸거나 전부 접는 것만으로 해결하지 않는다. 기존 기능 후보 소스는 보존하되, 최신 사용자 지시에 따라 추가 개편과 공개 배포를 보류하고 대표 화면의 목적·구조부터 재검토한다.

## 대표 개선안

### 결과를 읽는 상태

상단은 자료와 보기 이동을 유지한다. 지도/그래프 가까이에 현재 조건 한 줄을 둔다. 조회창은 분석용에서 좌측 고정, 시연용에서 기본 닫힘을 후보로 삼는다. 상세·후보 화면에서도 같은 조건 편집기를 열고 화면을 되돌리지 않는다.

### 조건을 편집하는 상태

기본 한 열을 **기간 → 지역 → 분석 대상** 순으로 읽는다. 묶음 제목에는 현재값을 요약한다. 상권의 업종·단일 분석 기준, 이동의 도착/출발·시간/누적/일계, 전출입의 제공 연도·구/동 지원 범위는 자료별로 다르게 유지한다. 모든 자료의 필드를 억지로 같게 만들지 않는다.

검색이 필요한 목록은 검색 내장 선택기 하나로 통합하는 안을 우선 검토한다. 별도 대형 검색 버튼을 필드마다 반복하지 않는다. 데이터가 없는 상태에서도 현재값 확인·한 조건 해제·복구는 가능해야 한다.

### 선택적 도구

- 지도 표시: 팔레트·범례·범위. 원자료를 바꾸지 않는다는 뜻을 명확히 한다.
- 그래프 표시: 실제값/증감/기준100·축. 해당 그래프 안에서 연다.
- 창 설정: 좌우 고정/분리·크기·배경 불투명도·배치 초기화. 조회 본문 밖 제목 메뉴 하나로 묶는다.
- 내려받기·후보 추가는 결과 작업이다. 필수 조회 순서 안에 끼워 넣지 않는다.

기본 닫힘을 모든 항목에 일괄 적용하지 않는다. 사용자의 질문에 필수인 현재값·미지원 이유·시간 기준은 가까이 남겨야 한다.

## 실제 확인 범위와 한계

부모 에이전트가 Chrome 1800×905에서 로컬 준비 빌드를 관찰했다. 현재 감사용 산출물은 `index-C4RZsc9U.js` / `index-BmZtaFcD.css`이며 이후 문서 변경과 미빌드 소스가 있을 수 있다.

- 생활인구·생활이동·전출입·추정매출 네 지도 조회창의 묶음·입력 구조를 실제로 비교했다. 생활인구 플로팅 560×360, 조건 편집·접기와 기본 불투명 배경을 확인했다.
- 시연 상세에서 같은 조회창 열기, 날짜 필드 포커스, 시각 변경 후 조건/보기 유지, 전출입 미지원 연도에서 연령2025 전환 안내를 확인했다.
- 상권 홍대10 → 마포9 → 서교+발달2 결과와 관련 유형 A2/R2/D2를 실제 입력으로 확인했고 독립 원자료 기대값과 일치했다. 상권 재진입에서는 조건창2개·중복 ID9개를 발견했으므로 전체 동작 통과로 판정하지 않는다.
- 그래프 옵션을 실제 열어 새 창 배치 규칙의 적용 누락을 확인했다. 모든 크기·자료 조합의 드래그/Esc·native 전체화면·공개 화면은 이번 감사에서 완료하지 않았다.
- 32개 범위/팔레트/관련값/지원연도 단위 검사를 통과했고 준비 소스 빌드는 통과했다. UX 수용 통과와는 별개다.

DOM 구조 수집의 getClientRects 결과는 닫힌 details 내부의 레이아웃도 포함할 수 있다. 입력 개수를 실제 사용자가 보는 버튼 수로 해석하지 않는다. 위 감사는 전문가 관찰이며 사용자 성공률·시간 감소를 실측한 사용성 시험은 아니다.

## 다음 개편 관문

생활인구(언제·누가), 이동(어느 시각 기준·어떤 집계), 상권(어디·무슨 유형) 세 대표 조회를 먼저 시안으로 비교한다. 1366×768/1800×905, 긴 이름·검색0건·미지원 세분·설정 재열기·도킹/분리·투명도에서 같은 질문을 끝까지 수행해야 한다. 독립 원자료 수치·포커스·화면 밀도가 함께 통과한 뒤 다른 자료로 확장하고 공개 배포한다.
