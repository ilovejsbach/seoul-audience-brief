# 분석 화면 가독성 참고와 적용 권고

확인일: 2026-11-14. 상용 분석 도구·디자인 시스템의 **공식 문서**를 참고했다. 특정 제품의 화면을 복제하거나 아래 수치가 세 제품의 공통 의무 규칙이라고 주장하지 않는다. 실제 적용 여부는 PC 1440×900과 모바일 렌더 화면으로 검증한다.

## 공식 근거 3곳

| 참고 | 공식 지침에서 확인한 내용 | 이 화면에 적용할 방향 |
|---|---|---|
| IBM Carbon | 제품용 productive 서체와 홍보용 expressive 서체를 구분한다. 기본 스케일에는 14·16px가 포함된다. [Typography](https://www.carbondesignsystem.com/building-blocks/foundations/typography/overview) | 큰 홍보 문구를 줄이고 필터·데이터·설명에 안정적인 제품용 위계를 사용한다. |
| Tableau | 중요한 질문을 위쪽/왼쪽에 두고, 폰트 크기·굵기·색의 위계를 제한한다. 중립색 바탕과 절제된 강조색, 읽기 쉬운 수평 라벨을 권한다. [Visual Best Practices](https://help.tableau.com/current/blueprint/en-us/bp_visual_best_practices.htm), [Refine Your Dashboard](https://help.tableau.com/current/pro/desktop/en-gb/dashboards_refine.htm) | 첫 화면에 목적→조건→핵심 수치→지도/비교 순서가 드러나게 한다. 안내 장식보다 수치와 선택 상태를 강조한다. |
| Material Design 3 | display/headline/title/label/body의 역할을 구분한다. 본문은 작은 크기에서 읽기 좋은 서체, 작은 본문·라벨은 약 1.5배 행간, 자주 바뀌는 수치는 tabular 숫자를 권한다. [Applying type](https://m3.material.io/styles/typography/applying-type) | 설명과 버튼·표의 역할을 구분하고 숫자 폭을 고정해 조건 변경 시 흔들림을 줄인다. |

추가 색상 근거: [Carbon 데이터 시각화 팔레트](https://www.carbondesignsystem.com/building-blocks/data-visualization/color-palettes)는 수량에 순차색, 양/음 변화에 발산색을 구분한다. 밝은 테마에서는 진한 쪽이 큰 값이고, 어두운 테마에서는 밝은 쪽이 큰 값이다. 순이동은 중립 0을 사이에 둔 발산색과 명시적 ± 부호로 읽게 한다.

## 이 프로젝트의 적용 권고

공식 참고자료를 바탕으로 한 현행 제품 기준은 [기기별·영역별 타이포그래피](responsive-typography.md)와 [정본 R07](DASHBOARD_DEVELOPMENT_RULES.md)이다. 과거의 연속 크기 제안(12–13px, 14–15px 등)은 임의 크기를 늘릴 수 있어 아래의 역할별 토큰으로 대체했다.

| 역할 | 현행 규칙 | 판단 이유 |
|---|---|---|
| 기능 | 조건·control 토큰, 굵기500 | 메뉴·입력을 빠르게 구분하고 터치 입력을 작게 줄이지 않음 |
| 정보 | body·key 토큰, 본문400·대표값600 | 설명은 읽기 크기, 대표값은 중요도에 맞춰 강조 |
| 인포그래픽 부가 | meta 토큰, 굵기400 | 축·단위·출처를 일관되게 표시하며 해석에 필수인 주의는 본문으로 승격 |
| 창 구성 | panel·heading 토큰, 굵기600 | 창과 내용의 구조를 구분하고 중복 제목을 줄임 |

시연 네 단계·분석 여섯 단계 상한 안에서 PC·태블릿·모바일 값을 각각 선택한다. 상태와 증가·감소는 별도 의미 규칙이며 크기 종류를 추가하지 않는다.

서체는 한국어 가독성이 검증된 산세리프 한 계열을 중심으로 운영한다. 예: 설치된 시스템 한국어 산세리프를 우선 활용하거나 정식 배포된 한글 웹폰트를 선택한다. Carbon의 IBM Plex 사용이 곧 한국어 화면 전체에 IBM Plex를 강제한다는 뜻은 아니다. 본문에 과도한 자간·영문 대문자 장식·장식 서체를 쓰지 않는다.

색상은 밝은 회색 배경 + 흰 데이터 패널 + 진한 남색 본문 + 하나의 강조색을 기본 후보로 권한다. 기존 어두운 테마를 유지한다면 작은 회색 설명·지도 지역명·입력값의 대비를 실제 화면에서 먼저 확인한다. 색상표의 예쁜 조합만으로 접근성 검증이 끝나지는 않는다. 텍스트 대비 4.5:1, 필수 UI·그래픽 구분 3:1을 검증 목표로 두고, 선택 윤곽·기호·라벨을 함께 사용한다.

## 적용 후 확인할 세 가지

1. PC 1440×900, 배율 100%에서 지역·기간·타깃·단위가 보이고, 큰 소개문 때문에 지도·순위가 아래로 밀리지 않는가?
2. 실제 지도 최저/최고 색 위의 지역명, 보조 설명, 선택·포커스·오류 상태를 읽을 수 있는가? 순이동 음수/양수와 결측이 색만으로 구분되지는 않는가?
3. 긴 동 이름·큰 금액·최대 3곳 비교·인쇄에서도 글자 잘림이 없는가? 390px 모바일에서 핵심 정보를 글자 축소로 해결하지 않고 재배치하는가?

이 문서는 적용 방향을 정리한 참고이며 CSS 수정·화면 검증 완료 보고가 아니다.
