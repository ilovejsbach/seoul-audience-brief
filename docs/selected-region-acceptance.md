# 지도 선택과 지표 연동 — 독립 수용 기준

2026-11-15. R01·R02·R03·R13–18·R20–21. 독립 소스 감사와 의미 판정 기준이다. 실제 브라우저 검증과 수정 완료는 부모의 후속 실행 기록에서 구분한다.

## 문제와 화면 계약
지도에서 서초구와 특정 연령 집단을 선택했는데 아래 지표는 계속 서울25구 합계라면, 이용자는 같은 조건의 결과로 오해한다. 지도 클릭이 단순 미리보기인지 현재 분석 지역 선택인지 명확해야 한다. 이번 요구에서는 지도 클릭이 **현재 분석 지역을 선택**하고 옵션·선택 요약·KPI·추세가 같은 지역/시점/인구 집단을 사용하도록 한다.

현재 소스의 직접 원인은 main.tsx/ExtraDashboard.tsx의 MapCanvas onPreview가 setPopup만 호출하고, 지표의 원천 district/dong은 바꾸지 않는 것이다. 이는 소스상 확정이며 아직 수정·실행 통과로 기록하지 않는다.

## 단일 조건 계약
선택 상태는 다음 값을 공유한다.

| 차원 | 생활인구 | 이동/전출입/매출 |
|---|---|---|
| 지역 | 서울 전체/구/동의 코드, 동의 소속구 | 지원 공간 단위의 코드, 동의 소속구 |
| 기준 기간 | 실제 선택일자와 시각 | 출발/도착 기준·시간/누적/일계, 연도, 분기/시간구간 |
| 모집단/지표 | 내국인 추계·연령·성별 | 이동 건수, 전입/전출/순이동, 제공 업종 추정매출 등 |
| 선택 효과 | 조건창·선택요약·지도강조·KPI·추세·상세·CSV | 같은 지원 차원을 가진 결과의 연동 |
| 부가 결과 | 현재 조건의 후보 값·두 시점·패턴·대상비교 | 현재 지표의 후보 값·기간 비교·인구 세분 |

지도 전체를 유지하면서 선택 지역 지표만 바꾸는 것은 가능하다. 이때 **지도 비교 범위**와 **현재 분석 지역**을 분리해서 표기한다. 지도의 여러 도형을 색칠하는 범위와 하나의 지역 KPI가 같아야 한다는 뜻은 아니며, 각각의 범위를 오인시키지 않아야 한다.

## 30대 의미 판정
사용자가 올린 화면의30대는 **거주지 전입·전출의 연령별30대**다. 생활인구 타깃을 새로 추가하라는 요구가 아니다. 현행 생활인구20–39세를30대로이름만바꾸거나신규타깃을임의추가하지않는다.

- 해당 조건은 period2025, dimensionage, band003004(공식라벨30대), 구코드11650(서초구)다.
- 공식 연령별 응답의현재값 `val`을 사용한다. `preVal`은 비교용 이전값이고 `analVal`은 변화율이므로 현재 전입·전출 값과 혼동하지 않는다.
- 순이동=전입−전출이며, 생활이동 순유입·체류생활인구와다르다. 성별과연령별은각각주변분포이므로성별×30대교차값을만들지않는다.
- 연령별은2025년자치구까지만지원한다. 동별·다른연도에서값을총계로조용히대체하지않는다.

## 기능·의미 수용 기준

1. 서초구(11650)를 지도에서 한 번 클릭하면 현재 선택 지역은 서초구로 바뀌고 구 선택기도11650이다. KPI가서울전체합계로남아서는안된다.
2. 같은 시각·일자·성별·연령의 원본 서초구 모든 동을 합산한 값과 KPI·미리보기·추세 현재점이 일치한다. 반올림된 화면 값과 원값을 구분해 대조한다.
3. 동 클릭은 소속 구와 동 선택기를 함께 갱신한다. 동 KPI는해당동만, 구전체KPI는구합계만사용한다. 지역코드길이·명칭만보고다른공간단위를섞지않는다.
4. 지도 클릭 후 자동 이동/장면 전환을 강제하지 않는다. 현재 지도 카메라·확대상태를유지하고 선택 효과가 작게 즉시 보인다. 심화 추이·동별 분포 이동은 명시 버튼의 후속 행동이다.
5. 미리보기 닫기나 Esc는 창만 닫고 분석 지역을 서울전체로 되돌리지 않는다. 후보 추가도 현재 지역·기간·인구 집단을 바꾸지 않는다.
6. 서울전체/선택구전체 복귀는 명시 행동이다. 동을선택한후구전체복귀시동선택=all, 서울전체복귀시구/동=all이되며KPI와추세가대응합계로바뀐다.
7. 같은 지역을 반복 클릭해도 임의로 다른 집단/시점으로 바뀌지 않는다. ‘다시 클릭=추이 이동’ 같은 기존 규칙과 새 단일 선택 계약이 충돌하면 최신 요구에 맞는 행동을 명시하고 테스트한다.
8. 연령·성별·시간·일자를 바꾸면 선택 지역을 유지하며 모든 현재 결과가 같은 조건으로 갱신된다. 새 응답 준비 전 이전 값이 새 조건 아래에 남지 않는다.
9. 빠르게 구→동→다른구·날짜를 바꿔도 마지막 선택만 현재 지표에 반영된다. 이전 팝업/툴팁 값이 새 조건과 섞이지 않는다.
10. 전체화면 지도에서 선택한 지역은 전체화면을 닫은 뒤에도 옵션·KPI·추세에 유지된다. 심화 이동이 전체화면 밖이라면 먼저 해제하고 목적지가 실제 보이도록 한다.
11. 분석용/시연용은 같은 선택 상태와 계산을 사용한다. 시연 지역→시간흐름→후보장면을 오가도 현재지역과조건의뜻이바뀌지않는다.
12. 구·동 선택기·지도 도형·순위 지역명·후보에서지도보기는 같은 지역 선택 상태와 집계 규칙을 공유한다. 화면 이동 의도가 다른 경로는 별도 이동 함수를 둘 수 있지만, 입력 경로마다 KPI의 집계 범위가 달라져서는 안 된다.
13. 생활이동은 구 단위만 선택하며, 전출입 연령별의지원공간단위·연도를보존한다. 지원하지않는동별·연령범위를구합계로조용히대체하지않는다.
14. 전입·전출·순이동 방향 전환은 현재 지역을 유지하고 해당 지표의 부호·단위·연도와 KPI·추이를 갱신한다. 순이동은 전입−전출이고생활이동순유입과섞지않는다.
15. 지도순위가선택구의동별분포로전환되는경우와서울전체순위를유지하는경우를각각표기한다. 선택지역하나의KPI를순위25개합계로다시계산하지않는다.
16. CSV에는 현재 집계 범위·일자/시각·대상 집단이 들어가며 화면의같은값과대조한다. 구전체일때동별내역을내려받는의도라면그합계/범위를분명히설명한다.
17. 후보 비교는 현재 조회 조건의 값으로 계산하되 후보 지역 목록을 임의 삭제하지 않는다. 저장 시나리오를 다시 적용하면 저장 지역/기간/집단이함께복원된다.
18. 상시 선택 요약은 작고 분명해야 한다. 출처·계산 방법·길어진 제한 문구는 상세/툴팁으로 분리할 수 있으나 현재지역·기간·집단·단위와핵심해석경고를숨기지않는다.

## 독립 원본 대조 결과

구현 담당이 전달한 fixture와 별도로 `data/raw/residential-migration-demographics/board24-2025-11650-in.json` 및 `...-out.json`의 공식 응답을 읽었다. 공개 준비 JSON의 records나 프런트 계산 함수를 기대값으로 재사용하지 않았다. 두 원본의 mapData.dataList에서 id003004 및 category30대가 함께 일치하는 항목의 `val`을 Decimal로 변환해 직접 계산했다.

|---|---:|---:|---:|
| 2025년 서초구30대(11650/003004) |13,705명|13,007명|+698명|
| 같은 조건의 서울25구 원본 합계 |308,182명|326,912명|−18,730명|

서초구값과서울25구합계는확실히다르므로, 지도서초구클릭후하단이308,182/326,912/−18,730을계속보이면선택범위연동실패다. 전입원본의preVal12,857·전출원본의preVal12,900 역시현재값으로사용하면안된다.

원본 SHA-256:
- 전입: `82ca03d99bd3a805ae3067be3dc1ee6f969a740763af4424e7fc90b4f1e5dd60`
- 전출: `15b880c031ac99fc1f0e142a41d6af6e6aa0e04db8fb92784567a5ef0d04f602`

서울합계는각방향의`board24-2025-*-in/out.json`25개에서같은연령id의현재값만한번씩더했다. 구·동이나연령합계를중복합산하지않았다. 원본수치의독립검증은완료했으며, 화면연동의실제브라우저통과여부는부모의후속실행기록에서판정한다.

수집 명세의 요청도 대조했다. 두 원본 SHA는 명세와 일치하고 요청은 `mapChartId=24`, `areaCode=11650`, `prdDe=2025`, `moveType=IN/OUT`이며 공식 endpoint는 `https://stat.eseoul.go.kr/stat/sip/sts/move/getMapBoardDataList.do`다. 수집 명세는 원본의 지역/기간 식별과 무결성 확인에만 사용했고 기대 수치는 원본 dataList의val에서 다시 계산했다.

## 구현 후 독립 소스 검토

main/Extra의onPreview경로가현재구/동상태를먼저갱신하고같은지역의팝업을보여주도록바뀐것을확인했다. main의선택지역→selectedRows→curve와Extra의selectedCode→selected(구는mapStats/동은stats)→activeStats→sum이같은상태를소비한다. 연령별서초구를선택한경우Extra의activeStats는해당레코드한개이며선택실패를서울25구합계로대체하지않는다. MapCanvas는지도클릭으로선택한구의도형범위/카메라를유지하고명시상세행동에서만동별지도로내려가는분리를소스상확인했다. 실제반영시간·값·지도범위유지의통과는부모E2E에서최종판정한다.

선택지역명과지도전체비교조건은별도문맥으로유지해야한다. 예를들어선택이서초구인상태에서다른구를마우스오버했을때, 해당구툴팁이‘서초구’조건의값처럼표시되지않는지확인한다. 현재선택요약에만선택지역명을넣고다른도형의조회조건문자열에혼합하지않는다.
