# 확장형 분석 작업공간 설계

2026-11-16 · 설계안 v2 · **디자인·사용성 우선 / 운영 화면 미적용**

[방향 분석](expansion-ia-audit.md)을 화면·상태·검증 단위로 구체화한 제안이다. 최신 지시는 새 화면 재구성보다 **공간 활용·가독성·동작의 동시 개선**이며, 사용자는 세 불편 모두 필수라고 답했다. 운영 코드·집계·배포 변경이나 사용성 효과 검증 완료를 뜻하지 않는다. 현행 [개발 규칙](DASHBOARD_DEVELOPMENT_RULES.md)의 R01–07, R10–19, R20–21을 따른다. 기존 화면에서 해결할 수 있는 문제는 먼저 해결한다. 아래 새 IA는 확장 시 참고안이지 첫 구현 과제가 아니다.

## 0. 요구 재인식과 설계 우선순위

### 앞선 설계에서 바로잡는 것

- 새 시작 화면·공통 껍질·전역 메뉴 개편을 선행 작업으로 둔 순서를 폐기한다. 메뉴 구조 변경은 국소 개선으로 해결되지 않는 증거가 있을 때 한다.
- 표본25구·대표3상권 시안은 화면을 설명하는 모형이다. 전체 자료를 다루는 실무 도구의 사용성 검증이나 최종 디자인으로 승인된 것이 아니다.
- 분석 완료 뒤 발표 제작으로만 흐르는 단방향 모델을 쓰지 않는다. 실무 탐색과 시연·결론 도출을 병렬 설계하고 필요하면 서로 왕복한다.
- 사용자는 시연의 중심을 **광고주와 현장에서 비교하며 결론을 만드는 협의**라고 확정했다. 사전 발표용 고정 장면 중심으로 설계하지 않는다. 별도 저장·버전 관리 도입은 사용자 확정이 아니며 디자인 개선의 선행 조건도 아니다.

**완료 원칙:** 각 화면에서 공간·가독성·동작·수치 의미가 함께 통과해야 한다. ‘색은 다음 단계’, ‘연동은 나중’, ‘페이지 방문했으니 사용성 통과’로 나누지 않는다. 단계는 공통 원인과 적용 범위를 나누는 작업 순서다.

## 2. 메뉴와 화면 구조 — 후순위 확장 검토안

아래 구조는 현행 화면의 국소 개선으로 해결되지 않는 문제가 확인될 때 검토한다. 이 구조로 바꾸기 위해 공간·가독성·연동 개선을 기다리지 않는다.

```text
공통 상단: 서비스명                         시작 | 분석 | 브리핑 | 근거·자료
시작
 ├ 상권 입지 검토 → 분석: 상권 지도
 ├ 구·동 인구 검토 → 분석: 생활인구 분포
 ├ 이어서 분석 → 마지막 문맥
 └ 자료 찾기 → 확보·미확보를 구분한 목록
분석 작업공간
 ├ 목적·자료 선택(분석 탐색)
 ├ 조회 조건: 자료·기간 / 지역·공간 / 분석 대상
 ├ 결과 보기: 분포 / 변화 / 비교(자료가 지원하는 항목만)
 └ 선택 대상 → 시간 추이·집단 구성 등 목적을 이름에 넣은 심화 보기
심화 분석 문서
 ├ 같은 질문의 주모듈 + 요청 시 펼치는 관련 모듈
 ├ 같은 도표 크게 보기
 └ 분석으로 돌아가기
브리핑
 ├ 현재 분석에서 장면으로 전환
 ├ 한 근거를 한 장면에 표시
 └ 분석으로 돌아가기
```

**탐색과 조건의 경계:** 전역 ‘분석’과 목적 선택은 무엇을 조사할지 정한다. 조회 조건은 현재 결과에 적용할 범위를 정한다. 목적 선택 목록과 세부 필터를 같은 세로 목록에 섞지 않는다. ‘보기’는 자료 종류와 별개다. 생활인구에서 변화 보기를 눌러도 자료가 생활이동으로 바뀌지 않는다.

향후 지하철·부동산은 분석 목적 목록과 자료 설명서에 추가한다. 준비되지 않은 화면을 활성 메뉴로 만들지 않는다. 행정구역은 구→동, 상권은 서울→구→상권, 교통은 노선↔역 등 각 자료의 공간 관계를 사용한다. 역을 동의 하위 항목으로 고정하지 않는다.

1440px PC 예: 내용 폭1408px = 조회280 + 간격8 + 중앙832 + 간격8 + 정보280. 상단도 같은1408px 정렬선에 맞춘다. 제목 길이에 따라 내용 최대 폭을 바꾸지 않는다. 1200px에서 같은 구성은 중앙592px가 되며 중앙540px를 확보하지 못하는 글자 확대/좁은 창에서는 한 패널을 접힘 방식으로 전환한다. 오른쪽 최소 폭보다 작은 값으로 글자를 억지로 줄이지 않는다.

분석 캔버스 높이는 `100dvh − 실제 상단·작업 바·조건 높이 − 하단 여백`이다. 줄바꿈·브라우저 도구막대·글자 확대 뒤 실제 높이를 재측정하며 고정56/48/36 합만을 최종 계산값으로 믿지 않는다. 상단의 같은 제목을 두 번 표시하거나 시간 슬라이더를 별도 전체폭 행으로 두지 않는다.

### 배치 조절의 단계

1. 기본은 예측 가능한 좌조회·중앙결과·우정보다. PC 첫 진입은 주영역을 우선하고 우측은 선택 전 간단한 순위만 표시한다.
2. ‘배치’ 안에 집중 / 주정보+보조 / 비교 템플릿을 둔다. 동작은 원값·조회 조건과 독립적이다.
3. 이동·자석·투명도·세부 크기 조절은 같은 ‘배치’의 고급 기능이다. 제목 바에 좌·우·띄우기·보기·초기화 버튼을 전부 상시 나열하지 않는다.
4. 현행 R05의 자석·취소·경계·지도 최소 공간·대체 버튼 계약을 유지한다. 플로팅 투명도는 배경에만50–100%, 도킹 시100%다. 데이터 해석 팝오버와 범례는 이동형 창으로 바꾸지 않는다.
5. 태블릿/모바일은 두 창을 반투명하게 겹쳐 유지하지 않는다. 요청한 창 하나를 우선하고 기존 조건·열림 의도는 보존한다. 돌아갈 버튼과 원래 결과로 복귀를 보장한다.

## 5. 조회 옵션: 세 묶음과 지원 조합

조회 첫 화면은 **자료·기간 / 지역·공간 / 분석 대상**의 동일 높이 요약3행이다. 클릭하면 선택한 하위 편집 화면 하나만 보인다. 단계 순서는 강제하지 않는다. 현재 조건 칩은 같은 입력의 해당 하위 화면으로 바로 들어간다. 하위 편집에서 ‘조회 항목으로’를 눌러도 조건은 지우지 않는다.

| 그룹 | 포함 | 포함하지 않음 |
|---|---|---|
| 자료·기간 | 자료, 지표, 제공 기간·주기, 기준일/분기/연도, 시각, 출발/도착 및 단일/누적 등 집계 정의 | 축·색상·배치·설명창 |
| 지역·공간 | 서울/구/동·상권 등 제공 범위, 이름 검색·상권 유형, 공간 단위 | 후보 목록·색상 강조 |
| 분석 대상 | 제공되는 성별·연령·업종·요일 등 대상 구분과 한 가지 주변분포 선택 | 원자료에 없는 교차 추정·지도 위치 |

지표·집계 정의는 자료·기간에, 사람/업종 등 대상 구분은 분석 대상에 소속한다. 이름이 같아도 의미가 다른 ‘시간 기준’과 ‘시간별 구성 보기’를 하나의 상태로 합치지 않는다. 후보는 조사 목록, 비교 기준은 비교 보기의 국소 조건이다.

| 자료 | 제공 조건의 설계 예 | 미지원 처리 |
|---|---|---|
| 생활인구 | 기준일·시각·구/동·원본이 지원하는 성별×연령 | 원자료 열로 직접 가능한 조합만 활성. 시안의 구합계·24시간 범위는 별도 표시 |
| 생활이동 | 자료일·출발/도착·유입/유출·집계 방식·제공 지역 | 당일 고유 방문자/거주지 전출입으로 바꾸지 않음 |
| 전입·전출 | 전입/전출/순이동·연도·지역·제공 성별 또는 연령 | 성별2021–2025구/동, 연령2025구의 현행 범위 밖은 이유와 지원 범위 제시 |
| 상권 추정매출 | 분기·상권·업종·제공 시간구간/주변분포 | 서로 다른 주변분포를 곱해 성×연령×시간 타깃을 만들지 않음 |
| 상권 유동 | 분기·상권·제공 성별/연령/요일/시간 중 지원 기준 | 일평균·일고유 방문객으로 임의 환산하지 않음 |

자료 변경은 호환되는 지역·기간·대상을 보존한다. 호환되지 않는 값은 새 결과 요청 전에 어떤 값이 해제/교체되는지 요약한다. 예: ‘분기 자료로 전환하여 날짜·시각은 해제됩니다.’ 성별이 미지원인데 조용히 전체로 집계하지 않는다. 유지할 수 없는 조건과 복구 선택을 함께 알린다. 실패 시 마지막 유효 결과를 ‘이전 조건 결과’로 표시하고 새 조건 결과인 것처럼 보이지 않게 한다.

## 6. 상태를 나누는 계약

### 상단 조회 통합의 영향 검토 — 삭제 확정 전

사용자의 ‘현재 조건 바를 직접 조회창으로 쓰면 좌측 공간을 반환할 수 있다’는 제안은 검토 대상이다. 앞선 응답의 좌측 창 불필요 단정은 철회한다. 같은 상태를 다룬다는 사실만으로 요약·단일 변경·연속 편집의 사용 목적이 모두 같다고 판단하지 않는다. 아래는 소스 확인과 예상 영향이며 새 동작의 실제 검증 결과가 아니다.

| 영향 | 확인한 의존·예상 손실 | 설계에서 보존할 것 |
|---|---|---|
| 조회 진입 전체 | QuerySummary는 직접 입력기가 아니라 query-control-open으로 MapPanel/MapWorkspace의 기존 입력을 찾음. 폼 삭제 시 칩·상세·후보·전체화면 진입 단절 위험 | 입력 정의·상태는 하나로 유지, 편집기와 배치 컨테이너를 분리한 뒤 단일 편집/묶음 편집에 재사용 |
| 미선택 조건 발견 | 상권 검색·유형·업종은 적용된 때만 칩이 생김. 칩만 남기면 첫 선택 경로가 사라짐 | ‘조건 추가/전체 조건’ 진입과 지원 항목 목록, 구→동·자료별 종속/미지원 안내 |
| 실무 반복 작업 | 단일 팝업을 열고 닫는 횟수가 늘 수 있음. 모든 항목 상단 노출은 세로 공간을 다시 소비 | 빠른 단일 변경 기본, 연속 편집은 요청 시 같은 편집기를 묶음/고정으로 사용 |
| 상태·해석 | 구 변경의 동 초기화, 성/연령 지원 조합, 단일/누적·출발/도착의 연쇄 영향 | 변경 적용 범위·해제 안내·비교 기준·후보 보존. 표시/배치 설정은 분리 |
| 상세·전체화면·접근 | 포털 호스트·팝업 앵커·Esc·바깥 클릭·검색 중첩·닫은 뒤 초점이 달라짐 | 현재 전체화면 안에서 입력, 상세 왕복과 칩 초점 복원, 단계 편집 중 예고 없는 닫힘 방지 |
| 지도·반응형·저장 배치 | 좌측 폭 제거 뒤 투영·라벨·카메라·오른쪽 정보 폭·저장 도킹 설정 영향 | 원값·선택·지도 위치 유지, 실제 가용 영역 재측정, 오래된 배치 복원 규칙·좁은 화면 재배치 |

권고안은 **상단 조회 바 기본 + 요청 시 연속 편집/고정**이다. 좌측 상시 점유를 없애는 안과 편집 기능 자체를 없애는 안을 구분한다. 아직 사용자 확정이나 운영 적용이 아니다. ‘상단만’과 ‘상단+선택 고정 편집’을 같은 실제 과업으로 비교해 발견성·반복 입력 부담·주도표 공간을 함께 판정한다.

추가 첨부에서 동일한 오륜동·기준일·시각·성/연령 조건이 한 줄/두 줄의 두 영역에 반복된다. 소스도 main.tsx의 상세 상단과 MapCanvas에 같은 populationQuerySummary를 별도로 전달한다. 이는 같은 조건의 중복 렌더 경로이며 동시 노출 여부는 현재 실화면에서 별도로 판정해야 한다. 목표는 **활성 작업영역당 공통 조회 바 한 곳**이다. 지도·상세·후보·전체화면에서 필요한 위치에 표시하되, 숨은 지도에 편집을 넘기거나 같은 요약을 두 곳에 상시 표시하지 않는다.

긴 ‘생활인구 현재 조회 조건’ 머리말은 자료 제목·조건 필드명이 이미 의미를 전달하면 화면에서 반복하지 않는다. 접근 가능한 영역 이름은 유지한다. 줄바꿈은 글자 축소/강제 가로 스크롤 대신 관련 항목 묶음과 범위가 명확한 추가 조건 진입으로 처리한다. 전환 시 열린 편집창·초점을 정리하고 새 활성 바의 같은 조건으로 복원한다. 비교 기준시점·협의 기준안과 조회 범위/선택 대상은 다른 의미이므로 이 중복 제거에 섞어 삭제하지 않는다.

변경 전 확인할 경로는 생활인구 날짜→시각→성/연령 반복, 구→동, 상권 검색+유형+업종과0건 복구, 상세/후보에서 조건 변경, 실제 Chrome 전체화면, 키보드·좁은 폭, 협의 기준안 복원이다. 지도·그래프·수치·CSV·설명 일치와 기존 후보/국소 비교 조건 보존을 확인한 뒤 공통 소비자에 확산한다. 통계 원본과 산식은 이번 배치 변경의 변경 대상이 아니다.

| 상태 묶음 | 예 | 유지·저장 규칙 |
|---|---|---|
| 전역 경로 | 목적ID, 화면ID, 현재 모듈, 분석/브리핑 | 주소/뒤로가기와 맞춤. 주제를 바꾸는 행위와 자료 필터를 구분 |
| 공통 조회 | datasetId, metricId, period, timeBasis, spatialScope, target | 지도·수치·순위·추이·CSV·설명에 같은 상태 전달 |
| 탐색·선택 | 지도 수준, 선택 entityId, 부모 범위, 카메라, 후보ID목록 | 조회 범위와 선택 객체를 분리. 선택 강조를 자료 제한으로 몰래 사용하지 않음 |
| 국소 조건 | 비교 기준시점, 해당 모듈 집계/강조 | 모듈ID 아래 보관. ‘이 도표만’ 표시하며 다른 도표를 바꾸지 않음 |
| 표현 | 색상 팔레트/범위, 실제값·증감·지수, 축 범위 | 원자료·후보·집계값 불변. 필요시 범위 전환 설명 |
| 배치 | 좌우도킹/플로팅, 크기·위치·투명도, 접힘 | 개인 화면 설정. 분석 주소 공유에 기본 포함하지 않음 |
| 임시 UI | 열린 팝오버, 입력 중 오류, 포인터 미리보기 | 다른 화면에 잔존하지 않음. 닫을 때 초점 복원 |
| 협의 기준안(제안) | 해당 협의의 조회·선택·보기 문맥, 비교에 필요한 자료 버전 식별 | 협의 세션이 소유. 새 협의 시작 또는 명시적 기준안 교체 때만 변경. 상세·분석 왕복은 재생성하지 않음. 후보 목록·개인 배치 제외. 영속 저장은 별도 미확정 |

시연도 같은 데이터 정의·계산을 재사용한다. 현장 협의의 현재 검토 조건은 활성 분석과 연결하며, 조건 변경·추가 근거 검토 뒤 같은 결과로 양방향 이동한다. 협의 진입 시점의 **비교 기준안**은 현재 검토 조건과 별도로 구분한다. 기준안은 저장된 발표자료가 아니라 현재 협의에서 되돌릴 조회·선택·보기 문맥이다. ‘기준안으로 복원’과 ‘현재 조건을 기준안으로’는 명시적 동작이며 단순 화면 복귀가 조건 변경을 취소하지 않는다. 후보 목록·개인 배치는 기준안 복원 때문에 지우지 않는다. 영속 저장·스냅샷·브리핑 버전 관리는 후속 제안이지 선행 조건이 아니다.

조건 변경 시 늦게 도착한 옛 응답을 새 결과에 덮어쓰지 않는다. `queryKey` 또는 동등한 요청 식별자로 지도·정보·추이의 결과 버전을 맞춘다. 로딩 중에는 현재 조건과 마지막 결과의 불일치를 표시한다. 단순 정적 시안의 로컬 상태 동작과 운영 데이터 로딩 계약을 구분한다.

## 7. 이동·확장·복귀

| 동작 | 바뀌는 것 | 바뀌지 않는 것·복귀 |
|---|---|---|
| 지도 구/상권 클릭 | 해당 경계 확대, 지도 수준에 맞는 정보창 | 기간·대상·후보 유지. 구→상권이면 상위 구 카메라 기록 |
| 상위 지도 | 공간 계층의 부모로 이동 | 방문 이력 뒤로가기와 구분. 부모 카메라·필터 정책 복원 |
| 시간 추이 보기 | S2 또는 크게 보는 추이 모듈 | 선택 대상·공통 조건 전달, 출발 카메라·초점 기록 |
| 펼치기/접기 | 같은 모듈의 상세 노출 | 조건·선택·다른 열린 모듈 유지 |
| 크게 보기/확대 닫기 | 같은 도표의 가용 영역 | 같은 값·선택·축 상태 유지, 원래 모듈 위치로 복귀 |
| 비교 보기 | 공통 조건에서 기준/대안 나란히 표시 | 자료·대상 정의 유지. 모듈 국소 기준만 추가 |
| 분석으로 돌아가기 | 출발 화면·카메라·읽던 위치 복원 | 상세에서 의도적으로 바꾼 공통 조회는 유지. 조건 되돌리기는 별도 |
| 시작 | 작업 허브로 이동 | 조회·선택·후보를 지우지 않음. 명시적 새 분석만 초기 상태 시작 |

브라우저 전체화면 호스트는 경로·자료 교체에도 유지되는 공통 앱 껍질이다. 조회 변경은 전체화면을 종료하지 않는다. 지도 집중 보기와 브라우저 전체화면은 구분한다. 현행 R05/R15처럼 지도 밖 상세 진입 시 지도 집중 보기는 해제하지만 브라우저 전체화면 유지 여부는 앱 껍질에서 관리한다. 이 구분을 운영에 적용할 때는 실제 Chrome 정상·전체화면·상세 왕복 회귀 검사가 선행되어야 한다.

툴팁은 짧은 값·의미·한계를 읽는 용도다. 장문의 분석을 읽거나 또 다른 창을 중첩하는 진입점으로 쓰지 않는다. 조작 가능한 짧은 옵션은 팝오버, 지속 참고가 필요한 조회는 패널, 다른 질문의 근거는 상세 화면이다.

## 8. 모듈·비교 규격과 자료별 도표

### 표준 모듈

- 문서의 읽기 폭은 공통 내용 정렬선 안에서 최대1280px. 지도 작업공간은 화면 가용 폭을 사용한다. 본문 문장은 긴 한 줄이 되지 않게 약65–80자 내외 읽기 폭을 별도 제한한다. 이 차이는 내용 폭의 기능적 이유이며 제목마다 임의로 달라지는 폭이 아니다.
- 주모듈은 질문·조건·핵심 결과를 짧은 헤더에 모으고 도표를 우선한다. PC 기본 도표 높이320px, 확대 모듈 도표 높이560px를 시안 시작값으로 쓴다. 헤더는 내용에 따라 늘되 같은 비교 행은 동일 헤더 높이와 도표 기준선을 공유한다.
- 관련 모듈 접힘 행은 PC 기본56px에 질문·한 줄 요약·펼치기 한 개. 긴 제목은 행 높이를 같이 늘리고 글자를 축소하지 않는다.
- 집중형은 주영역100%, 두 도표 비교는50:50, 후보3개는 같은 너비3열. 간격16px. 공통 조건·단위는 한 번, 대상 이름과 개별 자료 없음은 각 도표에 둔다.
- 두 지도는 같은 시점/대상 정의와 색상 눈금을 쓰고 같은 지역의 두 시점이면 범위·확대를 연동한다. 축척/모집단 차이가 있으면 명시한다. 비교 가용 너비가 부족하면 세로 또는 A/B 전환이며 작은 SVG로 전체를 축소하지 않는다.
- 브리핑은 주도표가 남은 높이를 채우며 하단 관련 모듈은 기본 숨김. ‘같은 지역 두 시점 비교’는 요청한 장면으로 전환하고 닫으면 원래 장면으로 돌아온다.

### 도표의 선택

| 자료·질문 | 기본 도표 | 선택적 파생 모듈 | 의미 제약 |
|---|---|---|---|
| 생활인구: 언제 가장 많이 머무나? | 시간 추이 선 | 두 시점 차이·성/연령 구성 막대·요일×시간 열지도 | 시점 인원 합계를 고유 방문객으로 계산하지 않음 |
| 생활이동: 어디서 들어와 어디로 가나? | 상대 지역 정렬 막대 | 방향별 시간 추이, 지원 범위의 흐름 | 출발/도착 시각·건수 기준 일치 |
| 전출입: 규모와 순변화는? | 전입·전출 나란한 막대 + 순이동0중심 막대 | 연도별 선·제공 집단 비교 | 순이동 부호 유지, 연령/성별 미지원 조합 금지 |
| 상권: 규모·구성과 변화는? | 상권 순위 막대·분기 선 | 매출 업종 구성 또는 유동의 제공 주변분포 | 매출과 유동의 기간/모집단 차이, 광고 전환율 금지 |
| 분포: 편차·극단값은? | 히스토그램/상자 그림 | 원자료 목록 | 관측 단위가 상권인지 개인인지 명시 |
| 관계: 두 지표가 함께 움직이나? | 산점도 | 대상 선택·정확값 | 공간·기간 정합, 축 단위 각각 표시, 인과로 단정 금지 |

규모 막대는0 기준으로 길이를 비교한다. 추이 축 좁힘은 허용하되 현재 범위·절단을 알린다. 기준100 지수는100중심·최대편차+여유율, 증감은0기준이다. 원값·지수·변화율은 같은 이름으로 표시하지 않는다. 누적막대 구성비는 중복 없는 분할과 분모를 확인한 경우만 제공한다. 열지도는 실제 교차집계가 필요하며 별도 요일·시간 합계를 곱해 만들지 않는다.

스토리는 자료마다 ‘분포→추이→구성’ 순서를 기계적으로 강제하지 않는다. 화면 목적에 맞는 첫 근거를 제시하고 관측 사실→가능한 해석→다음 검토를 나눈다. 상대 지역·업종·시간 자료가 없으면 해석 문장으로 빈 부분을 추정하지 않는다.

## 10. 대표 여정과 수용 기준

### 두 트랙은 같은 단계에서 각각 설계한다

분석 작업의 산출물은 확인한 사실·비교·미해결 질문이고, 시연·판단의 산출물은 그 근거에 따른 대안·해석·권고 또는 판단 유보다. 분석 트랙을 완료한 뒤에만 시연을 착수하는 것이 아니다. 원자료 계산은 공유하되 작업 동선·초기 정보량·완료 판정은 따로 둔다.

| ID | 분석자의 작업·조회 시나리오 A | 시연·결론 도출 시나리오 B | 공통 수용 기준 |
|---|---|---|---|
| AB01 생활인구 | 같은 지역에서 날짜·시간·지원 성/연령을 반복 변경, 다른 지역·두 대상/두 시점 비교, 필요시 요일/월내 패턴 조사 | 어느 지역·시간·대상이 검토 근거인지 설명, 같은 조건 대안 비교, 관측기간·누락 한계를 보고 권고 또는 추가 조사 | 지도·값·추이·비교의 조건 일치, 시점 추계≠방문객, 일부 공개시간 최대를 하루 전체 최대라 하지 않음 |
| AB02 상권 | 이름+유형+구/동을 함께 조회, 구→상권 확대, 매출/유동과 지원 주변분포·분기 비교, 후보 유지 | 후보별 규모·변화·제공 구성을 근거로 대안 설명, 서로 다른 기간/업종·표본 한계를 검토 | 검색 결과 교집합·0건 복구, 상권 상세→지도 문맥 보존, 주변분포 교차/광고전환율 생성 금지 |
| AB03 전입·전출 | 전입/전출/순이동 전환, 제공 연도·공간·성별 또는 연령 비교, 미지원 동/연도에서 복구 | 규모와 순변화를 구분하고 어떤 집단의 거주 기반이 바뀌는지 설명 | 0선·부호·기간 유지, 미지원≠0, 생활이동/당일 방문과 구분 |
| AB04 생활이동 | 출발/도착·유입/유출·시간별/누적/일계 전환, 선택 구의 상대 지역 탐색 | 언제 어느 방향의 이동 수요인지 근거를 설명하고 다른 후보·시점과 대조 | 이동 건수·구내 제외·집계 창 명시, 다른 집계끼리 같은 비교처럼 표시 금지 |

시연 B는 단순 ‘분석 화면에서 옵션 숨기기’가 아니다. **판단 질문 → 근거 → 대안 → 반론·한계 → 권고/유보**가 연결되어야 한다. 확보 자료로 설명할 수 없는 부분은 다음 확인 항목으로 남긴다. 규모가 크다는 이유만으로 최적 광고 입지·실제 광고 효과를 결론내지 않는다.

### B트랙의 중심: 현장 비교·협의

사용자 답변에 따라 B는 완성된 결론을 발표하는 경로가 아니라 **질문을 조정하며 함께 결론을 만드는 경로**로 설계한다. 대표 흐름은 다음과 같다.

`현재 판단 질문 → 비교 기준 확인 → 광고주의 조건/후보 변경 → 차이와 근거 확인 → 필요한 상세 조회 → 협의 화면 복귀 → 대안 유지/기준안 복원/기준안 교체 → 합의 또는 추가 확인`

- **가까이 둘 조작:** 현재 과제의 지역/후보·지표·기간/시간·지원 대상 변경, 비교 보기, 기준안 복원, 근거 상세. 큰 옵션창을 상시 열지 않아도 반복 비교가 가능해야 한다. 미지원 조건은 가능한 것처럼 노출하지 않는다.
- **접어 둘 조작:** 축·팔레트 세부값, 창 도킹/투명도/크기, 긴 출처·방법. 사용자가 원하면 열 수 있으며 기준·단위·결측 경고는 상시 필요한 맥락에 남긴다.
- **두 상태:** 기준안의 조건 요약과 현재 검토 조건을 구분한다. 차이 비교는 지원 단위·모집단·기간이 맞을 때만 수치화한다. 기준안이 있다는 이유로 다른 자료의 값을 직접 나누지 않는다.
- **기준 용어 구분:** ‘협의 기준안’은 복원할 작업 문맥, ‘비교 기준시점’은 두 시점 도표의 국소 조건, ‘지수 기준값’은 기준100 계산의 분모다. 한 개의 ‘기준’ 선택기에 합치지 않는다. 협의 기준안은 상세 왕복 때 덮어쓰지 않는다.
- **상세 왕복:** 협의 중 선택한 대상·조건·비교 보기로 상세 진입. 상세에서 바꾼 공통 조건은 돌아온 현재 검토 조건에도 반영한다. 질문·후보·기준안은 유지하며, ‘뒤로’가 기준안 복원처럼 동작하지 않는다.
- **결론의 경계:** 선택한 대안과 근거 조건·비교 결과·해석·미확인 사항을 연결한다. 조건이 달라졌다면 이전 해석을 새 결과의 결론처럼 남기지 않는다. 자동 광고 효과·인과 추론이나 합의를 흉내 내지 않는다. 기록·공유 UI의 추가 여부는 G1에서 기존 기능 재사용 가능성을 먼저 판단한다.
- **B 수용 기준:** 현장에서 조건을 바꿔도 큰 도표·현재 조건·비교 기준을 읽을 수 있음, 근거 상세→복귀 시 문맥 유지, 기준안 복원은 명시적으로만 실행, 후보 유지, 비교 불가를 설명하고 복구, 근거 부족하면 결론 유보 가능. 한 화면의 정보를 줄인다는 이유로 이 핵심 조작을 숨기지 않는다.

### 화면 하나의 설계 묶음

화면마다 다음을 한 묶음으로 만든다. 기능 목록만 작성하거나 정적인 기본 화면 한 장만 그리지 않는다.

1. 사용 목적·예상 판단·다음 행동과 A/B 시나리오.
2. 같은 실제 자료·지역·조건·화면 폭의 전/후 배치. 긴 상권명·14자리 매출·음수·0·결측 상태도 포함.
3. **상시 필수:** 현재 대상·기간/시각·업무 지표·핵심 단위·필수 집계/결측 경고. **요청 시 분석:** 비교·구성·정확값 표·상세 근거. **보조 메타:** 반복 출처·긴 방법·이미 설명한 단위 문구. 뒤 두 그룹도 용도에 따라 열 수 있게 하며 핵심 경고를 툴팁에만 숨기지 않는다.
4. 조회·선택·마우스 오버·키보드 초점·전체화면·로딩·무결과·미지원·오류·복귀의 예상 결과표. 같은 입력을 복제하지 않는다.
5. 지도/그래프 실제 그리기 영역의 전/후 치수, 글자 역할·선택 대비·동위 크기·정렬·축/라벨의 화면상 크기·가로 넘침 검사.
6. 조작·원자료 의미·시각 읽기·복귀의 개별 판정과 미검사 범위. 다음 화면으로 이동했다는 사실만으로 과업 성공이라 하지 않는다.

### 설계 시안의 대표 여정

1. 시작 → 구·동 인구 검토 → 생활인구2026-10-31·18시 구 분포 → 구 선택 → 정보 수치·시간 추이의 대상 일치 → 시각 변경 → 같은 구 값·지도색·그래프 선택점 일치.
2. 같은 지역 두 시점 비교 → 기준12시/선택18시 → 공통 눈금·같은 지역·단위 → 닫기 → 출발 지역·시각·카메라 유지.
3. 시간 추이 → 브리핑 장면 → 조건은 요약, 도표 확대 → 분석으로 복귀 → 같은 자료·대상·선택 시점.
4. 상권 대표3곳의 분기계열 → 종로3가역 선택·경계 확대 → 상세 → 같은 선택·분기·성별로 지도 복귀 → 종로구 범위 복귀. 실제 제공 분기계열을 사용하며 시점 생활인구와 곱하거나 나눠 가짜 전환율을 만들지 않는다. 전체 상권 탐색 완료를 주장하지 않는다.

## 11. 단계별 설계·적용과 영향 범위 — v2 기준

이전 v1의 D1–D6 ‘새 껍질→자료 이관’ 순서는 이번 지시로 대체한다. 새 단계는 G0–G4다. 각 단계에서 공간·가독성·동작·해석을 모두 다루며, 결함 종류별로 뒤 단계에 미루지 않는다.

| 순서 | 적용 단위 | 완료 판단 |
|---|---|---|
| G0 요구·기준선 | N01–N08과 현행 소스·화면 목록·과거 증거 대조, 모순 계약 정리. 구현 전 현재 버전에서 재현/해결/미검사 구분 | 문서 재검토는 이번 수행. 현재 화면 재실행·전체 목록 확정은 미수행. 과거 통과 소급 금지 |
| G1 공통 디자인·조작 설계 | 헤더/조건 요약/조회 편집/선택 정보/범례/그래프 옵션의 전후 시안과 정상·선택·오류·복귀 상태표. 기존 토큰·부품 우선 | A: 반복 조회·정확값 접근과 비교 기준/열린 모듈/선택/초점 보존. B: 주도표 집중과 근거 설명. 두 트랙 모두 글자·공간·대비·반응 판정이 있어야 다음 단계 |
| G2 실제 두 화면 묶음으로 적용·검증 | 생활인구와 상권을 대표 화면으로 사용. 각 화면의 분석/시연·상세/복귀를 함께 수정. 복잡한 실제 옵션·긴 값·미지원 조건을 제외한 축소 시안으로 대체 금지 | AB01/02의 A와 B 각각 통과. 선택→조회→지도/그래프/수치→상세→복귀·기준/대안의 의미를 실제 Chrome에서 원자료 대조 |
| G3 같은 원인의 전체 화면 확산 | 확인된 공통 수정만 생활이동·전출입·구/동 매출·비교·보조 분석·후보·시작/시연에 목적별 적용. 무조건 같은 배치 강요 금지 | 현행 소스로 화면/상태 목록 갱신 후 방문·후속 행동 기록, 공통 컴포넌트 소비자 누락 없음. AB03/04·무결과·키보드·기기·전체화면 회귀 |
| G4 필요한 구조만 변경 | G1–G3에서 해결되지 않은 메뉴·경로·다중 분석 문맥의 문제에 한해 대안 비교. 미래 역/부동산 확장은 호환성 검토 | 왜 국소 개선으로 안 되는지, 기존 작업 보존·이관 비용·두 트랙 효과 확인. 새 허브/전역 메뉴/저장·백엔드 일괄 도입을 완료 조건으로 삼지 않음 |

G2는 한 가지 자료만 완성하고 나머지의 읽기·동작 문제를 방치하는 순서가 아니다. 생활인구와 상권에서 서로 다른 자료·공간·기간 조건을 검증한 뒤 공통 원인을 확산한다. 작업을 막는 연동·의미 결함은 발견 즉시 같은 변경 묶음에서 다룬다.

분석 A에서는 조건을 연속 변경해도 비교 기준·열린 모듈·후보·선택·초점이 유지되는지 검사한다. 변경 조건 때문에 유지할 수 없다면 이유와 복구 경로를 표시한다. ‘상위 지도’, ‘이전 보기’, ‘조건 되돌리기’, ‘배치 초기화’의 범위는 분리하며, 이미 가능한 행동의 대체/공통화부터 검토한다. 새 되돌리기 이력 기능 전체를 선행 도입하지 않는다.

### 단계별 중단·통과 기준

- **설계 완료:** 화면별 N요구→전/후 시안→A/B 행동표→수용 기준이 연결되고 독립 검토의 모순을 처리한 상태. 문서 작성만으로 구현 완료가 아님.
- **화면 수정 완료:** 같은 조건의 지도/그래프/수치/설명이 맞고 핵심 도표를 실제로 읽을 수 있으며 상세/복귀가 이어짐. ‘그래프188px가 화면 안에 있음’은 노출 사실이지 충분한 가독성 증거가 아님.
- **확산 완료:** 현행 목록의 각 소비자에 적용/영향 없음/미검사를 표시. 클릭의 반응 유무뿐 아니라 다음 행동과 의미까지 검사. 모든 데이터 조합 통과를 주장하지 않음.
- **배포 완료:** 사용자 지시로 운영 반영하는 단계에서 빌드·독립 수치·실화면 검사 후 공개 페이지도 재검사. 이번 턴은 이 단계가 아님.

|---|---|---|---|
| 목적 중심 IA | Hero·전역 탐색·라우트 | 시작/재개·브리핑 복귀 | 현재 운영 코드 이번 미변경 |
| 공통 조회·상태 | main·MarketExplorer 조건 소유 재정의 | 지도·수치·순위·그래프·CSV·설명·요청 취소 | 원자료 산식·단위·결측 보존 |
| 모듈·비교 규격 | 상세·비교·시연·배치 | 폰트·축·표·툴팁·키보드 | 자료별 적합 도표 보존 |

## 12. v1 표본 동작 모형의 과거 검수와 제한

아래는 앞선 구조 설명 모형의 당시 확인 기록이다. v2 단계별 개선안의 새 화면·현재 운영 화면·분석 실무 전체의 검증 결과가 아니다. 이 시안은 이력으로 보존하며 이번 턴에는 수정·재실행하지 않았다. G1–G2에서는 복잡한 실제 화면의 전후 시안을 새로 만들어 검증한다.

[동작 모형 원본](prototypes/workspace-design.html) · [실제 화면·글자 검사](evidence/workspace-design/checks.json) · [시작 화면](evidence/workspace-design/home.jpg) · [분석 추이](evidence/workspace-design/analysis-trend.jpg) · [브리핑](evidence/workspace-design/briefing.jpg).

- Chrome에서 생활인구 성별·20–39세 변경,12시 변경, 추이→상세→두시각 비교→브리핑 연결을 확인했다. 조건 변경 후 선택기 초점을 유지했다. 시안의 지역 선택은 구 확대까지이며 동별 조회는 미구현임을 표시한다.
- 상권 종로3가역·여성·2026년2분기 선택→경계확대→상세→지도 복귀에서2,678,264명과 선택 조건을 유지했다. 직전 분기2,562,184명 대비+116,080명·+4.5%를 표시했다. 지도 색은 위치 표시이며 규모 비교는 수치·막대로 한다는 설명을 둔다.
- 독립 Codex 검토에서 강남구 두 날짜18시 전체·남/여20–39세 합계와 대표3상권의6분기 전체/남/여 값이 원본과 일치했다. 예:10/31 여성20–39세146,038.17명→표시146,038명. 시점 체류값을 일 방문객으로 합산하지 않았다.
- 실제 모형 영역 폭1648px 분석은12/14/16/20/28px,1106px 브리핑은14/18/28/36px,401px 브리핑은14/16/20/28px,384px 분석은12/14/16/20/28px였고 영역의 가로 넘침은 없었다. 이는 브라우저 모의 폭의 표본 장면 검사이며 실기기·모든 조합 통과가 아니다. SVG 축 문자를 HTML로 분리해 그래프 배율에 따른 글자 크기 변화를 피했다.
- 첫 방문의 가짜 재개 표시, 브리핑 글자5종, 상권 클릭 시 확대 누락, 입력 변경 뒤 초점 소실을 독립 검토에서 찾아 수정했다. 선택 정보창을 숨긴 상태의 상세 복귀 초점 대체 경로는 운영 이관 때 보강한다.

**모형과 운영 설계의 차이:** 모형은 대화 안에서 화면을 살펴보기 위한 축소된 범위다. 바깥 화면 고정·모듈320/560px·태블릿 단일 서랍·모바일 조회 전환은 운영 설계 규격이며 모형은 호스트 폭에 맞춰 패널을 세로 배치하고 도표280/340/350px를 쓴다. 조회 지원은 위 표의 두 날짜·두 연령 묶음·대표3상권에 한정된다. 후보3곳 보관, 브라우저 주소/뒤로가기, 읽던 위치 복원, 성별 두계열 동시 비교, 고급 도킹·투명도·크기 조절, 전체 자료, 전체화면,200% 확대는 이번 모형에서 구현·검증하지 않았다. 운영 기능을 제거한다는 뜻이 아니다.

현재 산출물은 **설계 제안과 표본 동작 모형**이다. 운영 코드·배포는 변경하지 않았다. 실제 사용자 과업 검증과 운영 이관은 별도 단계다.

이 절은 요구 재검토 당시의 기록이다. 이후 수행한 G0 실제 화면 표본 점검과 G1 실무/현장 협의 전후 시안은 [생활인구·상권 전후 시안 기록](paired-design-review.md)을 따른다. 운영 적용 G2와 구분한다.

- 독립 Codex 검토: 새 껍질 선행·시연 모형의 실무 대표성 부족·분석/시연 단방향 이해를 지적해 반영했다. 상권 선택의 R10/R12 모순과 전체화면 R05/R15 모순을 현행 소스·최신 사용자 지시에 맞춰 정리했다. 과거 모형 검수는 위 절로 구분했다.
- 확인: 변경 문서의 링크·요구 ID·단계 참조와 변경 형식 검사. 원자료·운영 소스·배포는 이번 변경의 영향 없음. 빌드/실화면/E2E/사용자 효과 시험은 이번에 수행하지 않았으며 과거 기록을 새 통과로 사용하지 않는다.
- 사용자 확인 완료: 시연은 광고주와 현장에서 비교하며 결론을 만드는 것이 중심이다. B트랙을 현장 협의로 구체화하고 현재 검토 조건/명시적 비교 기준안/상세 왕복을 설계했다. 영속 저장·버전 관리·자동 결론 기능은 여전히 미확정이며 선행 도입하지 않는다.
- 다음 산출물: G0의 현행 실화면 기준선, G1의 생활인구·상권 전후 디자인과 상태표. 현재 범위는 단계별 설계이며 G1 시안·G2 구현 완료를 뜻하지 않는다.
