# UX 감사 개선 1차 실행 보고

2026-11-14. 판단 목적은 ‘지도에서 조건을 바꾸며 후보를 조사하고, 조사 맥락을 잃지 않은 채 근거를 브리핑한다’이다. 사용자 지적을 독립 에이전트가 처음부터 다시 정리한 정본은 `docs/DASHBOARD_DEVELOPMENT_RULES.md`, 향후 작업의 연결 지침은 프로젝트 `AGENTS.md`다. 이번 적용 규칙은 R03–R12, R15–R17, R20–R21이다.

## 반영한 개발 규칙

|대상|기본 규칙|사용자가 조절하는 범위|
|---|---|---|
|주정보/보조정보|지도67:순위33, 최소 보조 너비280px|균형67/지도75/비교55, 지도비율55–75 슬라이더|

지도·순위가 합계·저장·긴 안내보다 먼저 나오도록 **DOM 순서도** 조정했다. 시연 세 장은 같은 프레임을 사용하고 보조 내용은 내부에서 펼친다. 사용자 지정 배치는 자료 수치·후보·색상 범위를 바꾸지 않는다. 같은 이름의 구·동 후보라도 실제 코드·독립 자료로 계산하며 지역 단위·면적 차이를 설명한다.

## 실제 실행 증거

Chrome **1800×961**, 정적 빌드. 실제 프로젝터·저시력 사용자·여러 브라우저/해상도 실험은 하지 않았다. 다른 해상도까지 통과했다고 주장하지 않는다.

- 기본4탭 실제 너비는 각각344px, 높이는54px로 같았다. 선택 번호 실제 배경rgb(255,210,138), 글자rgb(23,62,105), opacity1. 이 조합 대비약7.69:1, 흰 본문/남색약10.88:1이다.
- 분석 화면의 실제 표시 글자 집합은12/14/16/20/28/36px, 시연 시작·3장·전체화면·서식 펼침·포털 도움말은14/18/24/36px였다. 인포그래픽의 수치·부호·단위는 크기 제한 때문에 삭제하지 않는다.
- 첫 분석 화면 지도 범례 하단860.88px가 실제 viewport961px 안에 있었다. 화면 비율55/75에서 지도 패널 너비는746.9/1018.5px로 바뀌고 수치는 유지됐다. 지도380px 높이 선택, 초기화, 보조 순위5↔25, 접기↔다시보기 통과.
- 일반/전체화면 서울25구와 마포16동 이름의 bounding rectangle 겹침·SVG 밖 잘림0을 확인했다. 확대 상태도 확인했다. 작은 화면의 극단적 밀집은 최소충돌 배치가 필요할 수 있으므로 전 해상도 무겹침을 보장하지 않는다.
- 강남구/서교동/공덕동 후보를 담고 강서구로 옮겨도3개가 유지됐다.18시 전체값841,343/122,660/35,737,20–39세 여성으로 바꾸면146,038/41,256/5,851로 독립 원자료와 일치했다.
- 연간 전입 후보 강남/공덕/서교80,696/4,919/4,256, 순이동−1,728/−274/−250도 지역 변경과 무관하게 유지됐다. 전체화면에서 대상 변경과 후보 열기 경로를 확인했다.
- 기존 기능 E2E13개 통과. 신규 통합7개, 시각 규칙12개, 기존 인구확장5개, 색상 범위6개 확인. 색상 설정을 접힘으로 옮긴 뒤 적용·공백/−1/101오류·초기화도 다시 통과했다. 네트워크 오류 주입은 이번 범위에서 재실행하지 않았다.

실행 기록: `tests/ux-wave1-results.json`, `tests/ux-visual-rules-results.json`, `tests/ux-wave1-regression-results.json`. 기존 선택자 일부는 번호와 제목을 균등 flex 배치하면서 생긴 접근성 이름의 공백을 허용하도록 고쳤으며, 제품 동작 오류와 구분했다.

## 남은 항목

이 보고는 감사 전체를 완결했다고 뜻하지 않는다. 목적별 시작 화면의 차별화, 모든 차트의 공통 서식창 통합, 상권 성별/연령 주변분포 보조 차트, 긴 금액 대표단위의 전면 통일, 데이터 제공범위 확대, 인쇄/프로젝터/좁은 화면의 별도 검수는 후속이다. 이번 규칙의 크기·색·배치 기준은 보편적 최적 비율이 아니라 이 제품의 제한된 일관성 규칙이다.
