## 1. 확인한 출처와 실제 수집

- SHA256: `57ce0737c3fc3c6a3f7ac63dd7cf3b7b40c2fff1bf2175d48f4d6509add9884a`.

## 3. 2025년 ZIP과의 겹침, 미리보기 차이

최소 표본에 그치지 않고 **겹치는 67,113개 키 전체의 53필드**를 비교했다. 기존 ZIP의 CRC도 통과했다. ZIP에만 있는 키와 새 CSV의 2025에만 있는 키는 모두 0개다.

48개 수치 필드, 기간·행정동·업종 코드와 업종명은 모두 일치한다. 다만 7개 동 이름의 중간점이 물음표로 바뀌어 1,269행의 행정동명이 다르다. 따라서 두 원본을 바이트 또는 모든 문자열 동일이라고 부르면 안 된다. 기존 2025 행정동명을 새 CSV 이름으로 바꾸지 않는다.

`audit-results.json`은 비교 건수·차이 필드·대표 원본 레코드를 보존한다. 예를 들어 2025Q1/11110515/CS100001의 총매출 3,383,806,701원과 전체 필드가 일치한다. 2025Q4의 여러 동 표본과 미리보기의 5개 키도 ZIP/CSV를 대조했다.

**미리보기 응답과 CSV 사이에는 실제 수치 차이가 있다.** 2025년 5개 키에서 53필드씩 비교한 결과 총 63셀 차이(빈칸 대 CSV 0은 36셀, 비어 있지 않은 차이 27셀)다. 이 5개 키의 CSV는 ZIP과 모두 일치한다. 예를 들어 20254/11740700/CS300036 여성 매출은 미리보기 `182469`, CSV와 ZIP `1824690`이다.

2026년 5개 키에서는 100셀 차이(빈칸 대 0은 82셀, 비어 있지 않은 차이 18셀)다. 20262/11740700/CS300043의 목요일 매출은 미리보기 `198905`, CSV `1989050`이다. 문자열 말미 0이 빠진 듯한 사례를 관찰했으나 제공처 원인과 어느 출력 경로의 문제인지는 확정하지 않았다. 원본을 맞추려고 수정하지 않았고, 미리보기 빈칸을 근거로 CSV의 0을 결측으로 바꾸지도 않았다. 표본 차이를 전 행의 차이 비율로 일반화할 수 없다.

## 5. 확장 구현 계획 — 이번에는 적용하지 않음

1. **수집 경로:** `scripts/collect-commerce.py`는 현재 여러 데이터셋의 최신 ZIP을 받고 기존 raw와 `data/catalog-commerce.json`에 쓴다. 이 스크립트를 그대로 재실행해 2026을 얻지 않는다. OA-22175 전용 확장 수집기 또는 명시적인 Sheet 모드를 추가해 raw 파일·manifest를 불변 보존하고 실제 CSV 분기를 별도로 세도록 한다. manifest/자료 목록에는 ZIP 제공기간과 Sheet 확보기간을 구분한다.
2. **준비 경로:** `scripts/prepare-commerce.py`의 기존 ZIP 기준 2025년 1,700레코드를 모든 필드·순서 그대로 유지하고, 검증된 새 CSV의 20261/20262만 골라 같은 분기+동 합산을 적용한다. 대상 준비파일은 `public/data/commerce.json`이다. 현재 관측 기준 추가 850개, 합계 2,550개 분기·동 레코드를 예상하며 실제 생성 후 재검증한다. 2025 이름을 보존하고 새 이름의 물음표 원문은 출처 이력과 별도 관리한다. 미연결 2개 코드를 삭제하지 않고 coverage·미연결 목록·주석에 남기며, 결측 정책을 명시한다.
3. **검증기:** `scripts/validate-data.py`의 commerce 검사는 현재 2025 ZIP만 읽는다. 기존 2025 동별 매출·건수·6시간대 합계와 동일성을 유지하면서 새 CSV 2026 부분을 독립적으로 합산해 추가 검증하도록 확장한다. 분기 수·행 수·모든 공개 필드·null·중복·미연결 코드·원본 해시 관문을 둔다. 준비코드를 가져와 검증하지 않는다.
4. **공통 화면·캐시:** `src/main.tsx`의 commerce 데이터 로드에 자료 버전을 반영하고, `src/ExtraDashboard.tsx`가 읽는 periods·기본 선택·기간 표시·출처 안내를 실제 확보기간과 맞춘다. 기존 구현은 기간 목록을 자료에서 받으므로 필요 없는 화면 재설계는 하지 않는다. 영향을 받는 것은 일반 분석/시연의 행정동 추정매출 지도·순위·상세 추이·시간대·직전 분기 비교·후보·CSV다. 별도 `MarketDashboard`의 상권 매출 기간/업종/준비파일과 섞지 않는다. 현재 기본 직전 분기 비교를 전년동기 비교라고 부르지 않는다. 임의의 새 지원 차원은 추가하지 않는다.
5. **문서·검증 관문:** 승인된 후속 구현에서는 README·NEXT-SESSION·관련 요구/자료 계약에 행정동의 실제 지원기간·미연결 2동·Sheet 차이를 반영한다. R13/R18/R19/R20 영향으로 관리한다. 오프라인 재생성·2025 불변·원본 독립 수치 검증·단위검사·빌드 후 실제 Chrome 분석/시연에서 2025Q4→2026Q1/Q2, 전 구/대표 동/6시간대, 지도·상세·후보·CSV 같은 값, 상세 복귀 시 분기·지역·카메라 보존, 관측 없는 동과 미연결 안내를 확인한다. 실제 화면 대비·균등 크기·잘림도 검사한다. 향후 배포가 별도로 허가된 경우에만 배포 후 공개 데이터 해시·기간 선택지·대표 수치를 재확인한다.
