## 감독자 추가 지시 반영 — 동명 표시 결함 수정 (최종 12:12 KST)

- `prepare-commerce.py`는 물음표가 있는 2026년 이름에 한해 **동일 행정동 코드의 2025 공식 ZIP 이름**을 사용한다. 참조 이름이 유일하고 물음표가 없는지 확인한다. 임의 문자열 치환이나 유사 이름 추측은 하지 않는다.
- 2026년 850레코드 중 14개(7동×2분기)의 `name`만 화면용 이름으로 바꾸고, 해당 레코드의 `sourceName`에 CSV 원문을 보존했다. `provenance.displayNameCorrections` 14개에 기간·코드·원문·표시 이름·2025 참조 근거를 기록하고 출처 팝오버의 노트에도 7개 원문/표시 대응을 남겼다. 원본 CSV는 수정하지 않았다.
- 2025년 1,700레코드의 값·이름·레코드 순서·필드 순서는 시작 스냅샷과 계속 동일하다. 매출·건수·6시간대 값, 모든 분기 합계와 coverage도 불변이다. 전체 records의 화면용 `name`에서 물음표는 0개다.

## 화면 검사 최초 2건 실패 분석

분석/시연에서 첫 금액 검사의 기대값에 단위 앞 공백이 없었다. 기대 `25,036,425,038,435원`, 실제 `25,036,425,038,435 원`. 실제 `src/display-number.tsx`의 기존 exactNumber 계약은 숫자와 단위 사이에 공백을 넣는다. **두 실패는 검사 스크립트의 문자열 기대값 문제이며 제품의 매출 계산 결함이 아니다.** 최초 실행은 그 시점 이후 미실행이었다.

제품 표시는 바꾸지 않고 검사 기대값을 고쳤다. 복귀 버튼 locator도 실제 접근 이름의 화살표를 포함하도록 맞췄다. 이전 실패 증거는 `playwright-first-format-failure/`, `playwright-first-format-failure.json`에 보존했다. 최초 서버 EPERM은 환경 실행 차단으로 따로 기록하며 제품 실패 건수에 합치지 않는다.

이후 PC 1365×768·1920×1080에서 분석/시연 모두 통과했다. 여섯 분기의 서울 합계, 종로구→청운효자동, 2025Q4/Q1/Q2 각각 6시간대, 직전 분기 값, 실제 CSV, 출처 안내, 추이 팝업→본문→분기 변경→지도 복귀 시 분기·동·원값 보존을 확인했다. 새 캐시 키 요청·페이지 오류0·외부 요청0도 확인했다. 화면 배율은1이며 가로 넘침0, 지도 SVG 양수 크기/화면 내 배치를 측정했다. 현재 지도 캡처 4장을 직접 열어 확인했다.

기존 다른 작업자의 Playwright 묶음에는 행정동 commerce가 없어 산출물 폴더에 전용 설정/검사를 만들었다. `npm run test:e2e -- --config docs/workers-2026-11-17/w6-dong-sales-impl/playwright.config.mjs`로 실행했다. 다른 작업자 검사 파일은 손대지 않았다.

## 한계·인계

- 커밋·푸시·배포·외부 요청·pkill을 하지 않았다. 공개 재검수는 감독자의 배포 이후에 필요하다.
- 모바일은 사용자 지시로 보류. 태블릿·인쇄·전체화면·모든 조건·모든 상세/후보·합성색 대비 전수는 미검사다. 확대/카메라를 별도로 변형하는 회귀도 이번 여정에 포함하지 않았다.
- 동명 물음표의 사용자 노출은 감독자 지시로 수정했다. 화면은 동일 코드의 2025 이름을 사용하며 원문은 sourceName·주석에 보존한다. 작은 PC의 밀집 라벨 배치에 대한 전수 재설계/검증은 하지 않았다. 이 제품 동명 결함과 최초 자동검사 2건의 공백 기대값 오류는 구분한다.
- 미리보기/CSV 차이의 제공처 원인과 2026 실제 경계·소속 동일성은 미확정이다. 코드 연결 통과를 형상 동일성 통과로 쓰지 않는다.

상세 명령과 수치·미검사 범위는 `docs/dong-sales-2026-execution.md`에도 정리했다. 구현·로컬 대표 검증 완료 상태로 감독자에게 인계한다.
