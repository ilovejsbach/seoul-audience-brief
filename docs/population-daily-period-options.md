# 생활인구 일자 조회 기간 확장

2026-11-15 · R01/R06/R18/R20. 질문: 광고주가 다른 월의 같은 지역·시각·집단을 실제 일자별 자료로 조회할 수 있는가?

## 반영
- 기존 2026년 10월 31일 조회를 **2026년 1월 1일–10월 31일, 304일**로 확장했다. 동일한 OA-23016 현행 생산 방식의 원본만 사용한다.
- 조회 월→기준일 선택, 이전일·다음일을 제공한다. 월을 바꾸면 가능한 경우 같은 일자를 유지하고, 31일이 없는 달은 그 달의 마지막 제공일을 고른다. 이전/다음은 월 경계를 넘고 전체 기간의 양끝에서 비활성화한다.
- 일반 조회와 전체화면은 같은 날짜 상태를 사용한다. 지도 색상·지역 순위·현재 조건·시간 추이·CSV가 선택 날짜의 원값을 함께 사용한다. 월 선택은 월평균으로 바꾸는 조작이 아니다. 요일·월초/월중/월말 평균은 기존 별도 분석에 남긴다.

## 자료 구조와 배포 크기
- 기존 10월 일자 JSON 31개는 유지했다. 1–9월 273일은 같은 JSON 구조를 gzip 파일로 준비했다. 일자 하나를 선택할 때 해당 파일만 받아 브라우저에서 해제한다.
- 추가 gzip 파일 합계 267,722,990바이트. 304일 일자 파일 총 342,831,442바이트, public/data 전체 약492MiB로 GitHub Pages 1GB 미만이다.
- .json.gz 응답이 압축 상태인지 첫 바이트로 확인한다. CDN이 이미 해제한 JSON과 미해제 gzip을 모두 처리해 이중 해제를 방지한다. 실패하면 기존 오류·다시 시도 흐름을 사용한다. 응답에 요청 날짜를 함께 저장하고 현재 선택 날짜와 일치할 때만 지도·곡선·순위·대상 비교·CSV가 소비한다. 날짜 변경 직후 첫 렌더에서도 이전 날짜의 값이 새 날짜 아래 나타나지 않으며, 구 날짜 미리보기 팝업도 숨긴다.
- 원본의 32열·2자리 소수·0·비공개(null)를 그대로 보존한다. 원본 월 ZIP은 data/raw 아래에만 있고 공개 파일에 포함하지 않는다.

## 현재 검증
계산·자료 검사 9개 통과. 304일의 날짜 연속성, 3,115,392행의 날짜×24시간×427동 격자, 32열·결측 보존, 압축/기해제 응답 처리를 검사했다. 별도로 원본 CSV를 Decimal로 다시 합산한 6건을 대조했다. 2026-01-01 서울 전체18시 10,465,390.76명, 2026-01-31 공항동 청년남성12시 8,652.59명, 2026-02-28 강남구 여성18시 459,753.35명, 2026-07-31 창신1동 여성00시 비공개, 2026-09-30 강서구40–59세12시217,673.34명, 2026-10-31 공항동 청년남성12시7,676.14명이다.
