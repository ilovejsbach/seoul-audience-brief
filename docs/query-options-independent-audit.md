# 조회 옵션 독립 UX 감사

작성 기준: 2026-11-15 현재 작업 트리. 이 문서는 소스 구조의 독립 감사이며 새 브라우저 실행·공개 배포 검증 보고가 아니다. 참고 대시보드 조사는 별도 담당 결과와 합쳐야 한다. 이 감사에서는 소스를 수정하지 않았다.

## 핵심 판단

현재 문제는 버튼이 작동하느냐보다 **사용자가 어떤 질문을 하고 있고 지금 무엇을 바꾸는지** 읽기 어려운 데 있다. 조회 조건, 지도 탐색, 색상 표현, 창 배치가 같은 옵션 패널에 축적된다. 각 기능은 정당하지만 같은 빈도와 중요도로 노출할 근거는 없다.

사용자의 최근 화면 지적은 ‘모든 기능을 한곳에 넣은 결과’라는 경고로 읽어야 한다. 폭이 좁은 선택 상자와 옆 검색 버튼, 여러 시간 조작, 겹치는 투명 창, 배치 버튼이 늘어선 헤더를 각각 고치는 것만으로는 해결되지 않는다. **질문→필수 조건→결과→필요한 후속 행동**의 순서를 다시 설계해야 한다.

## 현재 옵션의 실제 목록과 목적

| 화면·소스 | 현재 조회 항목 | 판단 질문 | 구조상 위험 |
|---|---|---|---|
| 생활인구 `main.tsx` | 조회 월, 기준일, 조회 시각, 시간 슬라이더+앞뒤, 이전일/다음일, 자치구/행정동, 연령/성별, CSV | 어느 지역에 언제 어떤 사람이 머무는가? | 같은 시각을 select와 슬라이더로 연속 제시. 월·일·일 이동이 모두 앞부분을 차지. 지역마다 검색 버튼이 별도로 붙음. 분석 대상이 접혀 기본 전체 조건이 눈에 덜 들어올 수 있음. |
| 생활이동 `ExtraDashboard.tsx` | 자료일, 자치구, 유입/유출/차이, 도착/출발, 한 시간/누적/일계, 시각, CSV | 어디로 얼마나 이동하며 그 집계 기준은 무엇인가? | 시각보다 도착/출발·집계 방식이 의미상 우선인데 같은 일반 선택 상자에 섞임. 일계에서는 시각이 무효이므로 단순 비활성보다 이유를 바로 읽혀야 함. |
| 거주지 이동 `ExtraDashboard.tsx` | 연도, 자치구/행정동, 전입/전출/순이동 버튼, 전체/성별/연령, 세부 항목, 구성 분석 진입, CSV | 장기 거주 기반이 어디서 늘거나 줄고 어느 집단인가? | 세분 선택이 연도·공간 지원 범위를 바꿈. 자동 보정 안내가 떨어져 있으면 사용자가 예전 연도라고 오인. 구성 분석 ‘이동’은 조건과 다른 역할. |
| 구·동 추정매출 `ExtraDashboard.tsx` | 분기, 구/동, 매출 시간대, CSV | 어느 지역의 소비 규모가 크고 시간대 차이는 어떤가? | ‘상권 추정매출’ 용어가 상권 단위 작업공간과 혼동될 수 있음. 구/동 집계와 개별 상권은 별도 단위임을 제목에서 분명히 해야 함. |
| 상권 지도 `MarketExplorer.tsx` | 매출/유동인구, 분기, 구/동, 상권 이름, 유형, 매출 업종, 세부 기준 하나(시간·성별·연령·요일)+항목, 색상 분위/균등, 팔레트/범위, CSV | 어느 상권이 타깃과 맞으며 후보끼리 어떻게 다른가? | 실제 공간 조회·통계 주변분포·색상 표현이 한 controls에 누적. 구/동/유형/업종에 검색 버튼이 반복됨. 전체 조건 요약·상권 수·관측 수·여러 구 안내가 지도 위에 쌓임. |
| 그래프 `TrendExplorer.tsx` | 실제값/증감/기준100, 기준시점, 축(0/100중심/맞춤/직접), 여유, min/max/적용/초기화, 재생간격, 해석/계산, 위치·크기 초기화 | 같은 지역 값이 언제 얼마나 변했는가? | 표시 변환과 축은 다른 단계. 설정창에서 현재 축 요약·적용 기준 설명·원본 최대/직전차이가 중복될 수 있음. 그래프 헤더의 보조분석/두시점/옵션/지도/후보도 중요도 재분류 필요. |
| 공통 지도 `MapCanvas.tsx` | 구/동 단위, 확대/축소/맞춤, 색상 시작0/관측최소, 여유%, 팔레트, 직접min/max·±20%, 초기화, 범례 | 지도에서 차이를 어떻게 읽을 것인가? | 지역 단위는 조회 결과의 공간 단위, 확대는 카메라, 색상은 표현. 현재 조회창의 추가 host로 합쳐져 같은 역할처럼 보일 수 있음. 자동 기준과 직접 범위의 초기화도 구별 필요. |
| 창 배치 `MapPanel.tsx`, `MapWorkspace.tsx`, 지원창 | 좌/우/띄움, 이동/가로세로 크기, 투명도50–100, 위치·크기 초기화, 접기 | 결과를 가리지 않고 어떻게 작업공간을 쓸 것인가? | 조사 질문에 직접 답하지 않는 저빈도 기능. 반복 헤더에 상시 나열하면 내용보다 창 관리가 주인공이 됨. 투명도는 아래 지도와 글자가 겹쳐 오히려 읽기를 방해할 수 있음. |

소스상 `MapCanvas`는 외부 controls가 있는 경우 같은 표시 설정을 옵션 host로 포털 이동한다. JSX 대체 경로가 둘 있다는 사실만으로 화면에 중복 노출된다고 판정하지 않는다. 실제 중복 여부는 실행 DOM과 가시 상태를 확인해야 한다.

## 우선순위와 역할 분리 제안

### 가장 먼저 보여야 할 것

1. 현재 결과의 자료·대상·기간과 사용자가 답하려는 질문.
2. 그 질문을 바꾸는 최소 조회: 지역, 시점, 해당 자료의 핵심 지표/대상.
3. 결과를 보고 바로 할 행동: 상세, 후보 담기, 비교.

색상·축·범례는 결과의 해석을 바꾸는 표시 설정이다. 배치·투명도는 창 설정이다. CSV·출처는 근거 확인과 반출이다. 조회창에 함께 존재할 수는 있지만 같은 크기·기본 펼침·같은 시각적 무게를 주지 않는다.

| 합칠 것 | 나눌 것 | 의도 |
|---|---|---|
| 날짜+시각을 한 ‘시점’ 블록으로, 월은 달력/날짜 선택의 범위 탐색으로 흡수 | 시점 조작과 재생 속도 | 조사 시점 선택과 발표 재생은 목적이 다름 |
| select+별도 검색을 하나의 검색 가능한 선택 입력으로 | 상권명 자유 검색과 구/유형 선택 | 상권명은 직접 입력, 제한된 선택지는 목록 탐색 |
| 공간 조건 요약과 선택 해제 | 조회 범위와 클릭한 상세 대상 | 상세를 고른 행위가 조회 조건 변경이라고 오인되지 않게 함 |
| 색상 팔레트·자동/직접 범위를 한 표시 편집기로 | 조회 대상과 색상 편집, 카메라 맞춤 | 원값과 색의 변화가 혼동되지 않게 함 |
| 창 헤더의 배치·투명도·초기화를 하나의 ‘창 설정’ | 접기/닫기 | 닫기는 자주 필요하고 즉시 발견되어야 함 |
| 일반 설명을 가까운 도움말로 | 집계 방식·모집단·지원범위 변경 안내 | 결과 의미를 바꾸는 정보는 도움말에만 숨기지 않음 |

## P0: 개편 전에 확정할 것

- **정보 구조를 먼저 확정한다.** ‘자료·시점 / 지역 / 지표·대상’을 조회의 공통 뼈대로 삼되 자료별 필요 항목만 넣는다. 표시·창 설정·내보내기를 해당 뼈대의 동급 필터로 만들지 않는다.
- **조회창의 최소 기능 폭을 정한다.** 선택값과 레이블이 읽히는 폭을 보장한다. 좁은 상자 옆의 별도 검색 버튼이 폭을 잠식하는 구조를 기본 해법으로 유지하지 않는다. 넓은 창은 한 열을 넓히는 대신 논리적 그룹을 제한된 다열로 배치한다.
- **시간 조작의 주역을 하나 정한다.** 생활인구는 빠른 연속 탐색용 시간 슬라이더를 주 조작으로, 정확 시각 입력은 보조로 둔다. 생활이동은 도착/출발과 집계 방식을 먼저 고르고 그 뒤 유효한 시각만 조작한다.
- **투명도 기본100%를 유지하고 도구로 겹침 문제를 해결하지 않는다.** 먼저 창 위치와 크기·도킹으로 지도 가림을 줄인다. 투명도는 저빈도 창 설정 안에 두고 조절 후에도 내용 대비가 유지되는지 실제 화면으로 검증한다.
- **대표 화면을 먼저 검토한 뒤 전파한다.** 생활인구·생활이동·상권의 세 가지 구조를 실제 데이터로 설계 검증하고 공통 요소를 추출한다. 같은 폼을 모든 자료에 일괄 적용하지 않는다.

## P1: 실제 사용 흐름 개선

- 생활인구 순위는 `main.tsx`의 기존 `<aside className="panel ranking">`이며 `DockableRanking` 연결이 누락돼 있다. 다른 세 자료에 연결한 새 배치 기능이 생활인구에도 적용됐다고 보고하면 안 된다. 이번 감사에서는 이를 미완료로 기록하며 추가 코드 수정은 하지 않는다.
- 그래프 옵션은 초기화·접기와 여러 부가 단락이 남아 있고 새 자석/통합 창 설정 규칙이 적용되지 않았다. 화면 역할을 검토한 뒤 적용 범위를 결정할 과제이며 기계적으로 지도창 기능을 복제하지 않는다.
- 구/동 선택의 검색은 선택 입력 내부에서 시작해 목록을 여는 통합 조작을 우선 검토한다. 키보드·검색 무결과·현재0건 조건 해제·목록별 건수의 의미는 유지한다.
- 생활인구 날짜는 월/일/앞뒤일을 동시에 별개 줄로 강조하지 않는다. 대표 날짜와 앞뒤 탐색을 한 덩어리로 만들고 긴 기간 탐색은 필요할 때 확장한다.
- 거주지 연령 선택 시 ‘2025년·구 단위’로 바뀐 사실을 대상 입력 바로 옆에 표시한다. 전입/전출/순이동은 목적상 핵심 지표이므로 발견성을 유지한다.
- 상권은 ‘찾기’와 ‘세분 분석’을 분리한다. 이름·구·유형으로 대상을 찾은 뒤 업종/한 가지 주변분포를 선택한다. 성별×시간 등 없는 교차집계는 만들지 않는다.
- 지도 위 요약은 하나의 현재 조건 행을 기본으로 하고 건수·결측·정확 조건은 요약 또는 확장 영역에서 확인한다. 출발/도착·집계 방식은 핵심 의미라 축약 뒤에도 남긴다.
- 그래프 설정은 표시 방식→기준시점→필요한 축 설정 순으로 종속 노출한다. 설명은 통합하되 본문의 기준100·0 제외축 주의는 남긴다.
- ‘이동/크기 조절 방법’의 상시 설명 줄은 도움말이나 최초 안내로 옮기는 것을 검토한다. 제목과 접기, 단일 창 설정만 헤더에 남긴다.

## P2: 검증 후 적용할 편의 기능

- 최근 사용 조건/저장 조건은 기존 기능과 연결하고 새로운 조건 패널을 중복 생성하지 않는다.
- 시연은 조회창 기본 접힘, 현재 조건에서 직접 편집, 한 장면 복귀를 유지한다. 분석용은 그룹 펼침 상태를 유지하되 최초 과밀 노출을 막는다.
- 창 설정은 필요하면 자료별이 아닌 역할별로 일관되게 기억한다. 조건·후보·색상 범위 초기화와 배치 초기화를 명확히 구별한다.

## 실행 검증에서 확인할 판정 기준

1. 사용자가 첫 화면에서 ‘어느 자료·지역·시점·집계’를 보고 있는지 읽고, 필요한 조건 한 가지를 찾아 바꿀 수 있는가?
2. 조건 입력→지도·숫자·순위·그래프의 의미상 변화→개별 해제→복귀가 이어지는가? 모르는 조건을 숨겼다는 이유로 성공을 선언하지 않는다.
3. 220px 고정창, 기본 플로팅, 가로 확장, 세로 축소, 좁은 화면에서 선택값·버튼·도움말이 잘리지 않는가?
4. 지도 중심 영역이 다른 고정창을 모두 제외하고 최소540px를 유지하는가? 두 플로팅이 겹칠 때 제목·접기·초점 우선순위가 살아 있는가?
5. 0건/자료 없음/미지원/실제0이 다른 설명과 복구 경로를 갖는가? 조건별 건수는 독립 fixture와 일치하는가?
6. 폰트 종류/크기 제한과 읽기 대비를 지키는가? 투명50%에서 뒤 지도 라벨이 앞 입력의 값을 혼란스럽게 하면 기능 통과와 별개로 UX 실패다.

현재 판정: 구조적 과밀 위험은 소스에서 확인했다. 사용자의 첨부 화면 지적은 시각 문제의 근거이며, 이 문서 작성자가 최신 구성을 실행해 재현한 결과로 대체하지 않는다. 현재 실제 실행·시선 이동량·소요 시간·공개 화면은 미검사다. 개편과 배포를 진행하기 전에 참고 사례와 대표 화면 설계를 먼저 검토해야 한다.

## 부모가 전달한 실제 화면 관찰

아래는 부모 에이전트의 실행 결과를 전달받은 기록이며 이 감사 작성자가 직접 실행한 결과와 구별한다.

- 4자료 지도 조회창의 고정 폭220px와 플로팅560×360px에서 기간/지역 두 열의 높이 불균형, 정확 시각 선택과 시간 슬라이더 중복이 관찰됐다. 기능 배선과 별개로 정보 구조의 재설계가 필요하다.
- 수정된 검색 영역134px/검색 버튼42px 배분, 제목+창 설정+접기로 정리된 헤더, 배경100% 기본은 부모의 확인 범위에서 정상이다. 정상인 고정 폭을 다시 손보는 것보다 검색 조작 자체의 역할을 재검토한다.
- 그래프 옵션의 부가 단락 과다와 생활인구 순위 배치 기능 누락이 확인됐다. 위 P1에 미완료로 기록했다.

공개 배포와 새 개편은 사용자 요청에 따라 보류한 상태로 이해한다. 이 결과를 완성 UI의 수용 통과나 전체 화면 전수 실행으로 확대 해석하지 않는다.
