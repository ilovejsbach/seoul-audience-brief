# 독립 조회창·기간 선택 구현과 실행 검수

2026-11-15. 질문: 광고 입지를 비교하면서 옵션창을 지도 밖에 놓고, 다른 월의 실제 날짜를 같은 조건으로 조회할 수 있는가?

## 반영한 화면과 동작
- 일반 인구·이동·전출입·매출 및 상권의 플로팅 조회창을 지도와 스크롤 부모 밖의 화면 전역 레이어로 옮겼다. 기본 560×360px, 최소 높이 220px이며 제목·모서리의 드래그와 방향키로 위치·크기를 바꾼다. 화면 경계만 제한한다.
- 지도를 눌러도 조회창은 열려 있다. 접기·Esc로 닫으며 버튼으로 초점을 돌린다. 다른 탭·장면·시작 화면으로 이동하면 해당 조회창은 숨고 복귀하면 원래 상태를 사용한다. 고정 배치와 위치·크기 초기화도 유지한다.
- 글자 크기를 줄이지 않고 그룹·입력 여백을 줄였다. 넓은 창은 라벨과 입력을 나란히, 중간 폭은 기간/지역·대상을 비대칭 두 열로, 큰 폭은 세 그룹을 한 줄로 배치한다. 1/2/3열은 창 자체 너비를 따른다.
- 생활인구를 2026년 1월 1일–10월 31일 **304일 일자별 지도**로 확장했다. 조회 월→기준일, 이전일·다음일을 제공한다. 월을 바꿔도 가능한 같은 일자를 유지하고 없는 날짜는 월말로 맞춘다. 월 선택은 해당 월의 평균이나 합계를 의미하지 않는다. 요일·월 구간 평균은 별도 분석에서 조회한다.
- 이동은 확보 일자의 시각, 전출입은 연도, 매출·상권은 분기를 유지한다. 자료가 없는 기간을 선택 가능한 것처럼 만들지 않는다.

## 간접 영향과 안전장치
- 전체화면에서는 조회창과 설명 툴팁의 포털 대상을 해당 전체화면 요소로 바꾼다. 앱 모드·글자·색상 변수를 독립 창에 전달하며 배경 레이어는 투명하고 창 밖 지도는 계속 조작한다.
- 날짜 응답을 요청 날짜와 함께 저장하고 선택 날짜와 일치할 때만 소비한다. 오래된 응답·값이 새 날짜의 지도·순위·곡선·타깃 비교·CSV·팝업에 섞이지 않는다.
- 추가 273일은 일자별 gzip JSON으로 필요할 때 한 파일만 읽는다. 원값·비공개값을 보존하며, 서버가 압축 해제를 한 응답도 처리한다. public/data 약492MiB, 빌드 결과 약525MiB다. 원본 ZIP은 공개하지 않는다.
- 주민등록 보조 자료의 설명은 선택 생활인구 기준일과 주민등록 기준연도가 다르다는 문구로 일반화했다. 통계값은 변경하지 않았다.

## 실제 검사
Chrome 1800×961에서 다음을 실행했다.
- 자유 이동·지도 클릭 유지·시연 장면 수명·전체화면 조회·고정/초기화/상권 복귀: 5개 시나리오.
- 1월 실제 값·월 경계·2월 말일·공항동 연령/성별·전체화면 기간 동기: 4개 시나리오.
- 다섯 조회창 각각 300/560/900px 및 낮은 높이·재열기 검사. 가로 넘침 0, 최소 창 높이에서 본문 172px.
- 색상 범위 4개와 핵심 분석 5개 회귀 경로 통과.
- 자료·계산 검사 36개 통과. 304일 3,115,392행의 격자 및 독립 원본 Decimal 대조 6건 포함.
- 2026-01-01 서울 전체18시 10,465,390.76명(표시10,465,391명), 2026-01-31 공항동 청년 남성12시 8,652.59명(표시8,653명)을 실제 지도와 대조했다.

## 공개 자료 목록의 캐시 보완
첫 공개 검증에서 새 화면이 이전 31일 목록을 브라우저/CDN 캐시에서 읽는 현상을 재현했다. 304일 목록 요청에 자료 범위 버전을 붙여 이전 목록과 구분했다. 목록 준비 중에는 월 선택을 비활성화하고 준비 중 문구를 표시하며, 날짜 자료 로딩 중에도 기존 선택 지역 목록을 유지한다. 기간 E2E는 적용 날짜와 자료 준비 상태를 기다린 뒤 후속 동작을 검사한다.
