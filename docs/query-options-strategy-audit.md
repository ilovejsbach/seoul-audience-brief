# 조회 옵션 전략 검토

2026-11-15 · 독립 소스 감사 · R01/R03/R05/R06/R13/R18/R20.

이 문서는 현재 코드에서 확인한 동작과 적용 제안을 구분한다. 새로운 옵션을 구현하거나 브라우저에서 전수 실행한 보고가 아니다. Tableau 공식 기능·사례 조사는 부모 작업의 별도 근거이며, 이 문서는 우리 데이터·화면에 맞는 적용 가능성을 판정한다.

## 사용자가 하려는 일
광고주는 ‘어느 자료로, 어느 지역·기간·대상을 보고 있는가’를 알고, 조건 하나를 바꾼 결과가 지도·핵심 수치·순위·추이에 일치하는지 확인하려 한다. 시연자는 설명 중인 화면을 유지한 채 필요한 조건만 잠깐 열어 바꾸려 한다. 조회 옵션이 모든 분석 기능을 나열하는 메뉴가 되어서는 안 된다.

## 현재 소스에서 확인한 것

## 우선 적용 제안 6개

### 1. 조회 조건, 지도 선택, 표시 설정을 다른 역할로 읽게 한다 — 최우선
**현재:** 동일 패널 안에 자료/기간/공간/인구조건과 색상/축/배치가 섞여 보일 수 있다. 상권은 네 묶음이 있으나 일반 자료들은 각자 항목 순서가 다르다.

**제안:** 공통 순서를 `자료·기간 → 지역 → 지표·대상 → 보기 설정`으로 통일한다. 첫 세 묶음은 결과의 모집단·시점·지역을 바꾸는 조회 조건이고 마지막은 색·축·배치만 바꾼다고 이름과 설명에서 구분한다. 자료 자체 선택은 상단 주메뉴와 중복시키지 않고 전체화면 등 주메뉴가 없는 곳에만 독립 선택을 둔다.

지도에서 선택한 지역/상권은 ‘지금 상세로 읽는 대상’, 지역 필터는 ‘지도에 남겨 두는 범위’라고 구분한다. 상권을 누른 것만으로 전체 지도의 나머지 상권을 제거하거나 후보를 잃게 하지 않는다. 후보 비교와 단순 선택도 구분한다.

**수용 기준:** 자료 전환·선택·색상 변경 각각에서 지도 영역·핵심 수치·순위·추이·CSV가 예상한 범위만 바뀌며 서로 다른 조작을 하나의 ‘필터 적용’으로 설명하지 않는다.

### 2. 실제 가능한 값만 안내하는 종속 옵션을 강화한다 — 최우선
**현재:** 구→동은 종속되지만 상권 유형은 전체 원본의 목록이며, 이름/지역 조건과 조합하면0건일 수 있다. 거주지 연령·성별의 지원 기간·단위는 안내되지만 기간 목록 자체가 항상 세분 기준으로 좁혀지는 구조는 아니다.

**제안:** 옵션은 ‘전체’와 현재 값이 사라지지 않게 하면서 관련 조건의 결과 수 또는0건을 표시한다. 구·동과 자료별 지원 기간은 가능한 목록을 우선 제공한다. 불가능해진 기존 선택을 자동 변경할 때는 무엇을 왜 바꿨는지 짧게 알린다. 단지 목록에서 사라져 선택이 초기화된 것처럼 느껴지게 하지 않는다.

상권의 성별·연령·시간·요일은 **한 가지 세부 기준**을 유지한다. 서로 다른 주변분포를 교차 필터로 오해하게 하는 다중 체크박스는 넣지 않는다. 반면 생활인구 원자료의 실제 연령×성별 교차는 그대로 제공한다. 자료마다 지원 범위가 다르므로 모든 패널에 같은 대상 옵션을 복제하지 않는다.

**수용 기준:** 연령2025구→성별2021–25구/동 전환, 다른 구 선택, 상권 이름+유형+구 조합의 현재 선택·무결과 이유·복구를 독립 판정한다.0건과자료없음/비공개는 구분한다.

### 3. 현재 적용 조건을 짧은 칩으로 읽고 범위별로 해제한다 — 높음
**현재:** 지도 조건 요약과 상권 공간 조건 문자열은 있지만 여러 조건이 긴 문장으로 읽히고 개별 해제는 주로 옵션창으로 돌아가야 한다. 현재 선택 지역과 조회 범위도 혼동될 수 있다.

**제안:** 결과 가까이에 `2026년1분기`, `마포구`, `연남동`, `이름:홍대`, `골목상권`, `20대`처럼 의미 단위 요약을 둔다. 바꿀 수 있는 조건 칩을 누르면 해당 옵션을 열고, 지울 수 있는 공간/검색/유형 칩에는 해제 행동을 둔다. 필수 기간·자료는 삭제하지 않고 변경으로 연결한다. 공간 필터와 별도의 ‘선택 상권’ 요약은 해당 선택만 해제한다.

시연에서는 칩을 여러 행으로 쌓지 않는다. 핵심 조건 한 줄+‘나머지 조건’ 펼침으로 읽으며, 해석에 필수인 출발/도착·한시간/누적·자료 기준일은 숨기지 않는다.

**수용 기준:** 칩 제거가 다른 조건·후보·카메라를 불필요하게 초기화하지 않는다. 닫힌 조회창에서도 실제 적용 상태를 정확히 읽는다.

### 4. 즉시 반영을 기본으로 유지하고 무거운 조작만 다르게 다룬다 — 높음
**현재:** 일반 드롭다운·상권 검색은 즉시 반영한다. 색상/축의 직접 min/max는 검증 후 적용 버튼을 사용한다. 상권 검색·구·동·유형 변경은 매번 카메라를 초기화한다.

**제안:** 드롭다운마다 ‘적용’을 추가하지 않는다. 정적 파일을 읽은 뒤 계산하는 현재 조회는 즉시 결과를 확인하는 것이 단순하다. 검색 입력은 짧은 입력 지연이나 Enter 확정 중 실제 실행 시간을 본 뒤 선택한다. 예를 들어 짧은 입력 지연을 시험할 수 있지만 특정 밀리초를 보편적 최적값으로 단정하지 않는다. 값 입력 도중 중간 상태가 잘못된 직접 축/색상 범위는 지금처럼 별도 적용과 오류 복구를 유지한다.

지도 범위 맞춤은 검색 결과를 보이게 하는 명시적 도구로 남긴다. 검색 한 글자마다 카메라가 재배치되는 것이 브리핑에 도움이 되는지는 실제 시나리오에서 측정해 결정한다. 무거운 원격 조회를 도입할 때에만 ‘변경 중 조건’과 ‘현재 적용 조건’을 분리한 적용 버튼을 검토한다.

**수용 기준:** 연속 입력에서 이전 결과가 새 조건 제목으로 남지 않는다. 적용 버튼을 도입했다면 화면은 적용 전/후를 명확히 구분하고 CSV도 현재 적용 조건을 따른다.

### 5. 초기화와 되돌리기의 범위를 분명히 한다 — 중간
**현재:** ‘배치 초기화’는 좌우 크기·띄움·좌표, ‘지역·검색·유형 초기화’는 상권 공간 필터, ‘직접 범위 초기화’는 색상 수동 설정을 각각 다룬다. 이 분리는 이미 타당하다. 다만 조회 전체를 처음 상태로 복원하는 동작이나 직전 조건 되돌리기와 동일한 기능은 아니다.

**제안:** 기존 범위별 초기화 명칭을 유지하고, 필요가 확인되면 별도의 ‘조회 조건 초기화’ 또는 ‘직전 조건으로’만 추가한다. 이때 자료·기간·선택 상권·후보를 어디까지 복구하는지 먼저 계약을 정한다. 모든 초기화를 ‘초기화’라는 한 이름으로 바꾸지 않는다. 일반 분석의 `ScenarioWorkbench`는 조건 저장/재적용 기능이 있으므로 같은 목적의 새로운 저장 기능을 중복 생성하기보다 적용 가능성을 먼저 검토한다.

**수용 기준:** 배치를 초기화해도 조회 수치가 바뀌지 않고, 공간 초기화가 세부 기준/색상 수동 범위/후보까지 지우지 않는다. 저장 조건 재적용 시 지원하지 않는 현재 자료에 억지로 값을 넣지 않는다.

### 6. 시연에서는 짧은 조건 진입, 분석에서는 작업용 조건창을 사용한다 — 중간
**현재:** 고정/이동 조회창과 화면 밖 배치, 비활성 화면의 창 숨김을 이미 제공한다. 시연 상세는 별도 분석 화면으로 교체하며 옵션을 계속 펼쳐 두지 않는 방향이다.

**제안:** 두 모드가 같은 조회 상태를 사용하되 시연은 ‘조건’ 단추와 한 줄 현재 조건 요약을 우선한다. 열면 마지막 사용한 의미 묶음을 보이고, 현재 결과를 가리는 기본 크기·위치는 실제 화면에서 조절한다. 분석은 여러 번 조건을 바꿀 수 있는 고정 왼쪽 패널이 기본이다. 이동창의 폭에 따른1/2/3열 반응형은 유지한다. Tableau처럼 보이게 하려고 모든 옵션을 오른쪽에 상시 나열하지 않는다.

**수용 기준:** 시연 조건 변경→그래프·지도 결과 확인→닫기 후 현재 조건 유지, 자료 전환 때 이전 창 정리, 좁은 PC에서 줄바꿈·모든 입력 접근·Esc 초점 복귀를 검사한다.

## 제공하지 말아야 할 가짜 기능
- 상권 주변분포의 성별×연령×요일×시간 다중 교차 필터.
- 생활이동에 현재 확보하지 않은 직업·관광객 세분을 UI만 먼저 추가하는 것.
- 생활인구 월 선택을 월 누적 고유 방문자로 표시하거나 임의 기간 합계를 방문자 수로 만드는 것.
- 연령별 전입·전출을 미지원 연도·동 단위에 추정해서 채우는 것.
- 다른 시기의 인구와 매출을 필터 동기화만 했다는 이유로 광고 구매전환율로 계산하는 것.

## 권장 다음 단계
1–3번의 역할·종속 값·현재 조건 요약부터 간단한 설계 시안으로 검토한다.4–6번은 실제 입력 속도·카메라 이동·기존 저장 조건 사용 여부를 보고 결정한다. 외부 도구의 기능 수를 따라가기보다 ‘같은 조건을 읽고 한 가지를 바꿨을 때 결과가 명확한가’를 수용 기준으로 삼는다.
