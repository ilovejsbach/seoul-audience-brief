# 의미를 확인하는 E2E 인수 기준

## 판정 목적

옵션을 누른 뒤 숫자가 나타나는 것만으로 통과시키지 않는다. 선택한 지역·기간·업종·분포가 원자료의 어느 열과 행을 뜻하는지, 결과가 그 범위 안에서 올바르게 설명되는지까지 확인한다. 광고주에게 후보지를 설명하는 데 사용할 수 있는 결과인지가 기준이다.

이 문서는 검증 기준이며 브라우저 실행 완료 보고가 아니다. 실제 조작 결과와 실패 화면은 E2E 실행 담당자가 별도로 기록한다.

## 독립 기대값

[semantic-fixtures.json](../tests/semantic-fixtures.json)에 원자료를 직접 읽어 계산한 119개 사례를 저장했다. 화면 계산 함수와 준비된 공개 JSON을 기대값 계산에 사용하지 않았다. 각 원본의 경로·공식 URL·바이트 수·SHA256을 함께 기록했다. 원본이 바뀌면 기존 기대값을 새 데이터에 그대로 적용하지 않는다.

각 사례는 `scope`(지역·기간·조건), `aggregation`(합산 방식과 열), `expectedExact`(원값), `expectedDisplay`(표시 참고), `meaning`(허용 해석), `forbiddenMeanings`(금지 해석), `assertions`(연동 조건)를 가진다. 화면 표현은 자연스러운 동의어를 허용하지만 의미와 범위가 빠지면 실패다. 축약 단위가 있으면 원값을 환산해 확인한다. 화면 반올림 오차만 허용하며 CSV 원값에 반올림을 역적용하지 않는다.

## 실제 조작 절차와 통과 조건

1. 상권 분석에서 공덕을 검색한다. 네 상권의 코드와 이름이 기대값과 일치해야 한다. 공덕역은 `3120107`이며 대표 행정동은 도화동이다. 이름에 공덕이 있다는 이유로 공덕동으로 대체하면 실패다.
2. 매출·분기·업종·분포를 사례별로 바꾼다. 지도, 순위, 상세값, 시계열 현재점, 이전 분기, 차이, CSV가 동일 조건을 사용해야 한다. 이전 분기만 전체 업종이나 전체 인구로 되돌아가면 실패다.
3. 유동인구로 바꾸고 2026년 2분기를 선택한다. 총계와 각 분포 값이 원본 열과 일치해야 한다. 남성·20대·금요일·17–21시는 서로 별도의 주변 분포다. 이들을 곱하거나 연속 선택해 결합 타깃 인구라고 설명하면 실패다.
4. 생활이동에서 2026년 10월 31일, 마포구, 도착 기준 18시를 선택한다. 구내 이동을 제외한 유입 분모는 59,831.71, 유출 분모는 52,525.73이다. 서울 밖 유입은 17,667.68(29.5%), 유출은 15,924.53(30.3%)이다. 서대문구 유입은 6,838.01(11.4%), 유출은 6,147.11(11.7%)이다. 비중 분모가 상위 몇 곳의 합이면 실패다.
5. 생활인구에서 같은 원본 날짜의 삼청동 남성을 확인한다. 02–09시는 비공개이며 0명으로 그리면 실패다. 최대값은 공개 16시간 중 15시의 7,426.53명이다. 이를 하루 전체에서 확정된 최대라고 표현하면 실패다.
6. 조건을 바꾼 뒤 후보를 저장하고 다시 적용한다. 저장 당시 조건과 현재 조회 조건을 구별해야 한다. 표시된 후보값이 어떤 조건의 값인지 알 수 없거나 CSV에 그 조건이 빠지면 실패다.

## 숫자가 맞아도 실패하는 해석

- 상권 유동인구 원본 추정치를 하루 고유 방문자, 매장 방문자, 광고 노출 인원으로 바꾸어 부른다.
- 분기 제공 값을 월·일 합계로 임의 환산하거나 시간대 분포를 시간별 추이로 설명한다.
- 매출의 `당월`이라는 원본 필드명만 보고 분기 자료를 월 관측값이라고 설명한다.
- 남녀·연령별 매출의 합이 전체와 다르다는 이유로 원값을 보정한다. 원자료의 차이를 보존해야 한다.
- 상권 경계·제공 업종 합계를 서울의 중복 없는 전체 소비나 전체 인구로 설명한다.
- 도착 18시 유출을 마포에서 18시에 출발한 이동으로 설명한다. 유출도 도착 시각 조건이다.
- 생활인구의 시간별 재실 추정치를 전입·전출 주민 수나 하루 누적 고유 인원으로 설명한다.
- 조회값 차이를 광고 효과나 미래 예측으로 설명한다.

## 결과 기록

실행 보고는 사례 ID, 실제 조작 조건, 기대 원값, 관측값, 화면 의미, CSV 조건, 통과/실패, 증거 경로를 남긴다. 일부 사례만 실행했으면 통과 수와 미실행 수를 구분한다. 실제 확인한 화면 크기만 기록한다. 화면에 숫자가 존재한다는 검사는 보조 검사이며 위 의미 판정을 대신하지 않는다.

## 모든 옵션의 원본 열 대응

공덕역 매출과 유동인구는 각각 전체1·시간6·성별2·연령6·요일7의 22개 옵션을 전수 포함한다. 기존 26개를 유지하고 빠진 옵션 32개를 추가하여 총 58개다. 추가 사례의 `aggregation.rawColumnIndex`, `sourceColumn`, `optionLabel`은 원본 CSV의 0부터 시작하는 열 번호·원래 필드명·사용자 선택 의미를 함께 기록한다. 모든 사례는 현재·직전 분기·차이를 원본에서 독립 계산했다.

## 업종 옵션 전수

원본 전체에서 확인한 62개 업종의 코드와 이름을 공덕역 2025년 4분기·3분기에 각각 대입했다. 한식 기존 사례를 재사용하고 나머지 61개를 추가하여 총119개다. `scope.industryName`으로 선택 라벨도 확인한다. 원본행이 없는 업종·분기는 값과 차이를 null로 유지하며, CSV 빈칸·화면 자료 없음·추이 null 지점이 정상이다. 제공 62개 업종 전체와 공덕역에 실제 행이 있는 업종 수를 혼동하지 않는다.
