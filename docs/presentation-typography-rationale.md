# 분석·시연용 글자 크기 개발 기준

조사일: 2026-11-14. ‘사람에게 가장 편한 단일 비율’이 모든 한글 화면·시청 거리·시력에 통한다는 근거는 확인하지 않았다. 따라서 황금비 같은 숫자를 편안함의 보편 법칙으로 사용하지 않는다. 공식 디자인 시스템의 역할별 타입 토큰·일관된 단계·가독성 검증 원칙을 가져와, 이 제품의 지도/자료 밀도에 맞춘 제한된 부분집합으로 적용한다.

## 참고 근거와 적용 판단

- [GOV.UK Type scale](https://design-system.service.gov.uk/styles/type-scale/): 기기별 읽기 검증을 반복한 타입 단계에서 새 요소를 시작하도록 권고한다. 큰 화면 예시의 36/24/19/16px 등은 역할과 줄간격을 함께 정의한다. 특정 폰트·영문 서비스의 값을 한글 브리핑에 그대로 최적값이라고 부르지 않는다.
- [GOV.UK Paragraphs](https://design-system.service.gov.uk/styles/paragraphs/): 일반 본문과 작은 보조 본문의 역할을 구분하며 작은 본문은 제한적으로 사용한다. 이 대시보드도 보조 크기를 본문 대신 화면 전체에 남용하지 않는다.
- [IBM Carbon Typography](https://www.carbondesignsystem.com/building-blocks/foundations/typography/overview): IBM Plex를 바탕으로 역할별 폰트 크기·굵기·행간 토큰을 사용하고, 업무용과 표현용의 위계를 나눈다. 제공 단계에는 12/14/16/18/20/24/28/36px가 포함된다. 현재 프로젝트가 쓰는 IBM Plex Sans KR와 연결되는 공식 계열이다.

위 원칙과 Carbon 단계 중에서 시연은 4단계, 분석은 6단계만 선택한다. 이는 제품 구현 규칙이며 사용자 연구로 입증된 유일한 최적 조합이라는 주장은 하지 않는다.

## 시연용: 4단계

|크기|역할|배정|
|---|---|---|
|14px|보조·조작·축|기준일·출처·단위·탭 번호·부가 조작·차트 축·일반 지도 지역명|
|18px|주된 읽기·선택|본문, 주된 버튼과 탭, 순위, 전체화면 지도 지역명|
|24px|제목|장면 제목·패널 제목·미리보기 지역명|
|36px|핵심 수치·시작 의제|대표 지표·비교 수치·시연 시작의 제목|

## 분석용: 6단계

|크기|역할|배정|
|---|---|---|
|12px|메타 정보|출처·축·기준 설명·보조 조작·탭 번호|
|14px|조건·보조 본문|조회 조건·폼·도움말·일반 지도 지역명|
|16px|본문·목록|본문·지역 순위·선택 지역명·전체화면 지도 지역명|
|20px|패널 제목|지도·차트·세부 분석 패널 제목|
|28px|페이지 제목|분석 시작·분석 화면 제목|
|36px|핵심 수치|주요 지표·후보 값·선택 시점 값|

크기만으로 위계를 만들지 않는다. 같은 역할에는 같은 크기를 쓰고, 굵기400/500/600, 색상, 간격, 정렬로 구분한다. 글자가 길다는 이유로 별도의 크기를 만들거나 `clamp()`로 계속 다른 크기를 생성하지 않는다.

## 행간·수치·지도

- 본문은 대체로1.6–1.65, 제목은1.35–1.45, 큰 수치는1.3 수준을 기준으로 한다. 단위 없는 행간은 글자 크기나 브라우저 확대에 따라 함께 커진다. 여러 줄 한글 문구의 잘림·밀도는 실제 화면에서 확인한다.
- 수치는 기존 tabular 숫자를 유지한다. 긴 금액을 임의로 작게 줄여 일곱 번째 크기를 만들지 않는다. 영역 너비/줄바꿈/축약표기+정확값 도움말로 해결한다.
- 지도 지역명의 크기는 원근/줌 배율에 따라 다른 CSS크기를 만들지 않는다. `--map-label-size`는 일반/전체화면 모드의 지정 단계만 쓴다. 부모 구현에서 도형 줌/뷰박스 배율을 상쇄해 실제 화면 글자 크기를 유지한다.
- body에 포털로 그리는 데이터 도움말도 현재 `.app.mode-*`를 확인하는 선택자로 같은 단계에 포함한다.

## 적용 파일과 검수

- 시연: `src/presentation-type-scale.css`
- 분석: `src/analysis-type-scale.css`
- 두 파일은 `@layer dashboardTypography`에서 font-size의 important 선언만으로 기존 혼재된 important 규칙을 대체한다. 역할 배정 이외의 색·레이아웃·데이터 값은 바꾸지 않는다. 지도 변수도 레거시 비레이어 규칙에 밀리지 않도록 important 지정한다.
- 부모가 main에서 두 CSS를 import한 뒤 실제 Chrome의 계산된 스타일을 검사한다. 시연 시작/3장/세부 조건 펼침/툴팁/전체화면 상태에서 표시 중인 텍스트 크기의 집합이 각각 4/6개 이하인지 확인한다. CSS 파일만 작성한 단계는 시각 검증 완료로 기록하지 않는다.
- 화면 글자 확대와 브라우저 확대를 막지 않는다. 작은 화면에서는 컬럼·줄바꿈을 조정하고 글자를 새 크기로 축소하지 않는다. 다른 시청 거리, 실제 프로젝터, 저시력 사용자와의 읽기 실험은 별도 검증이 필요하다.
