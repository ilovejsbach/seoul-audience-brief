# 기기별·영역별 글자 규칙 실행 검증

2026-11-16 · 소스 `7761734` 및 끝 눈금 정렬 `681c7ab` · 실제 Chrome에서 CSS 화면 폭을 모의 변경해 검사했다. 휴대폰·태블릿 실물에서 실행한 검사와 구분한다.

## 적용한 변경

- 모바일≤767 / 태블릿768–1199 / PC≥1200px에서 시연4단계·분석6단계의 역할 값을 사용한다.
- 기능·정보·인포그래픽 부가·창 구성 폰트를 공통 역할로 분리했다. 옵션의 입력은 작은 화면16px, 설명창 본문은 읽기 크기, 출처는 메타 크기다. 상태·증감·결측은 글자 크기와 별도 의미를 갖는다.
- 고정 px important로 남아 토큰을 무시하던 조회/그래프/범위/팔레트/포털 소비자를 정리했다. 지도 라벨의 rem 단위 계산과 그래프의 실제 영역 측정도 맞췄다.
- 모바일 상권은 부정보 창을 먼저 접고, 선택 시 해당 상세만 연다. 추이는 독립된 큰 읽기 영역에서 보여 준다. 하단 작업공간은 가능한 세로 공간을 사용한다.

## 실제 확인

390×844, 1024×768, PC1512px 폭에서 시작 화면·상권·선택 상세·추이·조회 옵션·설명창을 검사했다. 767/768 및1199/1200 경계도 변경했다. 검사한 장면에서 분석은 최대6종, 시연은 최대4종이었다. 기기 규격 변경으로 조회 자료·수치는 바뀌지 않았다.

모바일의 그래프 축 선택창에14px가 남는 우선순위 충돌과, SVG의 과거 최소 너비가 새 크기 측정에 간섭하는 문제를 실제 화면에서 발견해 수정했다. 최종 검사에서는 축 옵션·재생 간격 선택 모두16px였다. 모바일 일반 생활인구의 입력16px, 지도 라벨14px 및 상세 그래프의 폭 조정도 확인했다.

설명 툴팁은 모바일 본문16px·제목20px, 옵션은 입력16px·항목/보조14px로 역할을 달리했다. 새로운 다섯 번째 시연 크기를 추가하지 않았다.

빌드 성공, 자동 검사70개 통과. 이 검사는 모든 화면의 모든 조합을 클릭했거나 WCAG 전체 인증을 받았다는 의미가 아니다. 실물 휴대폰/태블릿의 터치·키보드·글자 확대 및 보조기기 검사는 별도다.
