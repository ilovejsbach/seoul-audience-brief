# 옵션 영역 전수 소스 감사

2026-11-15 · 독립 감사 · 적용 규칙 R04–07, R11, R19–21. 이번 감사자는 소스만 읽었으며 브라우저를 실행하지 않았다. 아래 확정은 CSS/컴포넌트 계약의 확인이지 실제 화면 통과를 의미하지 않는다. 사용자가 올린 가로 확장 화면은 별도의 관찰 증거다.

## 1. 범위와 목적
광고 입지 검토자는 지도를 보면서 기간·지역·타깃을 바꾼다. 플로팅은 지도 작업을 유지하기 위한 작은 도구이므로 창을 넓히면 조건이 가까운 여러 열로 배치되어야 한다. 글자를 줄이거나 뜻이 다른 옵션을 한꺼번에 펼치는 것은 해결책이 아니다.

`src/*.tsx`의 입력·선택·접힘 요소를 모두 찾아 현재 사용 경로와 보조 설정을 조사했다. 주요 옵션 계열은 다음 15개다. 같은 컴포넌트가 여러 자료에 재사용되는 경우 소비 화면을 각각 적었다.

ResidentContext, MigrationDemographics는 접힌 보조정보이며 실제 select/input을 가진 새 조회창은 아니다. ScenarioWorkbench의 저장·복원·이름 편집은 가설 보관 도구다. 이들은 플로팅 재배치로 통합할 대상이 아니지만 긴 이름·버튼 줄바꿈·복원 결과 유지 검수에는 포함한다. DataMeaning/MapLegendTooltip은 가벼운 해석 툴팁이며 창 이동/크기 기능의 적용 대상에서 제외한다.

## 2. 공통 원인과 우선순위

1. **P1 우측 쏠림** — style.css `.controls{align-items:flex-end}`를 map-workspace-shell.css가 열 방향으로 전환하면서 cross-axis 정렬을 해제하지 않았다. 그룹에 stretch/min-width0/전체폭 또는 grid track을 지정해야 한다.
2. **P1 가로 확장 무효** — 창 너비·높이만 inline style로 변경하고 내용은 항상 한 열이다. window media query가 아니라 **실제 창 너비**를 기준으로 재배치해야 한다. 일반 조회와 상권의 공통 컨테이너 규칙이 필요하다.
3. **P2 상단 과점유** — resizable-workspaces.css 마지막 규칙이 제목과 액션에 각각 flex-basis100%를 강제한다. 넓은 창에서도 최소 두 줄에, MapPanel의 별도 이동·크기 안내 줄까지 추가된다. 넓을 때 제목·액션을 같은 행, 안내는 제목/핸들 tooltip으로 전환할 수 있다. 좁을 때는 버튼 겹침보다 줄바꿈 우선.
4. **P2 전역 CSS 간섭** — 전역 header 고정높이, controls label flex:1·min-width, mode별 후속 override가 섞여 있다. 새 규칙은 플로팅 부모 문맥으로 한정하고 실제 computed style을 검사해야 한다.
5. **P2 낮은 창에서 도구 분실** — 조회창 본문은 overflow:auto/flex1/min-height0로 적절하지만 상단이 크면 실사용 본문이 줄어든다. LayoutControls는 높이 제한 자체가 없다. 낮은 창에서는 본문 스크롤과 고정된 최소 제목행이 필요하다.

## 3. 권장 재배치 원칙

- 240–359px: 한 열. 제목·기능은 읽히는 크기를 유지하며 액션만 자연스럽게 줄바꿈한다.
- 360–599px: 여유가 되면 두 입력 열. 생활인구의 기간/지역/대상 묶음은 제목과 연결해 의미를 잃지 않게 한다.
- 600px 이상: 2–3개 의미 그룹을 가로로 나란히 배치. 단일 그룹 안 입력은 최소 읽기 폭을 유지한다. 고정된 100% label이 모든 열을 차지하지 않게 한다.
- 조회 조건과 지도 도구/색상 설정은 시각적으로 구분한다. 접힌 세부·보기 설정은 창을 넓혀도 자동으로 펼치지 않는다.
- 창 높이를 낮췄을 때 제목을 스크롤 영역에 묻지 않고 입력 본문만 스크롤한다. 이동·크기 힌트는 항상 큰 문장으로 공간을 점유할 필요가 없다.
- 설정 변경 전후 동일 원값·지역·시간·후보·수동 색상 범위를 유지한다. 창 크기 변경은 데이터 변경이 아니다.

정확값 표·24시간 히트맵의 의도적 가로 스크롤을 옵션창의 실패와 혼동하지 않는다. 이 문서 작성 시점에 실제 브라우저 E2E는 실시하지 않았으며, 부모의 후속 실행 보고가 최종 판정이다.
