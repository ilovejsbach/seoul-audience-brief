작성일 2026-11-18 · W22 · **계획만 작성, 구현·빌드·브라우저 검사·배포 미실행**.
조사 HEAD `2415cec` 기준이다. W16–W18의 실행 기록은 각 보고 당시 버전의 증거이며 현재 소스나 공개 서비스의 합격으로 사용하지 않는다.

[개발 규칙 전체](DASHBOARD_DEVELOPMENT_RULES.md), [요구서](DEVELOPMENT_REQUIREMENTS.md), [NEXT-SESSION](../NEXT-SESSION.md), [W16](workers-2026-11-18/w16-ia-midpoint-review/REPORT.md), [W17](workers-2026-11-18/w17-architecture-review/REPORT.md), [W18](workers-2026-11-18/w18-pages-deploy-limits/REPORT.md)를 함께 읽고 이 계획에 반영했다.

히어로 지표는 W20 REPORT:70–75의 **316일(2026.01.01–11.12), 현행 생활인구 427동, 보유 상권 경계 1,650곳, 행정동·상권 매출 6분기(2025Q1–2026Q2)**다. 1,650은 최신 관측 매출 상권 1,566곳/유동 1,648곳과 다르다. 유동 22분기를 매출 6분기로 잘못 제한하지 않는다. 구현 시 로컬 index·활성 코드·경계·각 매출 기간에서 다시 산출하고, 무거운 상권 전체 파일을 히어로 수치 때문에 선로딩하지 않는다. 기존 가벼운 메타가 없으면 검증된 작은 요약 상수/메타와 생성 근거를 같은 커밋에 둔다. 이후 자료 갱신 검사에서 숫자·기준기간 불일치를 잡는다.

이번 작업에서 만든 것은 이 문서와 W22 보조 자료뿐이다. 아래의 변경 파일·명령·배포는 **향후 구현 단계의 계획**이다. 모바일 개선, 교통/부동산 구현, 데이터 확장, 인증·서버 도입, 배포 방식 변경은 이 이전의 범위가 아니다.

## 3. 상태·호스트·최소 등록부 계약

계산과 로더를 한 번에 다시 쓰지 않는다. W17의 큰 구조 개편 중 **메뉴에 필요한 최소 등록부만 1–2단계에 채택**한다. 1단계 `serviceRegistry`는 주제 ID·이름·활성/예정·진입 대상만, 2단계 `dataset/viewRegistry`는 기존 자료/상세 ID·표시명·기간 단위·지원 보기·기존 동작 어댑터만 가진다. 한 정의에서 왼쪽 메뉴·상세 콤보·개수 검사를 만든다. 공개 데이터 catalog/manifest와 UI 등록부의 책임을 구별한다. 범용 플러그인 시스템, 계산기 합치기, 새 도메인/API/스키마 생성기는 넣지 않는다.

`main.tsx`에서 셸·메뉴 표현을 작은 컴포넌트로 뽑되 인구 집계 `:94–105`, ExtraDashboard 계산, 상권 집계는 그대로 둔다. 파일 분리만으로 상태 소유자가 바뀌어 조건이 초기화되지 않도록 한다.

|---|---|
| 서비스/지역 모드 | 마지막 서비스와 `region.mode`를 별도 관리. 상권에는 mode 값/전환 UI가 없음. `main.tsx:74,77,164`의 전역 클래스와 `MapWorkspace.tsx:109` 관찰, `FloatingQueryLayer.tsx:15–25,34` 복제까지 함께 차단. 상권 진입 때 지역 mode를 analysis로 덮어쓰는 해결 금지 |

### G: 모든 구현 단계에 공통인 검증/배포 관문

1. 구현 직전 HEAD·dirty 상태·현재 로컬/공개 자산 버전·PC2종 기준 화면·비기본 조건·대표 CSV/수치·data 해시를 기록한다. 다른 작업자 변경이 있으면 소유 범위를 구별한다. 과거 보고에 이미 통과했다고 적힌 결과를 현재 기준선으로 대신하지 않는다.
2. **G전체:** `npm run build`, `node --test tests/*.test.mjs`, `python3 scripts/validate-data.py`, `python3 scripts/validate-market-data.py`, 단계별 영향 E2E+규칙 a–h. 단위시험은 현재 12개 `tests/*.test.mjs` 파일을 명시하고 하위 판정 개수까지 기록한다. 일반 validator는 stdout을 새 단계 증거 폴더의 `data-validation.json`으로 저장한다. 상권 validator는 `--output <새증거폴더>/market-data-validation.json`을 명시해 기존 기본 보고서를 덮어쓰지 않는다. PC 실행은 `npm run test:e2e -- --project=desktop-1365 --project=desktop-1920`로 한정한다. 기본 설정은 패드/모바일도 포함하므로 전체 실행과 혼동하지 않는다. `PLAYWRIGHT_EVIDENCE_DIR`은 단계별 새 증거 폴더로 지정하고 기존 실행 기록을 덮어쓰지 않는다. 빌드 artifact·의미/시각 검수 대상이 동일 소스인지 확인하고 E2E가 개발 서버를 쓰는 사실을 기록한다. 데이터/로더 변경이 없더라도 validator와 공개data 해시 일치를 확인한다.
3. 독립 의미 감사자는 인구·이동·거주이동·행정동 매출·상권 각각의 독립 원문/기존 검증 fixture에서 코드·시점·조건·분모·단위·null·부호·합계·순위를 구하고 지도/KPI/상세/CSV/후보의 동일값을 대조한다. 같은 화면 값을 복사해 기대값으로 쓰지 않는다. 레이아웃 변경에서 데이터 원문을 새로 수집/변환하지 않는다.
4. 실제 Chrome에서 기능→후속행동→복귀, 의미, 시각을 별도로 판정한다. 분석6/시연4종, SVG 화면배율/포털 포함 글자, 합성색 대비·hover/focus/disabled, 동위크기, 숫자/축/긴이름/툴팁 잘림, 키보드·Esc·초점, 지도/그래프 첫 노출. PC1365×768·1920×1080, CSS viewport/DPR/zoom 명시. 모바일 전체 검수는 이번 범위 밖이지만 공통CSS 파급을 숨기지 않는다.
5. 각 단계는 위 관문을 통과한 artifact로 향후 승인된 배포 흐름을 따른다. **W22에서는 배포하지 않는다.** 공개 후 새 HTML/JS/CSS 버전과 metadata/대표데이터 응답을 확인하고 같은 핵심 진입·상세·복귀·후보/CSV·831px 화면을 독립 확인한다. 새로고침/기존 탭 재방문·이전캐시 응답을 구별한다. 로컬통과/배포성공/공개실화면통과는 별도 상태다.
6. 실패하면 다음 단계를 시작하지 않는다. 해당 단계 커밋만 통상 revert하거나 보존한 직전 artifact를 재배포한다. 공유 작업트리 전체 reset/restore·다른 작업자 커밋 취소 금지. 되돌린 공개 자산/화면까지 확인한다. 미래에 데이터 포맷을 바꾸는 L은 이전manifest/파일도 함께 복원할 수 있어야 한다.

## 6. 1365의 실제 지도 831px 관문

폭은 CSS viewport 기준이다. 좌우 경계선은 각 패널 폭에 포함하고 중간 gap을 더하지 않는다. 실제 지도/그래프 표면 폭 = `viewport − 좌측 − 우측 − 중앙패딩32 − 결과경계2`다(W20 REPORT:38–49).

| 좌/우 | 1365 중앙열 / 실제 표면 | 1920 중앙열 / 실제 표면 |
|---|---:|---:|
| 열림/열림 | 865 / **831px** | 1420 / **1386px** |
| 접힘/열림 | 1001 / 967px | 1556 / 1522px |
| 열림/접힘 | 1165 / 1131px | 1720 / 1686px |
| 접힘/접힘 | 1301 / 1267px | 1856 / 1822px |

화면너비가 아니라 `documentElement.clientWidth`와 실제 rect로 재계산한다. 기본배치 기대값은 ±1px 이내, 고급 사용자 배치에서는 같은 식의 실제 점유폭을 기록한다. 그래프 자체는 축 여백을 제외한 plot rect도 별도 기록한다. 목업의 min-width1200/min-height640·설명띠24px는 실제 서비스에 복사하지 않는다.
