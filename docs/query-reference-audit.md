# 조회 옵션 참고 대시보드 독립 감사

2026-11-15. **참고 조사와 개선 제안이며 구현·실화면 통과 보고가 아니다.** 사용자가 조회 옵션 전체 감사를 먼저 요구함에 따라 공식 제품 문서를 웹에서 확인하고 현재 소스·제공된 화면 문제와 비교했다. 소스·공개 페이지·원자료는 수정하지 않았다. 실제 제품 편집기나 대시보드에서 브라우저 사용성 실험을 수행하지 않았으며 효과 수치를 주장하지 않는다.

## 먼저 판단할 문제

현재 문제는 버튼을 더 작게 만드는 것에 그치지 않는다. 조회 대상·기간·지역·표시 설정·창 배치가 한 창에 함께 나타나 사용자가 지금 무엇을 바꾸는지 구분하기 어렵다. 창을 넓히면 의미상 하나인 편집 흐름이 여러 열로 흩어지고, 작은 창에서는 검색 버튼이 선택값의 폭을 빼앗는다. 투명도는 배치를 대신하지 못하며 겹쳐 보이는 배경 정보가 오히려 판독을 방해할 수 있다. 이는 사용자 제공 화면과 소스에 대한 분석이고, 모든 최신 화면에서 재현 완료했다는 뜻은 아니다.

## 현재 소스와 문제의 연결

| 확인한 소스·상태 | 감사 판단 | 다음 설계에서 확인할 것 |
|---|---|---|
| `QueryControls.tsx`는 native select와 별도 검색 버튼/검색 팝오버를 함께 제공 | 접근성·기존 선택 동작을 보존했지만 검색 시작점이 반복되고 작은 칸에서 값이 밀릴 수 있음 | 검색을 내장한 한 선택기로 통합할지 결정. 키보드·선택 해제·0건 복구까지 하나의 흐름으로 검증 |
| 생활인구 자료·기간에는 월/일/정확 시각/시간 스크러버/이전·다음 날짜가 함께 존재 | 시간 막대를 옵션으로 이동한 것만으로 역할 중복이 해소되지 않음 | 기본은 일자·시각. 월은 일자 탐색의 범위, 빠른 시간 이동은 선택적 보조 도구로 구분 |
| `QueryGroup`와 컨테이너 기반 열 배치가 공존 | 창 너비에 맞는 열 수만 결정하면 서로 다른 의미의 필드가 병렬로 흩어짐 | 기본 한 열. 넓은 창은 관련 필드의 정해진 쌍만 같은 행으로, 읽는 순서는 유지 |
| MapPanel/MapWorkspace에 조회·지도 표시·창 배치가 공존 | '값을 고르는 곳'과 '창을 꾸미는 곳'이 뒤섞이기 쉬움 | 조회/지도표시/창설정의 세 역할을 분리. 창 설정은 제목 옆 하나의 메뉴 안으로 |
| 새 자석 배치·투명도는 구현 중이며 부모가 실화면 검사 중 | 요청된 기능이 존재한다는 사실이 화면 전체의 편의성을 보장하지 않음 | 기본 불투명 고정창의 완성도를 먼저 검증. 도킹/플로팅은 같은 단일 편집기를 재배치하며 조건·후보는 불변 |
| `QuerySummary`는 현재 조건·개별 편집·해제를 제공 | 유지할 가치가 있으나 기본값까지 매번 큰 칩으로 반복하면 새 혼잡을 만듦 | 현재 질문에 필수인 기간·지역·지표, 바뀐 조건을 우선. 정확한 전체 조건은 접근 가능한 한 경로로 제공 |

## 대표 개선안 — 아직 제안

**원칙: 한 화면에서 결과를 읽는 자리와 조건을 바꾸는 자리를 분리한다.**

1. 상단은 자료/보기 이동과 현재 화면 제목. 조회값을 바꾸는 큰 행을 추가하지 않는다.
2. 지도 위에는 현재 적용 조건 한 줄과 지도 조작만 둔다. '현재 시각'은 보여주되 긴 슬라이더를 상시 점유시키지 않는다.
3. 조회를 열면 지도 밖 좌측 한 영역에서 편집한다. 시연에서는 닫힌 상태로 시작한다. 상세·후보에서도 같은 편집기를 재사용한다.
4. 영역 내부는 **기간 → 지역 → 분석 대상** 순서의 한 열을 기본으로 한다. 각 묶음 제목 옆에는 현재값 요약. 사용자가 여는 묶음 외 불필요한 설명·보조 도구는 접는다.
5. 표시 설정은 지도/그래프에 종속된 별도 작은 메뉴, 배치·투명도는 창 제목의 '창 설정'에 둔다. 조회 조건을 바꾸는 동작처럼 보이지 않게 한다.
6. 폭이 넓어져도 필드를 자동으로 여러 열에 쏟아놓지 않는다. 같은 의미의 날짜·시각처럼 검증된 쌍만 같은 행을 사용한다. 좁은 상태의 입력 폭·줄바꿈·가독성이 먼저 통과해야 한다.

이는 공통 구조의 제안이다. 생활이동은 시각 기준/일계·누적, 전출입은 지원 연도/인구 세분, 상권은 업종/단일 분석 기준이라는 차이를 그대로 유지해야 한다. 모든 화면을 같은 필드 수로 맞추지 않는다.

## 채택 전에 통과할 수용 기준

- 광고주 질문 하나에서 시작해 필요한 조건만 바꾸고 지도/추이/후보로 이어갈 수 있다. 배치 도구를 먼저 배울 필요가 없어야 한다.
- 선택값과 검색 버튼·화살표·단위가 서로 밀지 않는다. 부모/창 너비별 가로 넘침 없이 실제 긴 지역명·상권명으로 검사한다.
- 조회 영역을 닫으면 지도 공간이 반환된다. 닫힌 상태에서도 결과의 기간·지표·지역·중요한 바뀐 조건을 알 수 있다.
- 화면의 조건 요약에서 편집을 열면 같은 입력 하나에 도착한다. 상세 화면에서 지도로 강제 이동하거나 숨은 창에 초점이 가지 않는다.
- 기본 불투명 상태에서 판독이 통과한다. 투명도 조절 시에도 글자·버튼 opacity는 유지하고, 겹침 때문에 읽기 어려운 상태를 기본값으로 저장하지 않는다.
- 창 배치·범례·색상 변경은 원자료·조회 조건·후보를 바꾸지 않는다.0건/자료 없음/미지원 상태마다 복구 행동을 검증한다.
- 분석/시연 × 일반/전체화면 × 좁은/넓은 창에서 실제 화면을 검사한다. 기능 시험·독립 원자료 대조·시각 검사를 따로 기록한다(R20/R21).

다음 단계는 기존 [중앙 조회 설계](tableau-query-options-plan.md)와 본 감사의 차이를 정리하고, 대표 한 화면의 시안을 먼저 검토하는 것이다. 조사 내용을 이유로 다시 모든 옵션을 한 번에 추가하는 것은 권하지 않는다.
