# 인포그래픽 비판적 독립 검토

확인일: 2026-11-14. 현재 `main.tsx`, `ExtraDashboard.tsx`, `TrendExplorer.tsx`, `TimeComparison.tsx`, `Hero.tsx`, `ScenarioWorkbench.tsx`와 실제 공개 가공 자료를 대조했다. 이전 통과 문구를 근거로 삼지 않았다. 이 문서만 작성했으며 UI 코드는 수정하지 않았다. 브라우저 실제 조작·배치는 별도 검증 대상이다.

## 우선 수정할 해석 문제

### P2 — 음수 순이동을 기준 100 지수로 바꾸면 방향을 오해하게 한다

- 재현: 생활이동 → 도착 시각 → 강남구 → 유입−유출 → 추세 표시 기준 100 → 기준 0시 → 6시 선택.
- 실제 원값은 0시 **−683.70건**, 6시 **+10,190.26건**이다. 현재 식 `선택값/기준값*100`은 약 **−1,490.46**으로 표시한다. 순유출에서 순유입으로 전환했는데 음수 지수로 보이는 구조다.
- 코드의 차단 조건은 `base===0`이므로 음수 기준이 허용된다.
- 권고: 순이동 같은 부호 있는 지표에는 실제값·증감 중심으로 설명한다. 기준 100은 적어도 기준값이 양수일 때만 허용하고, 음수/0이면 다른 기준 또는 증감 보기로 안내한다. 지수가 음수로 뒤집힌 결과를 개선·감소로 해석하지 않는다.

### P2 — 부분 결측이 있어도 하루 전체의 최대 시각으로 단정한다

- 재현: 생활인구 → 2026-10-31 → 종로구 삼청동 → 남성·전체 연령.
- 원본의 선택 성·연령 합계는 02~09시의 8시간이 비공개여서 계산할 수 없다. 공개된 16시간 중 최대는 15시, 약 7,426.53명이다.
- 현재 요약과 비교 카드의 “하루 중 가장 많은 시간”/“최대 15:00”은 공개되지 않은 시각까지 포함한 확정 최대처럼 읽힌다.
- 권고: 결측이 있으면 **“공개된 시간대 중 최대 · 16/24시간”**으로 표시한다. 하루 전체 최대라는 말은 24시간 모두 비교 가능한 때만 사용한다. 결측을 0으로 채우지 않는 것뿐 아니라 요약 결론의 범위도 제한해야 한다.

## 의사결정 목적과 후속 행동의 공백

### P2 — 이동 상세가 구 합계·같은 시간 차트의 반복에 머문다

현재 생활이동에서 구를 선택하면 선택 구 KPI·추이로 이동하는 동작은 연결되어 있다. 상세 표도 클릭 가능해졌다. 그러나 “마포구에 어디에서 들어오고 어디로 나가는가?”에 답할 상대 지역 표·차트는 아직 없다. 지도는 25구의 전체 유입·유출 분포를 그대로 보여 주며, 선택 구의 이동 연결을 보여 주지 않는다. **구 선택→구명 반복→같은 차트**만으로는 광고 입지의 배후 수요 설명까지 이어지지 않는다.

권고: 현재 시간기준·집계방식·구내 제외를 그대로 적용한 선택 구의 유입 출발지/유출 도착지 상위 표를 제공한다. 서울 외는 여러 지역을 묶은 값이므로 별도 그룹임을 표시하고, 같은 구 내부 이동을 외부 유입으로 넣지 않는다. 이 기능이 생기기 전에는 지도 제목을 이동 경로·연결 지도라고 부르지 않는다.

### P2 — 상권은 분기 숫자 나열에서 비교 근거로 한 단계 더 나가야 한다

현재 추정매출은 분기·시간구간을 골라 구/동 원값과 두 시점 차이를 볼 수 있지만, “최근 분기에 얼마나 달라졌는가?”의 기준 기간이 기본적으로 설명되지 않는다. 큰 매출 숫자만으로 집행 기회를 단정하면 지역 크기·업종 구성·기간 길이·계절성 효과를 놓친다.

권고: 선택 분기의 전분기 차이와 증감률을 원값·비교 기간과 함께 표시하되 첫 분기는 비교자료 없음으로 둔다. 다른 업종 범위나 인구 자료와 나누어 구매전환율을 만들지 않는다. 전분기 증가는 인과적 광고 효과나 장기 성장 추정이 아니다.

## 제목·장식 숫자·시간 의미 판단

- Hero의 “광고 입지·집행 시점 분석”은 참고할 자료의 목적을 말하는 정도로 유지한다. 공개 통계가 광고 도달·비용 대비 효과·최적 집행안을 계산해 주는 것처럼 결론형 제목을 붙이지 않는다.
- 생활이동의 시간 기준은 도착/출발을 바꿀 수 있고 누적·원본 일자 전체를 구분한다. 원본 일자와 자정 넘는 도착의 달력 날짜 미검증을 화면 가까이에 남긴 점은 필요하다. 2026-10-31 하루의 패턴을 평일 일반 패턴이나 월평균 패턴으로 확대하지 않는다.
- 원본 일자 전체 모드에서 지도는 전체 합계이고 추이는 시간대별이라는 안내가 있지만, 현재 지도 값과 아래 차트의 선택 시점 값이 같다고 기대하는 사용자는 혼동할 수 있다. 안내를 차트 제목 가까이에 유지하고, 차트 선택/재생 시 시간대 모드로 바뀐 사실을 눈에 띄게 표시한다.
- “브리핑 후보 0/3”은 상태이지만 의사결정 지표가 아니다. 큰 KPI 세 개를 맞추려는 장식으로 반복하지 않는다. 후보가 없을 때는 작은 상태/행동 안내로 두고 핵심 지표 영역은 공개 시간 범위·전분기 변화·선택 구 상대 지역처럼 실제 질문에 답하는 값에 우선 배정할 수 있다.
- 조건별 시나리오 비교는 예측이 아니라 저장한 조회값 비교다. 실제값이라는 표현도 생활인구·매출·이동이 추계/추정임을 지워서는 안 된다. 시간대 합계와 하루 누적처럼 관측 창이 다른 조건을 저장할 때 차이만으로 “더 좋은 안”을 고르지 않도록 요약 조건을 함께 읽게 한다.
- 현재 상권 화면은 행정동 자료이며 새로 확보한 상권 단위 1,577코드 파일을 아직 표시하지 않는다. 화면 제목을 이미 세부 상권으로 구현한 것처럼 바꾸지 않는다.

## 검증할 사용자 여정

1. 마포를 지도·순위·표에서 각각 선택해 같은 KPI·시간 추이·지역 이름으로 바뀌는지 확인한다. 같은 동을 반복 선택해도 화면이 의미 없이 움직이거나 상위 구로 되돌아가지 않는지 확인한다.
2. 18시 도착·시간대 집계에서 위 마포 상대 지역 기대값을 확인하고 출발 기준으로 바꾸면 제목·숫자·내보내기 조건이 함께 바뀌는지 확인한다.
3. 시간대→누적→일자 전체를 오갈 때 “무엇을 합친 값인지”를 차트 제목만 보고도 이해할 수 있어야 한다.
4. 상권 마포 Q4에서 Q3 대비 차이를 위 값과 대조하고, Q1은 가짜 0% 대신 비교자료 없음으로 표시한다.
5. 삼청동 남성 전체의 결측 8시간과 최대 요약의 제한 조건을 확인하고, 순이동 음수 기준 100의 처리 여부를 확인한다.

## 추가 확인: 상권 자료 확보와 길단위인구 공개 해상도

2025 상권 매출 ZIP을 다시 열어 CRC와 CSV 행·코드를 재집계했다. 파일은 실제로 존재하며 14,035,292 bytes, 85,732행, 1,577상권이다. 20251/52/53/54는 각각 21,427/21,452/21,520/21,333행이다. 기존 영역 상권 ZIP도 CRC 정상이며 연결 검증 파일은 경계 1,650개 중 매출 코드 1,577개 전부 일치·미일치 0을 기록한다. 원본은 변경하지 않았다.

[공식 길단위인구－상권](https://data.seoul.go.kr/dataList/OA-15568/A/1/datasetView.do)의 [OpenAPI 명세](https://data.seoul.go.kr/dataList/openApiView.do?infId=OA-15568&srvType=A)는 `VwsmTrdarFlpopQq` 서비스와 기준년분기 코드 `STDR_YYQU_CD`를 제공한다. 상권코드별 총 유동인구, 남녀, 10/20/30/40/50/60대 이상, 6개 시간구간, 월~일 필드가 있다. 시간대는 00~06·06~11·11~14·14~17·17~21·21~24다. 성별·연령·시간의 각각 분포가 있다고 해서 모두 결합된 교차값까지 있다고 판단하면 안 된다.

해당 포털은 갱신주기를 월간으로 적지만 실제 통계 조회 키는 분기다. **갱신 주기와 분석 시간 해상도를 구분**해야 한다. 현재 FILE 목록은 없고 정식 API 인증키로 회당 최대 1,000행을 조회한다. 공개 sample은 최대 5행이다. 이번 확인은 공식 메타데이터와 명세 확인이며 길단위인구 상권 전체 원본 확보 완료가 아니다. 실제 일평균/분기 누적 해석은 제공 매뉴얼과 원본 샘플을 추가 대조해야 한다.

| 상권 전분기 비교 | 기존 행정동 상권 화면에는 이전 분기 매출과 차이, 새 상권 지도에는 선택 상권의 직전 분기 차이가 있다. | 실제 공덕역 값을 아래 원본 기대값으로 검증한다. 첫 분기는 비교자료 없음이어야 하며 0으로 만들지 않는다. |
| 상권 숫자의 해석 | 새 지도는 분기 제공 원본 유동인구 지표·하루 고유 방문자 아님을 표시하고 성/연령/요일/시간은 한 가지씩 고른다. | 자료 전환 후 업종이 인구에도 적용된 듯 보이지 않는지, 분기·단위·세부 조건이 지도·상세·추이에 함께 표시되는지 확인한다. |
| 두 지도 분포 비교 | `DistributionComparison`은 같은 조건의 두 시간에 공통 색 눈금을 쓰고 한쪽 결측이면 차이를 계산하지 않는다. | 자료 전부 없는 경우 증감 범례의 ±0이 실제 0변화로 읽히지 않게 “비교자료 없음”을 확인한다. 지도 색만 보고 고유 인구 이동을 추정하지 않는다. |
| 원자료 범위 | 매출 2025, 인구 2021 Q1~2026 Q2를 독립 기간 선택으로 제공한다. | 최신 분기를 자동 비교한 구매전환율을 만들지 않는다. 지도 도형·대표 동 소속의 과거 기준 한계를 유지한다. |

### 이전 P2 — 상권 지도의 이전 화면 복귀 (최종 동결에서 수정 확인)

- 재현: 분석을 한 번 연다 → 시작 화면으로 돌아온다 → 지도 중심 조회를 연다 → “이전 화면으로”.
- 당시 main은 `visited ? 'analysis' : 'overview'`로 복귀했다. 따라서 실제 직전의 시작 화면이 아니라 과거 분석 화면으로 이동한다.
- 대안: 상권 지도를 열 때 직전 view를 저장해 복귀한다. 분석에서 연 경우는 분석으로, 시작 화면에서 연 경우는 시작 화면으로 돌아가고, 기존 선택 조건은 유지한다.
- 이것은 공개 자료 값의 오류는 아니지만 “이전 화면” 동작 계약과 다른 실제 상태 전이다. 브라우저로 재현한 뒤 수정 여부를 판단한다.

### 실제 브라우저에서 특히 볼 행동

오른쪽 상세 패널을 접은 뒤 지도에서 상권을 고르면 선택 상태는 바뀌어도 패널은 계속 접혀 있을 수 있다. `MapWorkspace` 내부의 `detailsOpen`과 지도 선택은 직접 연결되어 있지 않다. 의도적으로 큰 지도를 보려는 동작을 존중할지, 새 선택에서 상세를 자동 열지 제품 결정을 명확히 하고 사용자가 “클릭해도 반응 없음”으로 읽지 않게 한다. 이를 정적 계산 오류나 확정 출시 차단으로 단정하지는 않는다.

이 재평가에서 새로운 P1 계산 오류는 확인하지 못했다. 활성 상태·잔류 선택·후보 버튼의 수정 중인 항목을 제외하고, 확정적으로 재확인한 신규 상태 전이 문제는 위 복귀 P2다.

### 검증 범위의 한계

이 독립 검토는 소스·원자료 검토다. 주 실행자는 Chrome에서 기존 기능 13건, 상세 축 5건, 상권 7건, 실패 복구 1건과 네이티브 상권 클릭 상세 자동 열림을 통과했다고 전달했다. 보조 검증 6건 및 원본 전수 검증도 통과했다. 이 문서는 그 브라우저 검사를 독립적으로 다시 실행했다고 주장하지 않는다.

실제 확인된 화면 크기는 **1800×905**다. 뷰포트 변경이 적용되지 않았으므로 1440×900이나 모바일을 실제 화면에서 검증 완료했다고 표시하지 않는다. 작은 화면과 인쇄의 최종 시각 검증은 별도 범위로 남긴다.

### 출시 차단과 분리한 후속 개선

원본 유동인구의 일평균 환산식 확정, 최신 상권 경계 형상 대조, 10대 분류의 정확한 최저 연령 확인, 실제 작은 화면 검증은 후속 항목이다. 현재는 분기 제공 원본 추정 지표·하루 고유 방문자 아님·경계 기준 한계를 유지해야 한다. 이 항목을 해결한 것처럼 표현하거나 임의 환산하면 안 되지만, 현재처럼 제한을 명시한 탐색 화면에서 새 기능 범위로 확장할 필요는 없다.
