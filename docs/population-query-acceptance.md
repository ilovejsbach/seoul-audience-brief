## 초기 소스 검토와 위험

검토 시점의 `main.tsx`는 전용 `valueOf`에서 선택한 구성값 중 하나라도 null이면 null을 반환하고, 추이도 일부 null이 있으면 합계 null을 유지했다. 상세·후보와 조회 입력은 같은 상위 상태를 사용한다. 이는 소스 확인이며 실제 실행 통과는 아니다. 구현 에이전트가 동시에 수정 중이므로 최종 소스는 다시 대조한다.

상권 P0는 `MapWorkspace.tsx`의 패널 `key="controls"/"details"`와 분할선의 `key={panel}`가 같은 직계 형제에서 충돌하는 것이 강한 원인 후보다. 기존 부모 실화면에서는 조건창과 입력 ID 중복이 관찰됐다. 분할선과 패널의 key 공간을 구분하고 열기/닫기/도킹/로딩 후 실제 DOM 중복0개를 재검증해야 한다. 독립 평가자는 이 파일을 수정하지 않았다.

## 생활인구 적용 소스의 독립 재검토

2026-11-15, 부모의 생활인구 개편 후 소스를 다시 읽었다. 이 절은 직접 소스 확인과 부모 전달 실화면 결과를 구분한다.

### 직접 소스 확인

- `main.tsx`의 기본 입력은 기준일·시각·자치구·행정동·연령·성별6개이며, 기간→지역→대상의 한 열 순서를 갖는다. 시간 스크러버는 ‘시간 빠르게 이동’의 접힌 보조 조작이다. 지도 아래 전체폭 시간 조작과 조회 본문의 내려받기 버튼은 제거되고, 내려받기는 결과 제목 옆으로 이동했다.
- 지역 선택은 탐색 장면을 바꾸는 함수가 아니라 조회 상태만 변경하는 전용 함수를 쓴다. 구를 바꾸면 이전 동은 초기화되고, 다른 조건·후보는 보존된다. 현재 조건 칩에서 해당 입력으로 들어갈 수 있다.
- 날짜 응답은 현재 날짜와 일치할 때만 `pop`으로 사용한다. 이전 요청은 정리 함수의 active 플래그로 무시한다. 자료가 오기 전 이전 날짜의 수치를 새 제목 아래 사용하는 경로는 없다.
- 집단 선택의 계산·결측 전파는 기존 규칙을 유지한다. 모든 자치구와 소속 동을 검색 목록에 남기고, 값이 없는 집단은 ‘자료 없음’을 붙여 복구 경로를 잃지 않게 했다.
- `MapPanel queryLayout="focused"`는 조건 영역을280px 기본·260–360px 범위로, 플로팅은360×560px 기본으로 구분한다. focused 조건창 안의 자동 다단 배치를 막고, 같은 기존 입력을 포털로 이동하므로 중복 편집기를 복사하지 않는다.
- focused `MapOptionsHost`를 null로 두어 지도 탐색·색상 표시가 조건 본문에 주입되지 않는다. `MapCanvas`의 지도 조작은 실제 지도 쪽에 남고 현재 조건 요약도 유지한다.
- `SearchableSelect`는 한 선택기에서 현재값·검색·결과·0건 복구를 다룬다. 빈 검색어에서 Enter는 현재 선택을 유지하며 첫 옵션으로 무조건 초기화하지 않는다. 일부 입력 ID가 native select에서 combobox 버튼으로 바뀌므로 과거 `.selectOption()` 자동화는 새 실제 조작 흐름으로 갱신해야 한다.

### 전달한 보완점

`SearchableSelect`의 트리거는 `aria-haspopup="listbox"`인데 실제 팝오버 루트는 `QueryPopover role="dialog"`이다. 검색 입력과 목록을 함께 가진 dialog이므로 트리거의 팝업 유형도 dialog로 맞추는 보완을 부모에게 전달했다. 이는 인구 계산 결함은 아니지만 보조 기술의 동작 예고를 맞추기 위한 항목이다. 구현자가 수정한 뒤 최종 소스 확인이 필요하다.

새 생활인구 소스에서 추가적인 원값·집단 계산의 중대 회귀는 발견하지 못했다. 드래그·화면 경계·초점·브라우저 날짜 입력의 실제 입력 반영은 소스만으로 통과 판정하지 않는다.

## 생활인구 검수 뒤 다른 자료로 적용한 소스의 독립 점검

2026-11-15, 부모의 단계 적용 뒤 `ExtraDashboard`, `MapCanvas`, `SearchableSelect`, `MarketExplorer`, `MapWorkspace` 소스를 읽었다. 수정은 하지 않았다.

- 생활이동·거주지 이동·추정매출은 focused 조회창의 기간→지역→분석 기준 순서를 공유한다. 표 내려받기는 결과 제목 행으로 옮겼다. 생활이동은 도착/출발·한시간/누적/일계의 뜻을 유지하고 일계에서는 시간 선택이 비활성화되며 이유를 붙인다.
- 거주지 이동은 성별2021–2025 구·동, 연령2025 구의 실제 지원 제약과 가장 가까운 지원 연도 안내를 유지한다. 연령별 동 조회를 허용하지 않는다. 전체·세분 자료를 한 모집단처럼 교차 집계하지 않는다.
- `MapCanvas`의 지도 조작 JSX는 한 경로로 렌더링하며, 조회 조건과 지도 표현을 다른 위치에서 다룬다. 팔레트·min/max가 인구·매출 원값을 바꾸는 계산 경로는 없다.
- `SearchableSelect`의 `aria-haspopup`는 실제 팝오버의 dialog 역할과 맞도록 수정됐다. 앞서 전달한 접근성 팝업 유형 불일치는 소스상 해소됐다.
- 상권의 지도 표시 설정은 조회 본문 밖 별도 팝오버로 분리했다. 검색·유형·지역의 교집합과 관련 선택지 건수를 유지하며, 성별·연령·요일·시간대는 한 비교 항목씩 조회하는 제약을 유지한다.
- 상권 `MapWorkspace`의 분할선은 `split-controls`/`split-details` key를 사용하므로 패널의 `controls`/`details`와 구분된다. 이전 중복 key 원인 후보는 소스상 해소됐다.

이 범위에서 추가 중대 회귀를 발견하지 못했고 변경 형식 검사도 통과했다. 부모가 전달한 서초구30대 전입13,705/전출13,007/순이동698, 이동 일계시간 비활성화, 상권 홍대+마포+서교+발달2개 및 도킹 뒤 중복 ID0개는 부모의 실제 실행 결과로 구분한다. 독립 평가자가 브라우저를 다시 실행한 결과는 아니다. 미실행 크기·조합·공개 화면 검증은 부모의 최종 실행 보고를 따른다.
