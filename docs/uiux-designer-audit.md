# 독립 UI/UX 디자이너 화면 품질 감사

2026-11-16. 평가 역할로 작성하며 구현 코드는 수정하지 않는다. 적용 기준은 R01 목적, R04–06 공간·위계·역할, R07–08 글자·대비, R20 실제 화면 검수다.

### 공개 전 차단 기준

빌드·타입 검사·단위 검사 통과는 시각 품질 통과가 아니다. D01처럼 실제 지도가 밀리거나 잘리는 P0가 남으면 공개 완료로 보고하지 않는다. 일반/시연 두 모드에서 구·동 지도, 일반/지도 전체화면을 각각 실제 Chrome으로 열고, 옵션 아이콘의 실제 화면 크기와 지도 잔여 영역을 확인해야 한다. 화면별 결과를 작성하지 않은 상태에서 ‘전체 화면 검수 완료’라고 묶지 않는다.

## 개선 후 재감사

현재 대기. 부모 에이전트가 새 Chrome 화면을 제공하면 동일 목적·동일 크기 기준으로 D01–D07을 재판정한다. 정적 화면 판정과 실제 조작·계산 검증은 구분하여 기록한다.

### 중간 캡처 재감사 — 생활인구 지도 두 모드

검토 이미지: `evidence/shared-query-presentation/population-analysis-after.jpg`, `population-presentation-after.jpg`(각2000×1120). 부모가 이후 조회 입력을 항목명+현재값 한 줄 형태로 더 압축 중이라고 전달했으므로 최종 캡처로 간주하지 않는다.

- D01: 두 캡처에서 거대한 옵션 SVG가 사라졌고, 서울 도형 전체가 지도 패널 안에 보인다. 이 두 정적 화면 범위에서 차단 결함 해소. 구/동·전체화면의 실제 조작 검증은 별도다.
- D02: 왼쪽 조회창과 읽기 전용 현재 조건 칩이 사라지고 실제 입력 한 벌이 상단에 보인다. 구조 개선 확인. 값 변경·메인/전체화면 호스트 이동의 의미 검증은 부모의 실제 실행 결과가 필요하다.
- 새 P1 공간 지적: 약1360px폭 지도 패널 안의 서울 도형은 약540×450px로 패널 면적의 약4분의1만 쓰며, 제목·후보0개 트레이·지역 단위/조작 안내가 세 행으로 쌓인다. 지도 탐색이 목적이므로 빈 후보 트레이는 작은 후보 배지·설명으로 압축하고, `구 선택→…`·`휠로 확대·드래그로 이동`은 도구 설명으로 옮기는 편이 적합하다. 단 도형 자체를 가로로 늘려 지리 비율을 왜곡해서는 안 된다.
- 새 P2 일관성 지적: 시연 화면의 휠/드래그 안내가 세 줄로 접혀 같은 도구 행의 높이가 분석용과 달라진다. 안내 문장을 상시 표시하지 않고 해당 조작의 툴팁으로 합치면 두 모드의 도구 정렬도 안정된다.
- 조회 바의 긴 미지원 문구가 시연에서 말줄임 된다. 전체 의미가 필요한 장애/미지원 사유는 짧은 상태명과 접근 가능한 설명으로 나누고, 단순 공간 부족을 글자 축소로 해결하지 않는다.

D03–D07의 새 상세 화면·콤보 지속성·통일된 틀은 아직 재감사 대기다. 정확한 글자 크기 개수·색상 대비율도 미측정이다.

### 좁은 PC 중간 캡처 — 공개 차단

`evidence/shared-query-presentation/presentation-narrow-preaudit.jpg`에서는 지도 도형이 약170×125px로 줄고25개 구명이 서로 겹친다. 지도 중심 조회의 목적 수행이 불가능하므로 **새 P0(D08)**로 판정한다. 큰 화면의 D01 해소를 이 해상도의 통과로 소급할 수 없다.

좁은 PC에서는 빈 후보 안내·긴 조작 문장을 압축하고, 필요하면 우측 순위나 아래 숫자 패널을 접거나 별도 선택 장면으로 보내 지도에 실효 최소 높이를 확보해야 한다. 지도 종횡비를 왜곡하거나 지역명을 무조건 작게 만들어 문제를 덮지 않는다. 도형 fit·SVG viewBox와 실제 잔여 높이를 함께 확인한다. 예를 들어320px 같은 제품별 지도 최소 높이를 정해 실측할 수 있지만, 해당 숫자를 보편적 인간공학 기준으로 주장하지 않는다.

이 이미지는 이름 그대로 수정 전 중간 검수 자료다. 수정 후 동일 크기 캡처로 D08을 재판정하기 전에는 시연 지도 전체 품질 통과로 보고하지 않는다.

### 좁은 PC 지도 수정 재감사 — 2차 중간 상태

`evidence/shared-query-presentation/presentation-narrow-map-fixed.jpg`를 독립 열람했다. 도형과 구명은 전체가 읽히며, 이전 약170×125px 도형과 이름 겹침은 해소됐다. 부모 측 실측은1365×768에서 지도 높이397px이며, 이 수치는 부모의 실제 DOM 측정으로 구분한다. 빈 후보 트레이·조작 문장을 제거하고 아래 KPI를 옮긴 결과, 지도 탐색의 주목도가 회복됐다. 상단 입력도 항목명+현재값 한 줄로 바뀌어 조건 표시와 수정 위치의 관계가 명확하다.

다만 같은 캡처에서 오른쪽 KPI의 `−97,110`이 `−97,11`과 `0`으로 끊기고, 단위와 설명도 좁은 두 열에서 여러 줄로 갈라진다. 이는 **P1(D09) 숫자 단위의 시각적 결합 파괴**다. 부모가 한 열·숫자 줄바꿈 방지 수정 중임을 전달했으므로 아직 해소로 표시하지 않는다. 전체 시연 품질 통과는 해당 최종 캡처를 받은 뒤 판정한다.

우측의 공개 시간대 최대·직전 시간 차이는 ‘지금 어느 지역을 선택할까’라는 지도 첫 장의 질문보다 부차적이다. 숫자가 깨지지 않게 하는 수정과 별개로, 이 둘은 순위와 지도보다 낮은 위계의 접힘 정보 또는 추이/특성 분석의 근거로 관리하는 것이 적합하다. 주정보를 확보하려고 모든 보조 수치를 좁은 우측 칸에 무조건 밀어 넣는 방식은 권장하지 않는다.

부모 실제 실행의 `frame-matrix.json`14개와 `extra-frame-matrix.json`34개를 읽고 별도 집계했다. **각 자료·각 모드 내 모든 상세의 top/width/height/bottom 값이 동일**하며, 모든 항목에서 활성 콤보1개·활성 조회 입력 묶음1개가 기록됐다. 생활인구는 각 모드7종, 생활이동6종, 전입전출6종, 매출5종이다. 폭은1250.85px이며, 분석용 생활인구/전입전출/매출 높이561.60px, 시연용560.59px다. 생활이동은 조회 바 두 행 때문에 각각517.60/516.60px이며, 모든 하단은759.78px로 일치한다. 이는 임의의 컨텐츠 길이에 따른 틀 변경과 구분되는 반응형 잔여 공간이다. 상권은 이 두 행렬의 집계 범위에 포함되지 않는다.

부모의 `typography-map.json`에는 분석용12/14/16/20/28/36px6종, 시연용14/18/24/36px4종이 기록돼 지도 화면의 규격을 만족한다. 이 파일 하나로 모든 상세 표·팝오버·인쇄까지 같은 수를 썼다고 확대 해석하지 않는다. 색 대비율의 별도 실측 증거는 아직 받지 않았다.

`chrome-fullscreen-menu.txt`의 Chrome 보기 메뉴에 `전체 화면 종료`가 표시되는 증거도 확인했다. 부모가 Ctrl+Cmd+F 이후 자료4종 전환·상세 왕복 때 유지됨을 실제로 실행했다고 전달했다. 이는 부모의 네이티브 전체화면 실행 증거이며 디자이너가 직접 GUI를 조작한 결과로 표기하지 않는다.

## 공통 헤더·조회 배치·상권 정보 압축 재감사 (2026-11-16)

앞선 판정 이후 새 변경을 R04/R05/R06/R07/R17/R18/R20에 따라 별도 검토했다. 구현 코드를 읽고 `docs/evidence/compact-header-query-placement/market-map.jpg`, `market-detail.jpg`를 독립 열람했다. 실제 Chrome 조작은 부모가 수행했다.

### 목적과 정보 위계

- 상권 지도는 ‘어느 상권을 더 조사할 것인가’에 답한다. 첫 행은 작업 이름·복귀, 둘째 행은 실제 조회 입력, 지도 안의 짧은 행은 지리 경로·단위·결과 개수·도구다. 새 이미지에서 자료/분기/구/검색/유형이 한 줄에 읽히고 지도와 구 이름이 본문의 중심이다. 큰 제목/조건 반복/출처 footer를 없애도 현재 기준은 입력에 남는다.
- 상권 추이는 ‘이 상권의 분기 규모가 어떻게 달라졌는가’에 답한다. 모달은 선택 상권·지표·조건, 현재 분기/값, 큰 선 그래프를 우선한다. 분기 라벨·축·재생행이 틀 안에 있고 상세 콤보와 닫기/본문 전환이 상단에 남는다. 축이0을 제외했다는 주의도 유지됐다.

### 정적 검토와 실제 확인의 구분

조회 배치는 같은 입력 호스트를 상단/우측/플로팅으로 옮기는 구조다. 최소 지도폭540px, 실제 지도폭 재확인 후 플로팅 대체, 화면 경계 제한·상단 복원·키보드 조작 경로가 코드에 있다. 이 구조만으로 실제 배치 통과를 판정하지 않는다.

공통 헤더는 동위 자료4개를 같은 격자로 두고 현재 선택을 강조하며 부가 작업을 추가 메뉴로 옮겼다. 좁은 폭의 줄바꿈 규칙은 있으나1100px 경계와 시연의 긴 제목은 상권2장으로 판정할 수 없다.

출처와 해석은 안내 도구로 이동했다. 단위·분기·0제외 축 주의·자료 없음은 결과 가까이에 남는다. 원래 범위/조회 범위 맞춤 및 서울→구→상권 경로도 남아 핵심 복귀 경로의 정적 손실은 발견하지 못했다.

**상권2장에 새 P0/P1 시각 결함은 관찰되지 않았다.** 부모는 헤더52px, 일반 우측 조회320px일 때 지도624px, 생활인구19시11,246,286 및 모달→본문→지도19시 유지, 상권 종로구→종로3가역→추이→닫기에서 선택/140%/4분기 유지, 출처 원본 링크를 실제 확인했다고 보고했다. 이는 부모의 실행 결과다.

P2 권고: 단위 옆 지표 의미ⓘ와 내려받기 옆 출처ⓘ의 모양이 같아 구별이 약하다. 접근성 이름/툴팁은 다르므로 차단 결함은 아니다. 단일 ‘자료 안내’ 안의 의미/출처 구획으로 묶는 방안을 검토할 수 있다.

새 이미지 미검수 범위는 일반4자료 통합 헤더, 시연용 새 글꼴/헤더, 우측/플로팅 최소 지도폭·투명도, 좁은 폭의 긴 조회값, 출처 팝오버 키보드·터치다. 이전 빌드 검증을 새 변경의 통과로 대신하지 않는다.

### 시연·우측 배치·가로 플로팅 추가 검토

같은 폴더의 `presentation-map.jpg`, `right-dock.jpg`, `floating-wide.jpg`를 독립 열람했다.

- 시연 지도: 한 줄 헤더의 자료 선택·상세 콤보·모드, 한 줄 실제 조회값이 잘리지 않는다. 지도와 구 이름, 현재 시각 주지표를 읽을 수 있고 보조 비교는 접힌 상태다. 새 시연 지도 사례의 공간/판독성은 수용 가능하다.
- 우측 배치: 지도·순위·조회3단이 되지만 현재 사례에서 지도 구 이름과 순위 값은 유지된다. 순위 안내 문장이2줄인 것은 주수치 잘림과 다른 허용 가능한 보조 설명이다. 지도폭624px는 부모 실측이다. 우측 배치는 작업자가 선택하는 방식으로 유지하고 기본 상단 배치를 바꾸지 않는 편이 지도 중심 목적에 맞다.
- 가로 플로팅: 제공 이미지는 수정 전이다. 넓은 제목행과 시간 바로이동 단독 칸이 빈 공간을 만들며 지도 상부를 많이 가린다. 부모가 제목행44px와 시간 도구 재배치를 수정 중이라고 전달했으므로 이 사례는 재확인 대기다.2열 전환 자체는 확인되지만 컴팩트한 최종 창으로 통과시키지 않는다.

부모는 실제 드래그x846→196, 크기360×480→776×361에서2열 전환, 투명도50% 뒤 오른쪽 자석 부착 시 우측 배치/불투명 흰 배경 전환을 확인했다고 보고했다. 정적 캡처는 이동 과정이나 투명도 복원 동작 전체를 증명하지 않으므로 부모 실행 기록으로 분리한다. 새 일반4자료 헤더 전수/긴 값/출처 키보드·터치 검수 범위는 여전히 별도다.

### 가로 플로팅 최종·전체화면 재확인

`floating-wide-final.jpg`, `fullscreen-top.jpg`를 추가 열람했다. 가로 창은 제목행이 압축되고 시간 바로이동이 시각 입력 옆에 붙어 단독 도구가 빈 셀을 만들던 문제는 해소됐다. 부모 실측은 제목행44px, 창776×331px다. 사용자가 선택한 큰 플로팅은 지도를 일부 가리지만 창을 옮기거나 상단 복원하는 경로가 보이며, 이전처럼 입력 자체의 잘못된 빈칸 때문에 커진 구성과 구분한다.

전체화면은 상단 실제 조회 한 줄, 좌측 지도 범위 전환, 우측 확대·표시 도구, 하단 작은 범례가 서로 겹치지 않는다. 구명도 판독 가능하다. 부모는 조회 높이51px·지도 시작y113/높이647px·도구폭369px 및 우측 배치/자료 변경/전체화면 닫기 복귀를 실제 확인했다고 보고했다. 이 사례의 정적 배치에는 새 차단 결함이 관찰되지 않는다.

P2 확인 사항: 최종 플로팅 이미지에서 우측 정보와 출처 텍스트가 파란 범위선택 상태다. 캡처 직전 수동 선택이면 화면 결함으로 보지 않는다. 창 이동/크기 조절에서 뜻하지 않게 생긴 선택이라면 드래그 중 본문 선택 방지가 필요하다. 이미지만으로 발생 원인을 확정하지 않고 부모에 확인을 요청했다.
