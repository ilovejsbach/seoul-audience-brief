# 구별 상세 클릭 원인과 개선

2026-11-14 실제 게시 화면의 상태(시연용 1장 / 생활이동 / 영등포구 선택 / 같은 구 팝업)에서 재현했다.

## 원인

- 상세 버튼은 같은 `district` 값을 다시 넣고 팝업을 닫기만 했다. 이미 선택한 구에서는 지역 상태가 변하지 않았다.
- 생활이동은 확보한 자료가 구 단위여서 동 지도로 내려가지 않는다. 지도 전체 구의 색과 순위는 비교를 위해 유지되므로 화면 변화가 작았다.
- 시연 1장은 시간 추이를 숨긴다. 구를 선택해도 실제 상세 정보가 있는 2장으로 이동하지 않았다.
- 상세 내역 표의 지역명은 일반 텍스트여서 클릭 동작 자체가 없었다.
- 공통 팝업이 생활이동에도 “동별 내역 확인”이라고 안내해, 실제 자료 범위와 다른 기대를 만들었다.

## 적용하는 대안

1. 생활이동의 상세·순위·표 선택은 지역을 적용하고 해당 구의 시간대별 추이로 이동한다. 같은 구를 다시 눌러도 이동한다. 시연에서는 2장으로 전환한다.
2. 전입·전출과 추정매출은 확보된 동 자료로 들어간다. 상세 표의 지역을 실제 버튼으로 연결하고 선택 표시와 전체 복귀를 제공한다.
3. 현재 지역과 가능한 상세 범위를 지도 근처에 표시하고, 생활이동은 동별로 내려갈 수 없다는 점을 행동 안내에도 반영한다.

단순히 클릭 안내만 바꾸는 방식은 실제 이동이 없어 제외했다. 구내 동별 생활이동을 임의로 추정하는 방식도 원자료가 없어 제외했다. 후속 확장으로는 이미 확보된 출발지·도착지 자료를 이용한 상대 지역별 이동 내역이 가능하지만 이번 수정은 기존 상세 여정의 연결과 피드백에 집중한다.

이전 E2E는 구 선택 후 값 변경을 확인했으나, **이미 선택한 구의 상세를 시연 1장에서 다시 누르는 경로**와 **텍스트 표의 클릭 기대**를 포함하지 못했다. 이번 회귀 검사에 추가한다.

## 수정 후 검증

Chrome의 배포용 빌드에서 신규 경로 4건(시연 동일 구 반복 상세, 생활이동 표 선택·복귀, 매출 구→동 표 선택, 전입·전출 과거 연도 대체 표시)과 기존 회귀 4건(생활이동 집계, 전입·전출, 매출 조건, 시연 3장)을 통과했다. 실행 기록은 `tests/e2e-artifacts/district-detail-results.json`, 반복 실행기는 `tests/district-detail-e2e.mjs`에 저장했다. 테스트는 조건 적용과 모드 전환 완료를 기다린 뒤 다음 행동을 한다.
