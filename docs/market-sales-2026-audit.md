# 2026년 상권 추정매출 독립 데이터 감사

검사일: 2026-11-17. 수집·준비 코드와 프런트엔드 계산을 가져오지 않고 원본 CSV 열과 준비 JSON을 별도로 대조했다. 데이터·구현 파일은 수정하지 않았다. 이 문서는 실제 화면과 공개 배포의 통과를 뜻하지 않는다.

## 판정과 범위

- 준비 매출128,053행의 키와 노출 수치 전 필드가 원본과 일치한다. 기존2025년85,732행은 세션 시작 스냅샷과 순서·값이 모두 같다. 기존 공덕역2025Q4 체크포인트도 일반 검증에서 그대로 통과했다.
- 2026Q1은21,188행, Q2는21,133행이다. 중복키·음수·잘못된 숫자 타입·준비 수치 null은 모두0이다. 이는 **이번 공식 CSV에 빈값이 없어 null이 없다는 뜻**이며, 일반적인 결측을0으로 채워도 된다는 뜻이 아니다.
- 모든 매출 상권코드는2023년 경계에 연결된다. Q1은1,564상권, Q2는1,566상권이고, 전체1,650경계 중 각86·84개에는 해당 분기 관측값이 없다. 관측 없는 경계는0매출과 다르다. 브라우저의 회색·자료 없음 표현은 부모가 별도 확인한다.

## 원본 다운로드와 Sheet의 차이

요청은2026Q1–Q2 범위였지만 다운로드 CSV에는2025년까지 포함한128,053행이 들어 있다. 수집기가2026을 명시적으로 골라 기존2025자료에 붙이는지 확인했다. 새 다운로드의2025년 숫자와 업종 필드는 기존 ZIP과 같다. 다만218행의 상권명에 `종로·청계`가 `종로?청계`로 바뀐 문자 차이가 있어 **새 다운로드 전체를 기존2025와 바이트 동일하다고 부르면 안 된다.** 준비2025레코드는 기존 값을 유지한다.

[Sheet 원응답](evidence/market-sales-2026/official-preview.txt)과 [동일키25필드 비교](evidence/market-sales-2026/preview-vs-csv.json)를 별도로 저장했다. 예를 들어20262/3001496/CS300032의00–06시·21–24시·10대 매출은 Sheet에서 빈 문자열, 다운로드 CSV에서는 문자열`0`이다. 같은 키의 여성 매출은 Sheet`19852895`, CSV`198528950`로 **비어 있지 않은 값도 다르다**. Sheet가0만 숨긴다는 원인은 확정하지 않았다. 준비파일은 공식 전체 CSV의 숫자 리터럴을 그대로 보존한다. Sheet와 CSV의 차이는 제공처 확인이 필요한 잔여 한계다.

## 코드·경계·명칭의 해석

2025 매출에 없고2026에 나타난 코드는3110086·3130011·3130193 세 개다. 모두 기존 경계에 있으므로 신규 매출 관측을 신규 경계 신설로 해석하지 않는다.2026원본과 경계의 이름 차이는 다음과 같다. 유형코드·유형명 차이는 없다.

|코드|2026 매출 원본 이름|2023 경계 이름|
|---|---|---|
|3001494|종로?청계 관광특구|종로·청계 관광특구|
|3110379|KTNG 북부지사|KT&G 북부지사|
|3110024|혜화동주민센터|혜회동주민센터|

구·동은 매출 CSV의 열이 아니라2023경계의 대표 속성이다. 준비된 구·동이 해당 경계 속성과 일치함은 확인했으나 **2026행정구역 소속·실제 공간 형상이 동일함은 독립 확인하지 못했다.** 코드 연결을 시간상 경계 호환성 검증으로 확대해서는 안 된다. [원본 ZIP 도형 검사](evidence/market-sales-2026/raw-geometry-validity.json)와 준비 경계의 유효성 검사 모두에서3110137·3110270·3110234·3110407·3110515·3110542의6도형에 자기교차가 남아 있다. 정밀 면적·밀도 분석에 부적합하다.

[서울시 공식 설명](https://data.seoul.go.kr/dataList/OA-15572/S/1/datasetView.do)의 제공기준 변경 적용일2026-07-03과2024년부터 표준단위구역 변경,2021년 이후 자료 제공 안내를 직접 확인했다. 이는2023경계와2026 매출의 공간 형상이 같다는 보증이 아니다. [확인한 공식 페이지 원문](evidence/market-sales-2026/official-dataset.html)을 저장했다.

## 실행과 남은 검사

```sh
python3 scripts/audit-market-sales-2026.py
python3 scripts/validate-market-data.py --output docs/evidence/market-sales-2026/general-data-validation.json
```

독립 스크립트는 세션 스냅샷이 없으면 원래2025 ZIP에서 기존 공개스키마를 독립적으로 재구성해 대조한다. Shapely가 있으면 경계 유효성도 검사하고, 없으면 미검사로 기록한다. 이번 감사는 별도 임시환경의 Shapely로 실행했다. 기존 dirty 파일`tests/e2e-artifacts/market-data-validation.json`은 덮어쓰지 않았다.

부모의 실제 크롬 검수에는 두 모드의 분기 전환·표/지도/추이/후보/CSV 동일값·원래 지역/카메라 복귀·2026자료 없는 상권의 null·긴 제목·출처 경계 경고·공개 배포 파일 갱신이 남는다. 이 데이터 감사만으로 해당 동작을 통과 판정하지 않는다.
