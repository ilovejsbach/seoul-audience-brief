# 기본·선택 색상 범례의 의미와 소형 표시 검토

2026-11-15 · 독립 소스 감사 · R06/R08/R10/R11/R17/R20.

사용자의 ‘기본 색상 범례’와 ‘선택한 색상 범례’는 의미 확인 중이다. 아래는 확인된 코드와 가능한 설계의 구분이며 구현·브라우저 실행·최종 사용자 선택을 대신하지 않는다. 범례를 다시 큰 상시 패널로 늘리지 않는 것이 공통 전제다.

## 1. 가능한 세 의미를 섞지 않는다

| 의미 | 실제 비교 대상 | 적절한 이름 | 원값 영향 |
|---|---|---|---|
| A. 색상 설정 비교 | 현재 조회 자료의 자동 눈금과 사용자가 조정한 min/max 눈금 | 자동 기준 / 현재 적용 | 없음. 같은 값이 다른 명도로 보일 수 있음 |
| B. 지도 선택 표식 | 값의 채움색과 선택 지역·상권을 표시하는 테두리 | 값의 색 / 선택 영역 표시 | 없음. 선택해도 채움색은 수치 색상 유지 |
| C. 조회 범위 비교 | 전체 지역의 색상 눈금과 필터로 좁힌 지역들의 색상 눈금 | 전체 조회 기준 / 현재 조회 기준 | 모집단·공간범위가 다름. 같은 명도라도 값 구간이 달라질 수 있음 |

A에서 ‘기본’도 초기 설정(0 포함 등)인지, 현재 선택한 자동 방식(관측최저 여유·분위 등)의 재계산값인지 정해야 한다. B의 ‘선택’은 데이터 색상 범위를 바꾸는 뜻이 아니다. C를 요청한 경우 A의 수동 범위 비교로 대신해서는 안 된다.

## 2. 현재 공통 기능

`MapLegendTooltip`은 작은80×9px 그라데이션과 ‘범례’ 설명 단추를 상시 표시한다. 본문은 `DataMeaning` 툴팁 안에서 요약, 색상항목, 정확 경계값, 주의를 읽는다. 현재 Entry는 `color/label/exactLabel`만 있어 **선택 테두리나 점선 등 표식의 모양을 설명할 구조는 없다.** 두 가지 범례 집합이나 자동/적용 쌍도 받지 않는다.

툴팁의 최대 높이는340px 또는 화면 높이에서24px를 뺀 값이다. 새 기능을 여러 행 상시 표시하거나 집합 두 개의10여 구간을 한 번에 모두 늘어놓으면 앞선 범례 과다 문제를 반복한다.

`useMapRange`의 입력에는 `automaticLow/automaticHigh`가 항상 들어온다. 적용 `low/high`는 수동값이 있으면 수동값, 없으면 자동값이다. 현재 반환에는 적용 low/high·manual·범위밖 개수·초기화·위치함수만 있다. **자동 기준값은 계산돼 있지만 소비 컴포넌트에 노출되지 않는다.** A를 구현한다면 hook에서 자동 범위 메타를 읽게 하거나 소유 컴포넌트의 기존 계산값을 전달할 수 있다. 단 자동 범위 메타 두 숫자만으로 분위 구간을 재구성할 수는 없다.

수동 범위는 같은 단위·대칭 상태에서는 조건 변화에도 유지될 수 있고 자동 기준은 현재 자료에 따라 바뀐다. 따라서 ‘기본’은 과거 최초 진입 때의 고정 범위라고 표시하면 사실과 다르다. 과거 기준 고정 비교는 별도의 snapshot 계약이 필요하다.

## 3. 지도 계열별 현재 상태와 확보 가능한 기준

| 계열 | 현재 적용 범례 | 자동/기본 기준 확보 | 선택 표식 |
|---|---|---|---|
| 일반 구·동 `MapCanvas` | 연속색 대표값5개와 결측. 음수/순이동은0 중심 주황–중립–파랑. 현재 적용 low/high를 표시 | `calculateMapColorDomain(currentValues,colorMode,padding)`가 관측 min/max와 자동 범위 제공. zero 기본과 observed 여유 자동은 다름. divergingMetric은 음수가 없어도0 대칭 강제 | `path.selected`는 원래 fill=shade(value) 유지, 테두리 강조. 선택 라벨은 값도 표시. 현재 범례엔 테두리 의미 없음 |
| 상권 `MarketExplorer` | 기본 quantile 순위별 최대5구간, equal 또는 직접 범위는 같은 값 간격. 같은 값은 같은 색이고 중복 경계는 제거 | current의 `observed` 정렬과 colorMode가 있어 현재 조회에 대한 자동 분위/같은간격 구간을 다시 계산 가능. hook automatic0..max는 분위 구간 자체를 나타내지 않음 | 선택 상권은 fill 유지·짙은 테두리/외곽광 강조. hover는 밝기변화. 현재 범례는 값/결측만 설명 |
| 두 시점 나란히 `DistributionComparison` | 두 시점 관측값 합집합의 공통5구간 | pairedValues 최대값으로 자동0..max. sideRange 자동/수동 모두 존재. 두 지도를 각각 자동으로 재정규화하면 안 됨 | 클릭하면 상위 지역 선택 화면으로 이동. 이 컴포넌트에 persistent selectedCode/선택영역 상태는 없음 |
| 증감 분포 `DistributionComparison` | 감소5구간·0·증가5구간·결측, 적용 deltaRange는0 대칭 | deltaValues 최대 절댓값으로 자동[-max,+max]. 수동도0 대칭. 자동값과 적용값 비교 가능 | 마우스 오버/초점 테두리는 있으나 선택 상태를 유지하는 범례를 붙이면 실제 동작과 불일치 |

일반 지도의 현재 `values`는 현재 구/동 경계 컬렉션에 해당한다. C의 ‘전체 서울 구 기준’과 ‘선택 구 동 기준’은 집계 공간 단위가 달라 이를 단순히 같은 기준으로 비교하면 안 된다. C가 필요하면 같은 공간 단위와 같은 조회 조건에서 전체/필터 모집단을 별도로 전달해야 한다.

상권은 current에 전체 상권값, ranked에 공간필터 후 상권값이 있어 C 계산 재료는 비교적 명확하다. 반면 분포 비교는 부모가 넘긴 geo와 frames 자체가 선택 범위일 수 있으므로 이 컴포넌트 혼자 전체 서울 기준을 보유한다고 가정할 수 없다.

## 4. A가 의도일 때의 컴팩트안

상시 표시는 기존 작은 그라데이션+범례 단추를 유지한다. 필요하면 작은 ‘직접’ 상태표시만 추가한다. 그라데이션은 현재 지도에 실제 적용된 색상에 대응한다.

툴팁 안은 다음 순서가 적절하다.
1. **현재 적용**: 방식, 최솟값–최댓값, 단위, 대칭/공통 여부. 실제 지도 구간만 기본 펼침.
2. **자동 기준과 비교**: 같은 조회 조건의 자동 방식·범위를 한 줄 또는 접힘 정보로 표시. 자동과 같으면 ‘자동 기준과 같음’ 한 줄로 중복 제거.
3. 범위 밖 개수와 결측 설명. 양 끝 색으로 포화된 값은 원값이 잘린 것이 아님을 표시.

예: ‘자동 기준 0–100,000명 / 현재 적용20,000–80,000명 · 직접 지정’. 상권은 ‘자동 기준: 순위별 분위’와 실제 분위 경계 집합을 보존해야 한다. 자동0..max를5등분해서 분위 범례라고 부르면 안 된다.

초기화는 표시 설정에 있는 기존 동작을 사용한다. 범례를 읽는 행과 설정 편집 입력을 모두 한 툴팁에 밀어 넣을 필요는 없다.

## 5. B가 의도일 때의 컴팩트안

툴팁의 기존 값 범례 아래 ‘지도 표식’이라는 작은 구분을 둔다.
- 색 채움: 현재 지표의 값(기존 그라데이션/구간).
- 두꺼운 외곽선: 현재 선택한 지역/상권. 필요하면 선택 이름을 한 줄 표시.
- 회색: 자료 없음이며0과 다름.

선택 표식은 단순 채움 사각형이 아니라 실제 테두리 모양을 그려야 한다. 흰/투명 채움+짙은 테두리의 작은 모양이 적합하며 데이터의 특정 값 색상처럼 보이게 하면 안 된다. 선택된 지역의 현재 fill은 값에 따라 변하므로 ‘선택색=남색’처럼 고정 데이터색으로 설명하지 않는다.

현행 일반 지도는 selected/hover/focus 테두리 색이 겹칠 수 있다. 범례 문구는 소스의 실제 동작과 맞아야 한다. 선택만의 유일한 시각 표식으로 안내하려면 hover/키보드 초점과 구분되는 굵기·윤곽을 함께 설계하고 실제 상태별로 확인해야 한다. 분포 비교는 클릭이 화면 전환이므로 존재하지 않는 지속 선택 범례를 추가하지 않는다.

## 6. 세 위계 배치와의 관계

현재 별도로 확인 중인 상단/좌측/본문의 세 위계 배치와 독립적으로, 범례는 ‘표시 설정’과 ‘해석’을 연결하는 도구다. 조회 조건의 자료·기간·지역보다 높은 주메뉴로 승격시키지 않는다. 읽기 범례는 지도 가까운 작은 단추, 편집 도구는 색상·표시 설정에 두는 역할 분리가 맞다.

현재 적용·자동 비교·선택표식을 모두 원하는 경우에도 상시 큰 패널3개를 만들지 않는다. 툴팁 안에서 ‘값의 색’과 ‘지도 표식’을 분리하고 자동 비교는 필요할 때 펼친다.

## 7. 부모 구현 후 실행해야 할 판정
- 선택 의미 A/B/C가 확정된 이름·산식으로 구현됐는지 확인한다.
- 일반0포함/관측여유/직접범위, 음수/순이동0대칭, 상권분위/동일간격/직접범위, 두시점공통/증감에서 실제색과 범례경계가 같다.
- 자동 기준은 현재 조건 변화에 따라 다시 계산되고 수동 적용은 계약대로 유지/초기화된다. 자동과 적용이 같으면 범례를 중복해 늘리지 않는다.
- 같은 값·중복분위·모두0·단일관측·자료없음·범위밖값을 처리한다. 양 끝 포화값·결측 개수와 정확값을 독립 대조한다.
- 선택/해제/hover/키보드초점과 범례 표식이 일치하고 선택은 원값·기본 색상 범위를 임의로 바꾸지 않는다.
- 창 열기/Esc/내부읽기/자료변경/전체화면/좁은PC에서 작동하고 그래프/지도 높이가 줄지 않는다. 현재 타입4/6단계와 대비를 유지한다.

이 문서는 소스 감사와 설계 제안이며 구현 완료나 실제 E2E 통과 판정이 아니다.

### A의 두 줄 요약 예시
툴팁 안에서 ‘자동 기준 [실제 색상 막대] 0–100,000명’, ‘현재 적용 [실제 색상 막대]20,000–80,000명 · 직접’의 두 줄로 먼저 읽을 수 있다. 색 막대 옆에 방식과 숫자를 함께 두어 같은 파랑 팔레트라도 값 대응이 다름을 알린다. 분위는 실제 비균등 경계에 맞는 이산색/구간을 표시하고 연속 균등 막대라고 설명하지 않는다. 자세한 전체 구간은 필요할 때 펼친다. 자동과 적용이 같으면 한 줄로 합친다. 이는 툴팁 내부의 비교이며 상시 두 줄짜리 큰 범례 영역을 새로 만들자는 뜻이 아니다.

## 사용자 확인으로 확정된 현재 요구
2026-11-15 사용자는 기본 자동 범위/현재 범위 비교가 아니라 ‘그라데이션 색상표 선택’을 의미한다고 확인했다. 위 A/B는 질의 전 의미 구분을 위한 감사이며 구현 요구가 아니다. 현재 적용 대상은 팔레트 선택기, 기본/선택 팔레트 미리보기, 지도와 범례의 동기화다. 수치 범위 비교 기능을 추가하지 않는다.
