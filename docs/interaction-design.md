# 서울 지역 인사이트: 목적과 상호작용 검토 기준

이 문서는 구현 완료 보고가 아니라 화면을 판단하는 기준이다. 아래 항목은 실제 화면·자료·내보내기를 대조해 통과 여부를 확인해야 한다. 특히 행정동 지도, 도착시간 기준 이동, 광고 성과 예측은 구현된 기능으로 약속하지 않는다.

## 1. 사용 목적

광고주가 서울의 어느 지역과 시간대를 더 조사할지 정하도록 돕는다. 기본 동선은 **탐색 → 후보 최대 3곳 비교 → 근거 설명 → 표 내보내기**다. 예를 들어 “평일 저녁에 20~39세가 많은 지역”을 찾고, 같은 날짜·시간·성별·연령 조건으로 후보를 비교한다. 인구가 많은 사실만으로 광고 도달·매출·전환율이 높다고 결론 내리지 않는다.

- 탐색: 사용자는 현재 지역·기간·시간·대상과 수치의 뜻을 알 수 있어야 한다.
- 비교: 후보끼리 같은 기준을 사용하고, 선택을 바꾸거나 해제하는 방법이 보여야 한다.
- 설명: 결론을 뒷받침한 출처·기준일·결측·경계 한계를 확인하고 현재 조건의 표를 받을 수 있어야 한다.

## 2. 네 탭의 정보 단위

| 탭 | 질문 | 표시·계산 기준 | 혼동 방지 |
|---|---|---|---|
| 생활인구 | 특정 시간에 어느 지역에 얼마나 머무는가? | 날짜 × 시각 × 지역 × 성별·연령, 추계 인구 명 | 시점 인구이며 고유 방문자·하루 누적 방문자가 아니다. 내국인 자료임을 명시한다. |
| 생활이동 | 어느 지역에서 어디로 이동하는가? | 자료가 제공하는 날짜 × **출발시각** × 구 OD, 추정 이동 건수 | 같은 구 내부 이동을 제외한다면 지도·요약·CSV 모두 동일하게 제외한다. 도착시간 유입이나 고유 인원으로 부르지 않는다. |
| 거주지 전입·전출 | 거주지가 어디로 옮겨 가는가? | 연도 × 구 또는 동, 전입·전출 명, 순이동=전입−전출 | 일상 방문과 분리한다. 공식 구 총계와 동별 값을 한 합계에 섞지 않는다. 결측이 있으면 순이동도 결측이다. |
| 상권·추정매출 | 어떤 지역·업종·시간대에서 소비가 관찰되는가? | 기준 분기 × 지역 × 제공 업종 범위, 매출 원·거래 건 | 분기 원값과 선택 시간구간의 값을 구분한다. 전체 소비·개별 점포 회계매출로 표현하지 않는다. |

필터가 없는 차원은 선택할 수 있는 것처럼 보이지 않아야 한다. 자료가 없는 지역·시간·지표는 0 대신 “자료 없음”으로 표시한다. 최신 자료와 과거 자료의 경계·산정 방식 차이를 무시한 비교도 피한다.

## 3. 휴리스틱에 따른 기준

### 현재 상태의 가시성

- 탭 이름과 함께 “어떤 질문에 답하는 화면인지” 한 문장으로 설명한다.
- 지역·기간·시간·단위·대상 인구를 요약 수치와 지도 제목 가까이에 계속 표시한다. 출처 링크와 기준일은 표 또는 차트 아래에서 바로 찾을 수 있어야 한다.
- 로딩 중, 자료 없음, 요청 실패를 구분한다. 날짜 변경 후 이전 날짜 수치가 새 날짜 이름 아래 남아 있으면 안 된다.
- 선택한 지도 지역·동·비교 후보가 시각적으로 구별되어야 한다. 색상만으로 선택·증감·결측을 전달하지 않는다.

### 일관성

- 지도·순위·요약·상세·비교·CSV는 같은 선택 조건을 따른다. 예외적으로 순위 전체를 내보내면 버튼에 그 범위를 명시한다.
- 같은 단위를 같은 형식으로 표시한다. 명/추정 이동 건수/원/거래 건을 섞지 않고, 축약 금액의 원 단위 원값을 확인할 수 있게 한다.
- 탭 이동 시 유지하는 조건과 초기화하는 조건이 예측 가능해야 한다. 지원되지 않는 연도·시간은 조용히 다른 값으로 바꾸지 말고 현재 선택을 보여 준다.
- 유입/유출과 전입/전출의 명칭을 구별한다. 상권 매출은 이동인구용 열 제목을 재사용하지 않는다.

### 오류 예방과 회복

- 구와 동을 동시에 합산하지 않는다. 동별 목록은 선택한 구에 속한 행만 보여 준다. 행정동 이름이 중복될 수 있으므로 구명·코드를 유지한다.
- 결측·비식별·요청 실패를 0으로 변환하지 않는다. 결측 구간 차트를 연결해 관측한 것처럼 표현하지 않는다.
- 다른 기간·공간 기준을 가진 인구와 매출을 나누어 구매전환율을 만들지 않는다.
- 비교 후보는 최대 3곳으로 제한하며 해제 방법을 제공한다. 필터 변경으로 후보가 무효가 되면 해제되었음을 알아볼 수 있어야 한다.
- 파일을 내보낼 때 탭, 지역 단위, 기간, 시간 기준, 성별·연령, 구내 이동 제외 여부 등 적용 조건과 출처를 남긴다.
- 공식 소스 간 불일치가 확인된 2023년 거주지 이동은 해당 연도 근처에 검증 한계를 표시한다. 원본 결측은 유지한다.

### 기억보다 알아보기

- 행정동은 이름으로 선택하고 구 소속을 확인한다. 코드만 보고 고르게 하지 않는다.
- 지도 색상 범례에 지표·단위를 붙인다. “많음/적음”만으로 매출인지 인구인지 추측하게 하지 않는다.
- 후보 비교에는 날짜·시간·대상 조건을 다시 보여 준다. 앞 화면의 선택을 기억해야 비교할 수 있는 구조를 피한다.
- 짧은 용어 설명을 필터·지표 가까이에 둔다. 출발시간 기준, 생활인구, 추정매출, 순이동 같은 의미를 긴 하단 설명만으로 전달하지 않는다.

## 4. 지도와 동 선택의 한계

현재 사용되는 2013년 자치구 경계는 참고도다. 통계의 기준연도·행정동 코드와 같은 경계라고 보장하지 않는다. 동별 지도 경계가 준비되지 않았다면 지도 클릭으로 동까지 탐색할 수 있다고 표현하지 않는다. **구 지도에서 선택 → 구에 속한 동 목록에서 선택**이라는 실제 경로를 알려야 한다.

구 지도는 공간적 위치와 분포를 파악하는 수단이고 정밀한 경계 판단 수단이 아니다. 선택한 동의 지표를 보여 주면서 구 전체 지도 색상을 동 값처럼 설명하면 안 된다. 행정동 경계가 확보되기 전까지 동별 정보는 목록·표·상세 값으로 확인한다.

## 5. PC 가독성과 가시성 검증

기준 화면은 1440×900, 브라우저 배율 100%다. 실제 렌더 화면으로 확인하며 코드에 규칙이 있다는 것만으로 통과시키지 않는다.

- 첫 화면에서 서비스 목적, 네 탭, 핵심 필터와 현재 단위를 읽을 수 있는가? 큰 소개 문구 때문에 지도·핵심 수치가 지나치게 밀리지 않는가?
- 지도와 상세 목록의 정보 위계가 분명한가? 구 이름·표 숫자·보조 설명을 화면 확대 없이 읽을 수 있는가?
- 본문은 원칙적으로 16px 이상, 보조 문구도 12px 미만을 피한다. 이는 목표값이며 실제 글꼴·밀도와 함께 판단한다.
- 일반 글자 대비는 4.5:1, 큰 글자·필수 UI 경계는 3:1을 목표로 확인한다. 밝은 강조색 위 흰 글자, 어두운 보조 문구, 비활성 선택지의 가독성을 특히 확인한다.
- 표의 머리글·단위·숫자 정렬이 일관적인가? 427개 동을 한 번에 보여 주는 경우 구 필터·스크롤 범위가 분명한가?
- 키보드 Tab으로 필터·지도·비교·내보내기에 도달하고 포커스를 볼 수 있는가? 지도는 Enter/Space 동작과 지역명을 제공하는가?
- 로딩·오류·결측을 실제로 유발했을 때 기존 수치를 새 조건 값으로 오해하지 않는가?

## 6. 모바일 검증

390×844와 375×812에서 확인한다. PC의 열 구조를 그대로 줄이는 것으로 끝내지 않는다.

- 가로 넘침 때문에 필터·숫자·버튼이 화면 밖으로 잘리지 않는가? 넓은 표만 별도 가로 스크롤을 허용하고 그 범위를 구별한다.
- 필터 → 요약 → 지도/표 → 상세 → 비교 → 출처 순서가 자연스러운가? 탭과 기간을 손쉽게 바꿀 수 있는가?
- 주요 터치 영역은 44×44 CSS px 수준을 목표로 하며 인접 버튼을 잘못 누르지 않는가?
- 지도 글자가 작아지면 동일 지역을 텍스트 목록으로 선택할 수 있는가? 지도 확대 없이 핵심 지표를 읽을 수 있는가?
- 최대 3곳 비교 카드가 순서대로 읽히며 삭제 버튼과 조건 요약이 남는가?

## 7. 통과 판정 방법

완료 판단은 네 탭 각각에서 대표 조건 한 개 이상을 원본 데이터와 대조하고, PC·모바일 실제 화면과 CSV를 확인한 뒤 한다. 특히 결측 전입 사례, 구/동 전환, 출발시간 이동, 성·연령 선택, 매출 시간구간을 별도 확인한다. 이 문서의 기능·수치·화면 목표 중 구현되지 않은 항목은 후속 과제로 남기며 구현 완료로 서술하지 않는다.

## 8. 지역 퍼널·시계열 퍼널 시나리오

여기서 퍼널은 조사 범위를 좁혀 가는 **탐색 단계**다. 같은 사람을 추적하는 코호트 퍼널이나 광고 전환 퍼널을 뜻하지 않는다. 단계마다 지역·시각·자료의 모집단이 달라질 수 있으므로 앞 단계 수치로 다음 단계 수치를 나누어 전환율을 만들지 않는다.

| 탐색 축 | 단계 | 검토 기준 |
|---|---|---|
| 지역 | 서울 전체 → 자치구 → 행정동 → 후보 최대 3곳 | 각 단계에서 현재 범위와 상위 지역으로 돌아가는 방법이 보인다. 행정동 지도 미지원이면 목록 선택 경로를 명시한다. |
| 시계열 | 제공 기간 → 날짜 → 시각 | 선택 가능한 해상도만 제공한다. 생활이동은 출발시각 기준이며, 연간 거주지 이동은 연도까지만 선택한다. 분기 매출은 분기와 원본 시간구간을 사용한다. |
| 설명 | 같은 조건의 후보 비교 → 다른 자료로 보완 → 조건과 출처를 담은 CSV·인쇄 | 탭 간 서로 다른 날짜·분기를 같은 조사시점처럼 합치지 않는다. 비교 불가능한 조건은 별도로 표시한다. |

대표 과제는 다음과 같다. 이 시나리오는 평가용이며 모든 단계가 구현되었다는 약속이 아니다.

1. 생활인구에서 **여성 20~39세**를 선택하고 서울 전체에서 마포구로 범위를 좁힌다. 구에 속한 동 목록에서 후보를 최대 3곳 담는다. 마포구 전체와 선택 동을 같은 행에 합산하지 않는다.
2. 같은 날짜·타깃의 후보를 **18시와 12시**에 비교한다. 현재 기능이 한 번에 한 시각만 보여 준다면 시각을 바꾸어 살펴보는 방식임을 명시하고, 두 시각 비교가 동시에 지원된다고 표현하지 않는다. 두 시각의 생활인구 합을 하루 고유 방문자 수로 해석하지 않는다.
3. 생활이동 탭에서 마포구의 외부 유입·유출과 이동시간 분포를 보완해 본다. 공개 가공자료가 구 단위·전체 인구·출발시각만 지원하면 여성 20~39세·동별·도착시각 조건이 유지된 것처럼 보이지 않게 한다. 생활인구 타깃에 대한 이동으로 추정하지 않는다.
4. 상권 탭에서 확보된 분기와 시간구간의 추정매출을 별도로 확인한다. 2026년 특정 일자의 생활인구와 2025년 분기 매출은 서로 다른 시기임을 분명히 한다. 매출/생활인구로 구매전환율을 만들지 않는다.
5. CSV 또는 인쇄물에 각 자료의 탭, 지역, 기간, 시각 기준, 적용된 타깃, 단위, 출처, 결측·범위 한계를 남긴다. 미지원 타깃은 “적용 안 됨” 또는 “전체”로 표시해, 선택한 타깃이 모든 자료에 적용된 것으로 오해하지 않게 한다.

## 9. 현재 구현 구조를 반영한 추가 검토 항목

다음은 2026-11-14 코드에서 확인한 흐름이며, 실제 렌더·키보드·인쇄 검증을 대신하지 않는다.

- 시작 화면은 지역 탐색·시간 탐색·거주 변화 시나리오와 확보 데이터 네 종류의 진입점을 제공한다. 사용자는 분석을 시작한 뒤 시작 화면으로 돌아오고 이전 분석을 이어갈 수 있어야 한다. 시나리오 선택은 분석의 입구이며 자동으로 타깃을 설정하거나 자료 간 모집단을 연결했다는 의미가 아니다.
- 분석용/시연용은 같은 데이터·계산을 사용한다. 시연용에서 세부 조건을 접어도 현재 적용 지역·시점·타깃·단위와 결측 안내를 알 수 있어야 한다. 조건을 다시 열었을 때 선택이 유지되는지 확인한다.
- 지도 지역을 누르면 값·조건·출처를 담은 정보창에서 상세 보기 또는 비교 추가로 진행한다. 이 정보창이 지도 지역명·값을 가리지 않고 닫기·키보드 포커스·선택 상태를 제공하는지 검증한다. 단순 hover만으로 필수 기능에 접근하게 해서는 안 된다.
- 지역·시간 탐색 단계 표시와 두 시점 비교가 함께 존재한다. 두 시점 비교의 기준·선택 값이 같은 자료·지역·타깃으로 계산되고, 어느 한 값이 결측이면 차이도 결측인지 확인한다. 단순 차이는 광고 효과나 코호트 전환이 아니다.
- 날짜 변경 중 또는 요청 실패 시 이전 날짜 수치가 새 날짜 이름 아래 표시·저장되지 않아야 한다. 로딩 문구만 추가한 상태로 이전 수치를 노출하는 것은 통과가 아니다.
- 동 지도·전체화면 기능이 추가되는 경우, 구현된 경계의 기준일·코드 연결·누락 지역·화면 종료 동작을 새로 대조한다. 이 문서 작성 당시의 구 참고도 한계를 새 경계가 검증되기 전에 삭제하지 않는다.
