# 상권 지도 탐색·정보창·플로팅 검증

2026-11-16 · 실제 macOS Chrome · 로컬 및 GitHub Pages 재검증.

## 목적과 수정

서울 전체에서 구의 상권 분포를 좁혀 보고, 개별 상권의 규모·분기 추이를 확인한 뒤 같은 조건의 구 지도로 돌아오는 여정을 검사했다. 정보창은 현재 지도 수준의 근거를 보여 주고, 추이·후보 담기는 별도 동작으로 제공한다.

실제 화면에서 발견하고 수정한 문제:

1. 시연용의 일반 지역 브리핑 숨김 규칙이 상권 추이까지 숨겨 빈 화면이 나왔다. 규칙을 일반 분석 영역으로 제한하고 상권 그래프를 현재 영역 크기에 맞췄다.
2. 조회·상세 플로팅 창의 초기 위치가 같아 겹쳤고, 상단 버튼을 가렸다. 좌우로 분리하고 작업 바 아래에서 열도록 했다. 창 높이를 포함해 이동·크기 변경·화면 변경의 경계를 제한한다.
3. 추이 앞에 지도용 창과 범례가 남았다. 추이 진입 때 플로팅 창을 임시 숨기며, 필요하면 명시적으로 다시 연다. 추이 종료 후 열린 상태를 유지하고 뒤 지도로 키보드 초점이 새지 않게 했다.
4. 상권 클릭은 정보창만 바꿨다. 상권 경계로 확대하고 정보창을 함께 전환한다. 서울 전체 → 구 → 상권 경로와 구 지도 복귀를 제공하며 선택·조회 조건·이전 지도 위치를 유지한다. 구 복귀 시 정보창도 구 요약과 목록으로 바뀐다.
5. 작업공간 높이가 화면 높이에서 고정 155px를 빼도록 되어 하단이 비었다. 실제 작업공간 시작 위치로 남은 높이를 계산해 지도·정보창을 함께 화면 아래까지 늘린다. PC 화면에 적용하며 작은 화면과 인쇄 규칙은 유지한다.

구현 커밋: `5c8983e`, `d84de17`, 세로 높이 수정 `6778355`. 빌드 성공, 단위 검사 70개 통과. 자동 검사와 아래 실제 브라우저 실행은 구분한다.

## 공개 화면에서 확인한 여정

| 확인 항목 | 결과 |
|---|---|
| 서울 전체 → 종로구 | 구 경계 맞춤, 상권 74개와 종로구 정보창으로 전환 |
| 종로구 → 종로3가역 | 실제 도형 포인터 클릭 및 키보드 실행으로 확대, 경로·개별 정보 동시 전환 |
| 상권 → 추이 → 상권 | 선택·분기·대상·값 유지, 그래프 표시 정상 |
| 상권 → 구 지도 | 기존 배율 140% 복원, 선택 유지, 정보창은 구 목록으로 전환 |
| 이전 화면 → 상권 재진입 | 구·상권·분기·대상 유지, 다른 화면에 상권 플로팅이 남지 않음 |
| 분석용·시연용 | 두 모드에서 추정매출과 유동인구 추이·복귀 확인 |
| 플로팅 두 창 | 좌우 분리, 상단 기능 바 미침범, 추이 임시 숨김·명시 재열기·복귀 확인 |
| 창 이동·크기 변경 | 하단까지 이동·크기 증가 후 창 전체가 화면 안에 유지 |
| 900×700 → 원래 크기 | 좁은 화면에서 요청한 창을 번갈아 표시, 자동 도킹 복귀 후 고정 위치가 남지 않음 |
| 크롬 자체 전체화면 | 분기 변경, 자료 변경, 상권 추이 왕복, 구·서울 전체 복귀 후 전체화면 유지 |

크롬 자체 전체화면 확인에서는 브라우저 디버거를 해제하고 네이티브 Chrome 메뉴·선택창을 조작했다. 조회·자료·상세 왕복 뒤 Chrome 보기 메뉴의 활성화된 **전체 화면 종료**를 확인했다. 이 검사는 페이지의 CSS 확대와 별개다.

## 원자료와 수치 대조

상권 코드 `3120009`(종로3가역):

- 추정매출 2025년 3분기: 원자료 45개 업종 행의 합 **315,641,801,526원**. 지도·개별 정보·추이는 **3,156.42억 원**으로 일치했다.
- 유동인구 2026년 2분기 여성: 원자료 **2,678,264명**. 조건 변경 후 지도·개별 정보·추이·복귀가 일치했다.
- 같은 분기 전체 유동인구 **5,792,307명**도 크롬 자체 전체화면의 자료 변경과 상세 왕복에서 확인했다. 분기 추정치이며 일 고유 방문자 수로 해석하지 않는다.
