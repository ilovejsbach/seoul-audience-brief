# 조회 옵션 단계 적용·실행 보고

2026-11-15 · 로컬 반영·검증 완료 범위. **공개 페이지는 이번 작업에서 배포하지 않았다.**

## 적용 순서와 목적

사용자가 승인한 순서대로 생활인구를 먼저 정리하고 실제 Chrome에서 확인한 뒤 다른 자료로 확장했다. 적용 규칙은 R03/R05/R06/R12/R13/R20이다. 이전 [조회 옵션 감사](query-options-audit-report.md)는 당시 문제와 개편 전 상태를 기록한 이력이며, 이번 구현 결과는 이 문서를 따른다.

생활인구의 질문은 ‘어느 날짜·시각에, 어느 지역에, 어떤 대상이 얼마나 머무는가’다. 기본 입력을 기준일·조회 시각·자치구·행정동·연령·성별 여섯 가지로 제한했다. 넓혀도 기간 → 지역 → 분석 대상 순서의 한 열이다. 날짜 달력은 확보한 2026년1–10월을 직접 탐색하므로 월 선택기를 별도로 반복하지 않는다. 시간 스크러버는 ‘시간 빠르게 이동’ 안의 보조 조작이다.

## 무엇을 바꿨는가

| 역할 | 결과 |
|---|---|
| 조회 | 검색 버튼과 native 선택기를 합쳐 검색 내장 단일 선택칸으로 교체. 긴 이름 줄바꿈, 현재값, 0건 복구, 키보드·Esc 복귀 제공 |
| 조회 영역 | 기본280px·조절260–360px, 플로팅360×560px. 창을 넓혀도 한 열·읽는 순서 유지. 자료별 필요한 내용만 내부 스크롤 |
| 지도 탐색·표시 | 구/동·확대/축소·색상·범위는 조회 본문 밖 지도 도구로 분리. MapCanvas의 복제 도구 JSX를 한 렌더러로 합침 |
| 결과 작업 | 표 내려받기는 결과 제목 행으로 이동. 기본 화면의 상단 조회 진입점을 중복하지 않으며 상세·후보에서는 같은 편집기를 열어 보기 유지 |
| 창 설정 | 제목 옆 하나의 창 설정 메뉴 안에서 배치·투명도·초기화를 유지. 기본은 불투명 |
| 다른3자료 | 기간 → 지역 → 분석 기준 순서. 생활이동의 도착/출발·시간/누적/일계, 전출입의 지원 연도·세분, 추정매출의 분기·매출 시간대는 보존 |
| 상권 | 기간 → 지역·상권 → 분석 대상. 지도 표시를 별도 작은 창으로, 내려받기를 결과 작업으로 이동. 패널·분할선 key 충돌도 분리 |

지도 팔레트·표시 범위·창 배치가 원자료 수치를 바꾸지 않는다. 미지원 연령/성별 교차 집계를 만들지 않았고 원본 자료·계산식·후보 집계도 유지했다.

## 실제 실행 결과

최종 준비 빌드: `index-h46p57Mk.js`, `index-DptfLDNj.css`. Chrome의 실제 조작은 CUA를 통해 수행했다. [실행 원본](evidence/focused-query/results.json), [최종 생활인구 화면](evidence/focused-query/population-desktop.jpg), [반복 가능한 여정](../tests/population-query-e2e.mjs).

### 생활인구를 먼저 검증

1800×905와1366×768 각각13개 시나리오, 총26개 실행 판정을 통과했다. 현재 실행은 이전 감사의 통과를 가져온 것이 아니다.

- 기간/지역/대상 한 열과 지도 도구 분리, 서울 전체 값, 서교동 남성20–39세18시32,951명·12시16,169명을 확인했다. 독립 Decimal 원값은32,951.45명·16,169.34명이다.
- 상세 시연의 동일 조건·그래프 값, 기존 입력 하나에 초점 이동, 현재 보기 유지, 검색0건 복구, 첫Esc 검색창만 종료·두 번째Esc 조회창 종료와 초점 복귀를 확인했다.
- 긴 종로1·2·3·4가동 이름, 다른 달 날짜 적용, 중복 입력 ID 없음, 화면 가로 넘침 없음을 확인했다.
- 날짜 입력 자동화는 필드를 실제 클릭해 편집하고 다른 입력을 클릭하여 확정했다. 필드 포커스 없이 값을 넣기만 한 첫 시도는 상태 확정 증거로 사용하지 않았다.

### 생활인구 통과 뒤 확장 확인

- 생활이동·전출입·추정매출의 기본280px/한 열/지도 도구 분리와 가로 넘침 없음을1800 및1366 폭에서 확인했다.
- 서초구2025년30대 전입13,705명·전출13,007명·순이동+698명이 선택 지표에 맞게 지도 가까운 요약에 반영됐다.
- 생활이동 일자 전체는 시간 선택을 비활성화하고 설명하며, 출발 시각·한 시간으로 바꾸면 조건 요약도 같은 뜻으로 갱신됐다.
- 상권 홍대 → 마포구 → 서교동 → 발달상권 교집합2개와 관련 선택지 A2/R2/D2를 확인했다. 오른쪽 도킹·플로팅 후에도 입력창1개·중복ID0개·조건 결과2개를 유지했다.
- 지도 팔레트를 바꾸면 도형 색이 달라지고, 자료 로딩 완료 후 핵심 지표 문구는 그대로였다. 첫 관찰은 로딩 전 ‘자료 없음’과 로딩 후 값을 비교했으므로 불변 검증에서 제외하고 안정된 자료로 재검사했다.
- 지도 표시 Esc는 표시 설정만 닫고 제목으로 복귀했다. 조회 폭을 방향키로280→290px 조절해도 그룹의 시작선은 같았다.
- 전체화면 대체 오버레이에서는 지도가 남는 영역을 사용하고, 조회창을 열면 날짜 입력1개·한 열3묶음·지도 도구 중복0개였다.

### 개발·독립 검사

`npm run build`, `git diff --check`를 통과했다. 관련값·지원연도·색상/축 범위·팔레트 단위 검사32개를 통과했다. 독립 Codex 검토자는 [생활인구 원자료·수용 기준](population-query-acceptance.md)에서12개 기대값과 지원 범위를 확인했고, 단계 적용 소스에서 추가 중대 계산 회귀를 찾지 못했다. 이는 독립적인 실사용자 시험을 뜻하지 않는다.

## 이번 완료 범위와 제한

- 로컬 개발 화면에 적용했고 Chrome에 최종 생활인구 화면을 열어 두었다. 이번에는 공개 배포·공개 화면 검수·원격 push를 하지 않았다.
- 실제 native 전체화면은 자동화 환경에서 열리지 않아 대체 오버레이로 검사했다. 모든 자료의 마우스 드래그·도킹 충돌·모든 투명도 조합을 새로 전수 실행한 것은 아니다. 이번 조회 개편과 관련된 클릭·키보드 경로 및 대표 도킹 전환만 기록했다.
- 그래프 옵션 내부 전체 재설계, 기존 순위·선택 정보 창의 모든 부가 기능 감사는 별도 범위다. 생활인구 순위는 기존 aside를 유지하고 불필요한 새 래퍼를 연결하지 않았다.
- 실제 사용자 성공률·조회 시간 개선을 실측하지 않았다. 4/6종 글꼴 규칙의 전체 페이지 계산, 모든 긴 이름·결측 조합까지 전수 통과했다고 주장하지 않는다.
