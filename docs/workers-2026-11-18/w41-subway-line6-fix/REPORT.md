1. **원인은 6호선 하나였다.** 좌표 파일의 6호선 외부역코드가 연신내~봉화산 구간(2615~2648, 34개)에서 원본 3종보다 한 칸씩(봉화산은 맨 끝에서 맨 앞으로) 어긋나 있었다. 4호선·7호선의 이름 불일치는 개명(별칭)이었고 다른 호선은 정상이다.
2. **수정:** 시간대·승객유형·혼잡도를 코드가 아니라 (호선, 정규화한 역명)으로 역 마스터에 잇고 다시 준비했다. 합정·상수·광흥창의 시간대·유형·혼잡도 화면 값이 이름 기준 원본과 일치한다. 일별·월별·지도 점은 원래 이름 기준이라 그대로 정상이다.
3. **검증기에 이름 기준 원본 대조 3종과 "일별 합↔시간대 합" 교차 검사를 추가**했다. 수정 전 준비 파일로 돌리면 새 4개가 모두 실패하고(기존 9개는 모두 통과해 빈틈이 있었음을 확인), 수정 후는 13/13 통과, E2E 92/92 통과.

## 3. 수정 방식과 근거

**선택: (호선, 정규화한 역명) 연결 + 코드는 참고 기록.** 근거: 어긋남의 정답 코드를 확정할 수 없고, 보정표를 쓰면 틀린 쪽에 표를 만들 위험이 있다. 이름 연결은 일별(OA-12914)이 이미 쓰던 방식이라 화면 안에서 일별과 시간대가 같은 역을 가리키게 된다.

`scripts/prepare-subway.py`:
- `match_station(line, name, idx)`: 별칭(이수·자양·**4호선 불암산 추가**) → 정규화한 이름(공백·괄호 제거, 끝 "역" 처리)으로 호선 안에서 **하나만** 일치할 때만 연결. 여럿이면 연결하지 않는다.
- 시간대·승객유형·혼잡도가 `match_tx`로 이 함수를 쓴다. 연결 키로 코드를 쓰지 않는다. 9000번대 지선 코드는 건너뛴다.
- 같은 역 id에 서로 다른 원본 코드가 들어오는 충돌을 기록한다(`codeCollisions`, 결과 0).
- 원본 코드가 좌표 파일 코드와 다르면 `stations.json`의 역마다 `txCode`로 기록하고 화면에 둘 다 보여 준다(35역: 6호선 34 + 2호선 까치산 1).
- B7용: 일별 원본에서 1~8호선이 아닌 노선(경부선·경의선·공항철도·9호선 등)에 같은 이름 역이 있는 환승 묶음에 `external` 목록을 붙인다(40개 묶음).
- 원본은 수정하지 않았다. 역 id와 좌표 파일 코드는 그대로다.

준비 결과 변화(이전 대비): 일별 연결 행 383,131 → 383,704(+573, 4호선 개명 후 "불암산" 날짜가 당고개로 이어짐), 혼잡도 미연결 36 → 30행/분기(2호선 까치산 지선 6행 연결), 시간대·유형 역 수·행 수 불변, 원본 유형 합계 `rawTypeTotals` 불변. 시간대·승객유형·혼잡도에서 6호선 34개 역의 값이 이웃 역 값으로 교체됐다.

## 9. 미확인

- 좌표 파일과 원본 3종 중 어느 쪽 외부역코드가 실제 코드인지는 확정하지 못했다(원본 3종이 서로 일치해 좌표 파일 오류 가능성이 높다). 서울교통공사 확인 또는 다른 근거가 필요하다.
- 이름 기준 연결이 안 되는 역: 7호선 부천 구간 7역·8호선 암사역사공원(좌표 파일에 없음). 동작(4호선)은 두 원본이 서로 31% 다른 값을 가진다(원본 차이, 이번 수정 범위 밖).
- 전체화면·키보드 전 보기 순회·인쇄·태블릿·모바일, 공개 화면은 보지 않았다. 지도 점 색 대비는 측정하지 않았다.
- B7의 "같은 이름" 표시는 일별 원본의 이름 일치 기준이라 환승 실제 여부(걸어서 갈 수 있는지)와 다를 수 있다.
