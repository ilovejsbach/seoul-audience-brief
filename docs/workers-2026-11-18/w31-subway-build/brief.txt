단계 (단계마다 체크포인트 보고)

1단계: 자료 수집
- 인증키 없이 받을 수 있는 공식 파일만 받는다.
  - API 키가 필요하면 그 자료는 멈추고 신청 경로만 기록한다.
  - 로그인과 유료 결제는 금지다.
- 대상
  a. 역별 일별 승하차(OA-12914): 최근 24개월 이상. 계절 비교용이다.
  b. 역별 시간대 승하차(OA-12252, 월별, 전 노선): 받을 수 있는 최대 기간. 계절 비교에 최소 2~3년이 필요하다.
  c. 역별·일·시간·승객유형 승하차(data.go.kr 15099330, 1~8호선): 최근 1~2개 반기
  d. 혼잡도(OA-12928, 1~8호선 30분 단위): 최신본
     - 9호선 혼잡(OA-22197)은 키 없이 받을 수 있으면 받는다.
  e. 역 위치 좌표(15099316 등). 전 노선 좌표를 확보할 수 있는지 확인한다.
  f. OA-21222 정류장/역사별 수단 출발/도착
     - 표본 1개월만 받는다.
     - 지하철 역 OD로 쓸 수 있는지 검증만 한다: 수단 코드, 환승 처리, 역 코드 대응.
- 각 파일은 MANIFEST.json에 추가한다. 적을 항목: URL, 받은 시각, SHA256, 바이트, 자료 ID, 기간.
- 수집 스크립트는 scripts/collect-subway.py로 둔다. 다시 실행해도 기존 원본을 덮어쓰지 않아야 한다.
- 외부 요청 허용 범위
  - data.seoul.go.kr, datafile.seoul.go.kr, data.go.kr, file.go.kr, seoulmetro.co.kr 및 그 공식 다운로드 경로
  - 그 밖의 사이트는 접근하지 않는다.

2단계: 준비·검증
- scripts/prepare-subway.py로 원본에서 public/data/transit/subway/ 파일을 만든다.
  - 역 마스터: 역 코드, 이름, 호선, 좌표, 행정동 연결
    - 환승역은 호선별 행과 역 단위 합계를 구분한다.
    - 이름만으로 병합하지 않는다.
  - 시간대: 역×시간×월. 평일·주말 구분이 가능하면 구분한다.
  - 일별: 역×일. 달력과 요일에 쓴다.
  - 월별·계절: 계절 정의(봄 3–5, 여름 6–8, 가을 9–11, 겨울 12–2)를 적고, 연도별로 비교한다.
  - 승객 유형: 일반 / 청소년 / 우대 / 기타
  - 혼잡도: 승하차와 다른 지표로 분리한다. 단위는 정원 대비 %다.
  - OD: 1단계 검증을 통과한 경우에만 만든다. 통과하지 못하면 화면에 "준비 중"으로 표시한다.
- 용량 한도
  - 지하철 전체 30MB 이하, 파일 하나 10MB 이하를 목표로 한다.
  - 기존 방식대로 큰 파일은 .gz로 둔다.
  - 질의 단위로 분할한다(w25 B안).
  - manifest를 둔다(w25 4.1 형식). 필수 항목: id, 기간, 단위, nullMeaning, 출처, 라이선스, 해시.
- 데이터 원칙
  - 원본은 바꾸지 않는다.
  - null을 0으로 채우지 않는다. 결측은 null이고, null이 섞인 합계도 null이다.
  - 승하차는 고유 방문자 수가 아니다.
  - 혼잡도는 광고 노출이 아니다.
- scripts/validate-subway.py와 단위 시험을 만든다.
  - 원본 행에서 독립 재계산해 3개 이상을 대조한다: 역 하루 합, 환승역, 시간대 합.
  - 결측 처리와 행 수를 기록한다.
- 체크포인트: 자료 표와 검증 결과를 REPORT.md 초안에 쓰고 "W31 DATA DONE"을 출력한다. 감독자의 확인을 기다리지 않고 3단계로 계속 간다.

3단계: 화면
- 디자인과 배치 원칙은 모두 기존 프로젝트를 따른다. 새 스타일 체계를 만들지 않는다.
  - DASHBOARD_DEVELOPMENT_RULES
    - 글자 크기 종류: 분석 6종, 시연 4종
    - 대비 4.5:1
    - 같은 위계 요소는 같은 크기
    - 조회 조건 / 표시 설정 / 상세 / 출처의 역할 구분
  - 기존 CSS 토큰과 컴포넌트를 재사용한다: 지도, 범례, 조회 바, 상세 팝업↔본문, 후보, CSV, 출처.
  - w20 목업 배치를 따른다.
    - 중앙: 한 줄 조회 바 + 지도
    - 좌측: 보기
    - 우측: 선택 역, 핵심 지표, 후보
- 코드 구조
  - 새 파일 위주로 만든다: src/topics/transit/ 아래 SubwayWorkspace 등
  - 데이터는 접근 계층 하나로만 읽는다. 화면 코드가 파일 경로를 직접 알지 않게 한다.
  - 메인과 겹치는 파일(main.tsx 등) 수정은 최소한의 연결 지점 하나로 제한한다.
- 보기 구성
  - 지도: 역 점. 크기·색은 선택 지표를 따른다.
  - 시간대 곡선
  - 일별 달력과 요일
  - 월별·계절 비교
  - 승객 유형(일반/청소년/우대/기타)
  - 혼잡도. 별도 보기이고 단위를 명시한다.
  - OD. 가능할 때만 만든다.
  - 성별은 "자료 없음"으로 둔다.
- 조회 조건: 기간, 역(검색), 호선, 평일/주말, 승차/하차
- 진입
  - 메인에서 1b(상단 주제 메뉴)가 반영되면 "교통" 메뉴에 연결한다.
  - 그 전에는 네 트리에서만 쓰는 임시 진입점(예: ?topic=subway)으로 개발한다.
- 시연용·분석용 모드 처리는 지역 분석 규칙을 따를지 판단해 REPORT에 근거를 적는다. 기본은 지역 분석처럼 두 모드를 지원하는 것이다.
