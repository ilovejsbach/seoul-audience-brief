할 일
1. 후보 자료를 조사한다. 공식 출처만 쓴다.
   - 서울 열린데이터광장(data.seoul.go.kr)
     - 지하철 호선별·역별·시간대별 승하차 인원
     - 역별 일별 승하차
     - 지하철 혼잡도
     - 역 위치·좌표
     - 역 출구 정보
   - 공공데이터포털(data.go.kr)
     - 서울교통공사 혼잡도(30분 단위 칸 혼잡도)
     - 역별 승하차
     - 연령·성별 이용 현황(우대권·청소년 등 권종별 자료 포함)
     - 역간 OD 자료가 있는지
   - 서울교통공사·국가교통DB(KTDB)·한국교통안전공단 교통카드 빅데이터 등에서 OD(출발역→도착역) 자료가 공개되는지, 신청형인지, 유료인지, 비공개인지
   - 서울 생활이동(OA-22300)처럼 지하철 이동을 간접적으로 볼 수 있는 기존 자료와의 관계
2. 자료마다 아래 표를 채운다.
   - 자료명, 출처 URL, 제공 기관
   - 공간 단위(역/호선/출구)
   - 시간 단위(시간대/일/월)
   - 제공 기간과 갱신 주기
   - 성별·연령 제공 여부와 그 정의. 권종 기반인지, 추정인지 구분한다.
   - 혼잡도 정의. 칸 혼잡도 %인지, 승하차 인원인지 구분한다.
   - OD 여부
   - 파일 형식, 행 수, 용량, API 제한
   - 라이선스(공공누리 유형, 상업 이용 가능 여부)
   - 인증키 필요 여부
   - 확인 날짜
   - 확인하지 못한 항목은 "미확인"으로 표시한다.
3. 실제 표본 확보
   - 인증키 없이 받을 수 있는 공식 파일은 1~2개 기간만 내려받는다. 예: 최근 1개월 역별·시간대별 승하차, 혼잡도 파일.
   - 받은 파일은 data/raw/transit/subway/ 에 저장한다.
   - 파일마다 manifest를 남긴다: URL, 받은 시각, SHA256, 바이트.
   - 인증키가 필요한 API는 호출하지 않는다. 키가 필요하다는 사실과 신청 경로만 기록한다.
   - 대용량 전체 기간 다운로드는 하지 않는다. 표본만 받는다.
4. 요구별 가능성 판정
   - 판정 기준: 가능 / 조건부 가능 / 불가 / 미확인
   - 근거와 대안을 함께 적는다.
   - 판정할 요구
     a. 역별 시간대별 승하차(유동인구)
     b. 일별
     c. 월별
     d. 계절별. 월별 자료를 계절로 묶어도 되는지, 기간이 몇 년치 필요한지 판단한다.
     e. 혼잡도. 칸 혼잡도와 승하차 인원은 다른 지표이니 구분한다.
     f. 연령별
     g. 성별
     h. 출발역→도착역 OD
     i. 역 위치(지도 점), 그리고 행정동·상권과의 연결 가능성
   - 표본 파일로 직접 확인한다.
     - 실제 컬럼 구조
     - 결측
     - 역 이름과 코드의 일관성(환승역, 호선별 중복 등)
     - 단위
   - 원문 행과 집계를 2~3개 직접 대조해 보고한다.
5. 분석 설계 초안
   - 가능한 범위 안에서 지하철 주제의 질문 → 지표 → 화면(지도 점, 시간대 곡선, 달력, 계절 비교, 연령·성별, OD)을 정리한다.
   - w20 목업 레이아웃(상단 주제 / 좌측 자료·보기 / 중앙 / 우측) 안에 넣는 방식으로 정리한다.
   - 데이터 규모를 추정한다: 역 수 × 시간대 × 기간. 정적 배포 한도(사이트 1GB, 파일 100MiB) 안에서 필요한 사전 집계와 분할 방식도 적는다.
   - 해석 주의점을 적는다.
     - 승하차 ≠ 고유 방문자
     - 환승 인원 포함·제외 여부
     - 혼잡도 ≠ 광고 노출
