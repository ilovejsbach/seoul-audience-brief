작업 w34: 지하철 화면을 1b 공통 셸에 연결 (w31 후속)

담당: 지하철 전담 작업자(같은 창, 같은 트리 /Users/koscom/workspace2/seoul-human-subway, 브랜치 transit-subway)

배경
- 메인 main에 레이아웃 1b가 커밋·배포되었다(76e22b6).
  - 공통 상단 주제 메뉴: AppShell, service-registry, MoreMenu
  - 새 히어로
  - 교통은 현재 "예정(비활성)"이다.
- 네 w31 화면은 자체 상단 바(주제 4개, 분석용/시연용, 더보기)를 만들었다. 이 바는 1b 공통 셸과 중복된다.

할 일
1. main(76e22b6)을 네 브랜치에 가져온다. rebase 또는 merge 중 충돌이 적은 쪽을 고르고, 충돌 해결 내용을 REPORT에 적는다.
   - 메인 트리의 작업 디렉터리 파일은 건드리지 않는다.
   - git fetch는 필요 없다. 같은 저장소라 main 참조를 바로 쓸 수 있다.
2. 공통 셸에 연결한다.
   - service-registry에서 교통을 활성으로 바꾸고, 진입 대상을 지하철 작업공간으로 한다.
   - 지하철 화면의 자체 상단 바를 없애고 AppShell 상단 메뉴를 쓴다.
   - 분석용/시연용 처리
     - 1b는 모드 전환을 지역 분석에서만 보이게 했다.
     - 교통은 두 모드를 지원한다.
     - 교통 화면에서도 상단의 모드 전환이 보이게 한다.
     - 모드 상태를 지역과 같이 쓸지 따로 쓸지 판단하고 근거를 적는다. 기본은 지역과 같은 mode 상태를 공유하는 것이다. 단, 상권 비상속(I04, REQ-23)은 깨지면 안 된다.
   - 임시 진입 ?topic=subway를 없앤다. 히어로에 버튼을 추가하지 않는다. 상단 "교통" 메뉴로만 들어간다.
   - 서비스를 왕복해도(교통↔지역↔상권↔히어로) 지하철 조건, 선택 역, 후보가 유지되어야 한다.
   - 상단 메뉴 라벨: "교통" (예정 표시 제거). 하위 자료는 좌측에서 "지하철"을 기본으로 한다. 버스는 좌측에 비활성 "버스(예정)" 항목으로 둔다.
3. 테스트
   - 1b의 기존 E2E 중 "교통(예정) 비활성"을 기대하는 검사는 새 동작에 맞게 바꾼다. 삭제나 skip은 하지 않는다.
   - 지하철 여정의 진입을 상단 메뉴로 바꾼다.
   - I04 양방향 검사가 계속 통과해야 한다. 여기에 교통 경유 왕복도 추가한다.
4. G 관문 (포트 4197)
   - npm run build
   - node --test tests/*.test.mjs
   - python3 scripts/validate-data.py
   - python3 scripts/validate-subway.py
   - E2E_PORT=4197 PLAYWRIGHT_EVIDENCE_DIR=<w34 폴더>/e2e npm run test:e2e -- --project=desktop-1365 --project=desktop-1920
