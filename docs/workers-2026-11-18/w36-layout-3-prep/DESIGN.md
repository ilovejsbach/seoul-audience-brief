## 0. 한눈에 보는 결론 (쉬운 말)

1. **지금 오른쪽 패널은 "지도 옆 칸"이다.** 지도와 순위는 `.workspace`라는 한 상자 안에 나란히 있고, 폭은 **비율(75:25)과 최소 280px**로 정해진다. 그래서 새 기본(오른쪽 300px 고정, 접으면 0)과 곧바로 맞지 않는다. 또 **같은 오른쪽 폭이 세 군데에서 따로 빠진다**(아래 1-3절).
2. **831px을 얻으려면 오른쪽 패널을 `.workspace` 밖(셸의 세 번째 칸)으로 빼야 한다.** 지금도 폭 827px(오른쪽 약 282px)인데, 300px로 늘리면 그대로는 약 809px로 **오히려 줄어든다**. 현재 지도 주변 여백(메인 12px, 분석 화면 8px, 칸 사이 18px, 지도 안 8+8px)이 계획서 식(중앙 패딩 32 + 경계 2)보다 많기 때문이다. 폭은 셸 격자 한 곳에서만 계산하고 다른 곳은 빼지 않게 한다.
3. **두 가지를 섞지 않는다.** "접기"는 패널을 0px로 접는 것(기존 `secondary-mode=hidden`과 같은 뜻), "최소화"는 떠 있는 고급 창을 줄이는 것(기존 `supportMinimized`)이다. 후보 최대 3곳·순위 선택·해제·출처 기능은 그대로 두고 **자리만 오른쪽 패널로 모은다.** 고급 비율·도킹은 더보기에 남기되 기본 300px과 충돌하지 않게 "비율을 직접 켰을 때만" 적용한다.

## 2. 목표 오른쪽 패널(300 / 접힘 0)과 셸 한 곳의 폭 계산

### 2-1. 구조

2단계 `regionBody`(왼쪽 메뉴 + `analysisView`)를 **세 칸 격자**로 만든다.

```
.regionBody { grid-template-columns: var(--left-nav-width) minmax(0,1fr) var(--right-panel-width) }
   └ 1칸 WorkspaceNav (200 | 64)        ← 2단계, 이미 있음
   └ 2칸 .analysisView (조회 바 + 결과)   ← 중앙
   └ 3칸 #regionSupportHost (300 | 0)    ← 새 칸. 안에 보조 패널
```

- 폭 변수 두 개(`--left-nav-width`, `--right-panel-width`)는 `regionBody`의 `data-*`로만 정해지고, **이 격자가 유일한 폭 계산 장소**다. 나머지 파일은 그 폭을 빼지 않는다.
- **패널을 3칸으로 옮기는 방법 = 포털.** 지금 패널은 자료마다 `.workspace` 안에 있다(생활인구 `main.tsx:184`, 나머지는 `ExtraDashboard` 인스턴스마다). 자료별 컴포넌트는 숨김 처리로 계속 마운트되어 있으므로(2단계 방식 유지) **활성 자료의 패널만** `createPortal(패널, #regionSupportHost)`로 3칸에 그린다(`active={view==='analysis'&&tab===kind}`일 때). 상태(후보 `compare`, 선택 지역)는 지금처럼 각 소유자에 두므로 이동으로 초기화되지 않는다. `RankingDisclosure`의 펼침 상태는 window 이벤트 기반이라 영향이 적다.
- `.workspace`는 지도 한 칸짜리(`grid-template-columns:minmax(0,1fr)`)가 되어 ①의 비율 규칙과 ④·⑤는 **고급 도킹 모드에서만** 남는다(`data-ranking-dock` 속성이 있을 때만 적용되도록 범위 좁힘).
- 접기 상태 `rightOpen`은 `App`의 한 불리언(기본 true). 닫으면 `--right-panel-width:0`, 호스트 `visibility:hidden`(초점 불가), 패널은 마운트 유지(상태 보존).
- **다시 열기 버튼의 자리:** 닫혀도 보여야 하므로 모든 자료가 공유하는 `UnifiedMapPanel`의 도구 줄(`.mapPanelTools`, 전체화면 버튼 옆)에 "‹ 보조정보 보기 / 보조정보 접기 ›"를 둔다(목업의 `auxToggle` 위치와 같은 취지). 패널 안에도 접기 버튼을 둔다. 둘 다 같은 상태를 쓴다.

## 3. 접기와 최소화, 다시 열기, 후보·순위

### 3-1. 용어와 상태(서로 독립)

| 상태 | 의미 | 위치 | 영향 |
|---|---|---|---|
| **접기** `rightOpen=false` | 오른쪽 칸 0px | `App` | 지도가 넓어짐. 패널·후보·순위 상태는 보존. 닫은 채 서비스 이동·자료 전환·상세 왕복해도 유지 |
| **최소화**(기존 `supportMinimized`) | **떠 있는 고급 창**의 내용만 접음 | `DockableRanking` | 접기와 무관. 기본(오른쪽 칸) 패널에는 최소화가 없고 접기만 있다 |
| 순위 펼침 `secondary-mode=expanded` | 순위 5개 ↔ 전체 | 기존 이벤트 | 그대로 |

- 기존 이벤트 `secondary-mode`는 호환을 위해 유지한다: `hidden` 수신 → `rightOpen=false`, `summary`/`expanded` 수신 → 열기. 즉 "보조 정보 접기" 버튼(`RankingDisclosure`)과 더보기의 "보조 정보 다시 보기"가 새 상태를 그대로 구동한다(기능 소실 없음).
- 키보드: 접기 버튼은 Enter/Space. **Esc로는 접지 않는다**(2단계 왼쪽 메뉴와 같은 원칙, R15). 접은 뒤 초점은 열기 버튼으로, 다시 열면 패널의 접기 버튼으로 돌려놓는다.

### 3-2. 패널 구성(위→아래, 300px)

w20 목업의 순서를 따르되 기존 기능을 보존한다.

1. **선택 대상:** 이름 + `날짜·시각·연령·성별` 한 줄(기존 `linkedMetricHeading`).
2. **핵심 지표:** 큰 값 1개 + "비교 지표" 접힘(기존 `selectedRegionInsights` 그대로). 긴 값(매출 14자리)은 줄바꿈 없이 축약+정확값 툴팁(R20).
3. **후보(최대 3곳):** `후보 n / 3`, 슬롯 3행(이름·값·`×`), "선택 대상 후보 담기" 버튼, "후보 비교 열기"(= `shortlist-*` 상세). 같은 `compare` 상태를 쓴다.
4. **순위:** 기존 `rankList`(5행 요약, "전체 순위 보기"로 전체), 행의 지역명 클릭 = 선택, `+/✓` = 후보 토글. 지금은 맨 위에 있지만 후보 아래로 내리고, 접힌 목록으로도 계속 접근 가능해야 한다(계획서 2절).
5. **해석·출처 요약:** 한두 줄 + "출처·해석 보기"(기존 `populationSourceInfo`/`sourceDetails`를 여는 버튼). 단위·기간·결측 주의는 결과 근처에 유지.

### 3-3. 후보 규칙(상태·동작은 현행 유지, 표시만 모음)

- **최대 3곳:** 상태 변경은 `toggleCompare`(`main.tsx:117`)·`shortlist`(`ExtraDashboard`)가 이미 3개 제한. **4번째:** 순위의 `+` 버튼은 이미 `disabled`(`compare.length>=3`); 새 "후보 담기" 버튼도 같은 조건으로 비활성하고 문구를 "최대 3곳 선택됨"으로 바꾼다(목업과 동일, 조용한 무시 금지).
- **중복 금지:** 이미 담긴 대상은 "후보에 담김"(비활성)으로 표시.
- **해제:** 각 행 `×`와 순위의 `✓` 클릭 둘 다. 해제 뒤 초점은 같은 위치의 다음 행(없으면 후보 담기 버튼).
- **0후보 복구:** 후보가 0개면 슬롯 3개는 "선택 전"(목업) + "지역을 눌러 담으세요" 안내를 보이고 "후보 비교 열기"는 비활성. 후보 상세(`shortlist-*`)에서 모두 해제해도 빈 상태 안내로 복귀 가능(현행 유지).
- **구·동 혼합:** 후보 코드는 5자리(구)·8자리(동)가 섞일 수 있다(현행). 값 표시는 코드별 `candidatePopulation`/`candidateRecord`를 그대로 쓴다.
- **지도 안 후보 막대(`MapCandidateTray`):** 오른쪽 패널이 열려 있으면 중복이므로 **전체화면일 때만** 표시한다(계획서 2절: "전체화면에서는 지도 안 후보 수·해제·열기 경로 유지"). 렌더 조건으로 처리해 숨은 중복 DOM을 만들지 않는다. 오른쪽을 접으면 지도 안 막대를 다시 보이게 할지는 결정 사항 5.
- **서비스 이동·접기·다시 열기 후 후보 유지:** 상태 소유자가 `App`/`ExtraDashboard`(숨김 유지)라 변하지 않는다. N05로 검사.

### 3-4. 순위 선택

지역명 클릭은 지금처럼 `selectPopulationRegion`/`selectRegion`을 호출(지도 선택·상세 이동 규칙 불변). 선택된 행은 `isSelected` 강조(색 외 굵기·막대). 키보드: 행의 두 버튼(이름, `+`)이 각각 Tab 정거장. 순위 행 수가 많아 패널이 길면 **순위 목록만** 내부 스크롤(패널 자체는 고정 높이).

## 4. 고급 비율·도킹·투명도와 새 기본값의 공존 (사용자 결정 b)

### 4-1. 원칙

- **기본:** 왼쪽 200/64, 오른쪽 300/0. 사용자가 아무것도 건드리지 않으면 이 값만 쓴다.
- **고급 기능은 명시적으로 열었을 때만 적용**하고 셸 격자 한 곳에서 계산한다. 더보기 메뉴의 "화면 배치"(`LayoutControls`) 안에 있다(1b 결과).

### 4-2. 각 기능의 처리

| 기능 | 현재 | 3단계 처리 |
|---|---|---|
| 지도/보조 비율 프리셋(67/75/55)·슬라이더 55–85·방향키 | `LayoutControls`, `WorkspaceSplitHandle`이 `.workspace` 안 비율을 바꿈 | **직접 비율 상태 `ratioShare: number\|null`** (기본 null = 300px). 값이 있으면 셸이 `오른쪽 = clamp(round((중앙+오른쪽) × (100−share)/100), 280, 480)`로 `--right-panel-width`를 계산(단, 중앙 칸 ≥ 540 보장). 손잡이는 중앙/오른쪽 경계(셸 칸 사이)에 둔다 |
| **"기본 배치 복원"** | 없음(새) | `ratioShare=null`, `rightOpen=true`, 왼쪽 메뉴 열기(**200/300**). 떠 있는 창·도킹은 그대로 |
| **"고급 비율 초기화"** | 슬라이더를 75%로 되돌림 | `ratioShare`를 **끈다(null → 300px)**. 문구를 "고급 비율 끄기(기본 300px로)"로 바꿔 두 이름이 같은 일을 하지 않게 한다. 기존 "초기 75%"는 옛 기본이므로 새 기본(300)과 혼동되어 제거(결정 사항 3) |
| 순위 창 도킹(왼쪽/오른쪽 붙이기)·떼어내기·투명도·너비 | `DockableRanking`(자료 3개). 붙이면 `.workspace` 안 `supportRankingMount` | **보존.** 기본(`default`) 모드는 오른쪽 칸 패널이고, 사용자가 "왼쪽에 붙이기/오른쪽에 붙이기/떼어내기"를 고르면 기존처럼 `.workspace` 안/떠 있는 창이 된다. 이때 오른쪽 칸 패널은 비우지 않고 "순위 창이 분리되어 있습니다 · 다시 붙이기" 안내만 둔다(칸이 비어 보이지 않게). 540px 안전선(`fits`)은 이 고급 모드에서만 적용 |
| 조회 바 우측 도킹(540px 안전선) | `UnifiedQueryBar.tsx:42–48` | 판단식을 **오른쪽 칸을 따로 빼지 않도록 수정**(이중 차감 ②). `ranking` 항은 고급 순위 도킹(`.workspace` 안)일 때만 유지하고 기본 패널은 0으로 둔다 |
| 생활인구에 도킹 없음 | — | 결정 사항 2에 따름 |

### 4-3. 저장값 version

지금 레이아웃 조절값은 **저장되지 않는다**(React 상태, 새로고침 시 초기화). 저장되는 것은 지도 팔레트(`MapPaletteSelector`의 `localStorage`)뿐이다. 따라서:
- 3단계는 **새 저장을 추가하지 않는 것을 권고**(탭 세션 중 유지만, 계획서 3절 "새로고침 후 복원 없음"과 일치).
- 나중에 저장을 넣게 되면 키를 `seoul-layout-v2`처럼 분리하고, 이해하지 못하는 옛 geometry(`v1` 또는 키 없음)는 기본 300/200으로만 되돌리고 조회 조건·후보·선택은 건드리지 않는다.

## 5. 831px 관문 측정 방법

### 5-1. 합격 기준(계획서 6절 그대로, 읽을 수 있는지가 핵심)

폭은 `documentElement.clientWidth`와 실제 rect로 재계산한다(±1px). 831이라는 숫자는 목업 근거이고 **실제 읽기 판정은 아래 항목의 사람 확인 + 측정**으로 한다. 실패하면 양쪽 열림 기본 배치를 합격으로 배포하지 않는다(도구·축 간격·중복 행·내부 스크롤 조정 후 재검사, 폭 변경이 필요하면 실패 화면·측정과 대안을 사용자에게 제시).

| 항목 | 기준 |
|---|---|
| 지도 | 구 25 라벨 전부 보임(자치구 지도), 선택 구의 동 라벨·긴 이름 보임, 라벨끼리·범례·도구에 가려지지 않음. 충돌은 코드·이름·쌍·화면 좌표를 기록 |
| 범례 | 막대·버튼 크기가 읽히고 값·단위·끝 색 의미 툴팁이 잘리지 않음 |
| 그래프 축 | 추이(24시간/연도/분기)·분포 2지도·긴 14자리 매출·음수/0/null의 축 눈금·단위가 잘리지 않음, plot 폭>0 |
| 글자 | R07 분석 6종/시연 4종 한도 그대로, **폭을 맞추려 글자를 줄이지 않음** |
| 첫 화면 | 1365×768에서 지도·범례·필수 주의가 스크롤 없이 함께 보임(2단계 483px 기준 유지) |

### 5-2. 측정 스크립트 설계(구현 단계에서 `tests/e2e` 또는 이 단계 폴더 스크립트로)

1. **여백 분해표(착수 직후 1회):** 지도 `svg` 폭, `.mapWrap` 폭, `.mapPanel` 폭과 테두리, `analysisView` 폭·패딩, `main` 패딩, 3칸 폭을 한 번에 읽어 "중앙 칸 폭 − svg 폭"을 항목별로 기록한다. 목표: 합계 = 34(패딩 32 + 경계 2). 아니면 A(여백 제거) 또는 B(식 수정)를 선택.
2. **좌우 4상태 × (1365, 1920) × (분석, 시연):** 각 상태에서 `regionBody` 칸 폭, 중앙 칸, svg 폭을 기록하고 기대값 표(2-2절)와 ±1px 비교. 접힘은 버튼으로 만든 뒤 측정(키보드 조작 경로 포함).
3. **지도 라벨 충돌:** 활성 지도 `svg`의 `text` 라벨 bbox(`getBBox`+`getScreenCTM`)를 구해 서로·범례·도구와 겹침 여부를 계산. 겹침은 실패 목록에 코드·이름·쌍·좌표로 남기고 스크린샷 저장. 흰 윤곽만으로 통과시키지 않음. 필수 라벨(구 25)이 가려졌는지 화면 캡처와 대조.
4. **글자 크기 집합:** 기존 `fonts()` 함수 재사용(SVG `getScreenCTM` 배율 포함). 4상태에서 6종/4종 이하.
5. **그래프:** 대표 상세(생활인구 추이·분포, 매출 14자리 추이)를 본문으로 열어 plot 폭·축 `fits`를 기록. 본문 상세가 열려 있을 때 오른쪽 칸 유무에 따른 폭 변화(결정 사항 4).
6. **산출:** 상태별 JSON(rect·여백표·라벨 충돌 목록) + 스크린샷, 사람이 읽기 판정을 별도 칸에 기록("측정 통과"와 "읽기 합격" 구분).

### 7-2. 위험

1. **포털과 숨김 자료:** 자료별 컴포넌트가 숨김 상태로 계속 마운트되므로 포털을 **활성일 때만** 그려야 한다. 아니면 네 개 패널이 한 칸에 겹친다. 활성 판정(`view==='analysis'&&tab===kind`)과 전체화면·본문 상세 때 가림 규칙을 정확히 한다.
2. **`FloatingQueryLayer`:** 떠 있는 순위 창은 `.app` 클래스·변수를 복제한다(`FloatingQueryLayer.tsx:15–34`). 기본 모드가 포털로 바뀌어도 고급 떠 있기 경로는 그대로여야 한다. 상권은 1b의 파생 클래스를 쓰므로 영향 없음(확인 필요).
3. **여백 합계(⑨):** 831은 식 맞춤 여백 제거가 선행되어야 한다. 제거 때 지도 도구·제목·범례 위치가 틀어질 수 있다(1b·2단계에서 이미 여러 번 조정).
4. **300px 안의 긴 내용:** 매출 14자리·긴 지역명·음수. `displayNumber`/정확값 툴팁 정책 유지, 줄바꿈은 허용하되 말줄임으로 뜻을 숨기지 않는다.
5. **툴팁·팝오버의 가장자리:** 오른쪽 칸 안의 `DataMeaning`·검색 팝오버가 칸 밖(왼쪽)으로 열려야 하고 화면 밖으로 나가지 않아야 한다.
6. **본문 상세 폭 감소:** 오른쪽 칸이 항상 있으면 본문 상세(추이 그래프)가 300px 줄어든다. 1365에서 `중앙 865 − 32` 정도이므로 축 잘림 검사가 필요(결정 사항 4).
7. **높이:** 패널은 칸 높이 100%이고 내용은 순위 목록만 스크롤. 1365×768에서 KPI+후보 3행+순위+출처가 들어가는지 측정(약 560–620px 예상, 실측 필요).
8. **인쇄:** 오른쪽 칸을 인쇄 때 어떻게 할지 현재 `print.css`는 `.workspace`/`.ranking`을 가정한다. 칸이 `display:none`/접힘이어도 필요한 출처·조건·결과가 인쇄되어야 한다(R20). 인쇄 전 열기/후 복원 로직(`main.tsx` `beforeprint`) 확인.
9. **1b·2단계와의 충돌:** `main.tsx`의 `regionBody`·`analysisView` 구역과 같은 곳이다. 2단계가 커밋된 뒤에 시작한다. 지하철 브랜치가 `main.tsx` 헤더/본문을 건드리므로 병합 충돌 가능(구역 최소화).
10. **미확인(이번 조사의 한계):** `analysis-detail-modal.css`·`map-workspace-shell.css`·`print.css`·`full-screen-fixes.css` 전체는 읽지 않았다. `MapPanel.tsx`(옵션 창 도킹)·`Navigation.tsx`의 팝업 도킹(`data-popup-dock`)이 오른쪽 칸과 어떻게 겹치는지는 구현 때 확인한다. 실제 화면·측정은 하지 않았다.
