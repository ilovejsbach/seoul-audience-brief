### 1-3. 등록부 필드(제안)


## 3. 왼쪽 메뉴 상태 설계

1b가 만든 `AppShell`(상태 없는 껍데기)과 `App`의 상태 소유 방식 위에 얹는다. 왼쪽 메뉴는 **지역 서비스 안의 한 컴포넌트**(`WorkspaceNav`)이고 상태는 `App`에 둔다(조건·후보와 같은 수명, 서비스 왕복에도 유지 — w28 DESIGN 2절 규칙 그대로).

### 3-1. 폭과 접힘

| 상태 | 폭 | 보이는 것 |
|---|---|---|
| 열림(기본) | **200px** | 머리줄(제목 "자료와 분석" + 접기 버튼), 자료 4개(전체 이름), 보기 그룹(지도 + 상세 8/6/6/5개, 전체 이름) |
| 접힘 | **64px** | 접기/펼치기 버튼, 자료·보기 항목을 **짧은 이름**(2글자)으로, 현재 항목 표시 |

- 경계선은 패널 폭에 포함(계획서 6절). 중앙 폭 계산은 셸 한 곳에서 한다(1b의 `--app-header-height`처럼 `--left-nav-width` 변수를 셸이 설정). 기존 내부 280px·비율 CSS가 왼쪽 폭을 이중으로 빼지 않게 확인한다. **3단계 전까지 오른쪽은 기존 구조 그대로이므로 지도 폭 기대치는 `viewport − 왼쪽`까지만 검증하고, 최종 831px 규칙은 3단계 몫이다**(계획서 N04).
- 접기 버튼은 머리줄에 둔다(목업 `sideHead` 방식). `aria-expanded`, 이름 "왼쪽 메뉴 접기/펼치기".

### 3-2. 기본값과 시연 규칙 (사용자 결정 a)

| 상황 | 동작 |
|---|---|
| 분석용 진입 | 열림 |
| **시연용에 처음 들어갈 때** | 접힘(한 번만) |
| 그 뒤 | 사용자가 펴거나 접은 상태를 그대로 유지 |

구현 방식 제안(둘 중 선택은 결정 사항 1): **모드별로 두 개의 상태**를 둔다 — `leftOpen.analysis`(초기 true), `leftOpen.presentation`(초기 false). 시연용으로 전환하면 시연용 상태를 쓰고, 분석용으로 돌아오면 분석용 상태를 쓴다. 이러면 "처음에만 접고 이후는 사용자 선택 유지"가 별도 플래그 없이 정확히 성립하고, 모드를 오가도 각 모드의 선택이 보존된다. 대안(상태 하나 + "시연 첫 진입 적용됨" 플래그)은 사용자가 분석용에서 접어 둔 것이 시연용에서도 접혀 있는 효과가 생기지만, 반대(분석용에서 열어 둔 채 시연용으로 가면 접힘으로 강제)도 생겨 규칙이 더 복잡하다.

- 서비스·히어로 왕복, 자료 전환, 상세 팝업↔본문, 전체화면 진입·종료는 이 상태를 바꾸지 않는다.
- 새로고침 후 복원은 하지 않는다(목업·이어보기와 동일, 탭 세션 중 유지만).
- 상권에는 모드가 없으므로 지역의 모드별 상태와 무관하다(4단계에서 상권 전용 한 상태).

### 3-3. 키보드

| 키 | 동작(제안) |
|---|---|
| Tab / Shift+Tab | 메뉴 안에서는 **그룹마다 한 정거장**: 접기 버튼 → 자료 그룹(현재 자료) → 보기 그룹(현재 보기) → 메뉴 밖. 롤링 탭인덱스(현재 항목만 tabindex 0) |
| ↑ / ↓ | 같은 그룹 안에서 이전/다음 항목으로 **초점만** 이동(활성화 아님). Home/End는 처음/끝 |
| Enter / Space | 초점 항목 **활성화**(자료 전환·지도·상세 열기·접기 토글) |
| Esc | 메뉴 안에서는 열린 설명 툴팁이 있으면 그것만 닫음. **메뉴 접기는 하지 않는다.** 이유: R15의 "Esc 한 번에 한 층"과 `UnifiedMapPanel.tsx:17`, `AnalysisDetailModal.tsx:105`의 기존 Esc 규칙과 충돌 방지. 접기는 접기 버튼으로만 |
| 포커스 링 | `analysis-navigation.css:13`의 `outline:2px solid #b75a1b;offset:2px` 재사용. 접힌 64px에서도 잘리지 않게 `outline-offset`을 안쪽(0)으로 줄이는지는 구현 때 실화면 확인 |

- 화살표로 초점을 옮기는 동안 상세 창을 열지 않는다(수동 활성화). 25개를 훑으며 지나갈 때 모달이 연속으로 열리는 사고를 막는다.
- 상세 팝업이 열려 있는 동안 왼쪽 메뉴는 `<dialog>`의 모달성(`showModal`) 때문에 **자동으로 비활성(inert)**이다(`AnalysisDetailModal.tsx:102`). 이 상태에서 상세를 바꾸는 길은 팝업 헤더의 콤보(`DetailNavigationControl`)다. 본문에서 보기 상태에서는 왼쪽 메뉴가 활성이고 콤보도 있다. 이 구분은 의도된 동작(REQ-07·08)이며 테스트에 명시한다.

### 3-4. 접힌 64px에서 이름과 초점에 접근하는 방법

1. **짧은 이름 + 전체 이름 이중 제공:** 보이는 글자는 2글자(`인구/이동/전입/매출`, 상세는 목업의 `요일·거주·대상·추이·시간·분포·후보·조건` 등). 접근성 이름(`aria-label`)과 `title`은 항상 **전체 이름**(예: "행정동 추정매출", "두 분기 비교"). 열림/접힘에 상관없이 같은 `aria-label`이므로 스크린리더 안내는 바뀌지 않는다.
2. **초점 시 이름 보이기:** 접힌 상태에서 항목에 키보드 초점이 오면 항목 오른쪽에 전체 이름을 가진 작은 안내(툴팁형, `position:absolute`, 메뉴 밖으로 나오되 뷰포트 안)가 뜬다. 마우스 hover도 같다. 이것은 "무거운 창"이 아니라 `focus-visible`/`hover` CSS만으로 만든다(별도 상태·포털 없음). 지도·그래프 위로 올라오지만 내용을 가리는 시간은 초점이 머무는 동안뿐이다.
3. **현재 항목은 접혀도 보인다:** 선택 표시(3-5)가 짧은 이름 항목에도 유지된다. 접힘 상태 머리줄에 현재 자료의 짧은 이름을 두지 않는다(중복).
4. **펼치기 경로:** 접기 버튼은 접힘에서도 같은 위치(머리줄)에 남고 이름은 "왼쪽 메뉴 펼치기"다. 기본 초점 순서의 첫 항목.
5. 짧은 이름이 둘 이상 겹치면 안 된다: 한 자료 안의 보기 짧은 이름 유일성은 등록부 단위 테스트(7절)로 검사한다.

### 3-5. 선택 표시

- **자료 그룹:** `aria-pressed="true"`(현재 자료는 하나). 시각: 진한 파랑 배경 + 흰 글자(기존 `.tabs>button.active`, `analysis-navigation.css:8`과 같은 색 `#173e69`).
- **보기 그룹:** 현재 화면은 `aria-current="page"`(지도 또는 열린 상세). 시각: 연한 배경 `#eaf1f8` + 왼쪽 3px 막대 + 글자 굵게(기존 `viewSwitcher button[aria-pressed=true]` 색 `analysis-navigation.css:12`). 색만으로 구별하지 않는다(막대·굵기 병용).
- 선택되었다고 폭·높이·글자 크기를 바꾸지 않는다(R04).
- 선택 상태의 출처: 자료 = `tab`, 보기 = `analysisDetail`(null이면 '지도'). 새 상태를 만들지 않는다.

### 3-6. 긴 메뉴 스크롤

- 열림 기준 높이: 머리줄 + 자료 4행 + 보기 최대 9행(지도 + 상세 8; 생활인구) + 그룹 제목 + 푸터. 행 높이 최소 36px(R04 기존 값) → 대략 4×36 + 9×36 + 제목·간격·푸터 ≈ 560px. **1365×768에서 헤더(1b 2줄 ≈ 100px)를 뺀 가용 약 660px이라 들어가지만**, 1365×591(확장 창 등) 또는 긴 이름 줄바꿈이면 넘친다.
- 규칙: 메뉴 영역은 뷰포트에 고정(`height:100%`, `min-height:0`)이고 **그룹 영역(자료+보기)만 `overflow-y:auto`**, 머리줄(접기 버튼)과 푸터는 고정. 스크롤바는 필요할 때만. 접힘 64px에서도 같은 구조.
- 초점이 스크롤 밖 항목으로 가면 그 항목이 보이도록 브라우저 기본 `scrollIntoView` 동작을 쓴다(커스텀 스크롤 코드 금지). 현재 보기 항목이 스크롤 밖에 있으면 열 때 보이게 한다(`block:'nearest'`).
- 긴 이름은 줄바꿈(`word-break:keep-all`)하되 말줄임으로 뜻을 숨기지 않는다. 가장 긴 이름 "연령·성별 거주지 이동 구성"(14자)은 200px에서 두 줄이 된다 — 행 높이가 가변이 되어 R04의 "같은 위계는 같은 크기"를 깨지 않게 **그 그룹 모든 항목의 최소 높이만 같고 줄바꿈은 허용**한다고 문서화(테스트는 높이 ≥ 최소와 폭 같음을 검사, 7-4절).

### 4-2. 전체화면에서도 자료 경로를 잃지 않는 방법

현재 사실(`UnifiedMapPanel.tsx:14,23`): 전체화면의 호스트는 **`.app` 루트**이고(`requestFullscreen`), `mapIsFullscreen` 패널은 `height:100dvh`로 화면을 덮는다(`fullscreen-map.css:3`). 따라서 왼쪽 메뉴가 같은 `.app` 안에 있어도 **시각적으로는 지도 패널이 덮는다**. 지금도 전체화면에서 자료를 바꾸는 길은 `mapPanelTools`의 "지도 데이터" select뿐이다.

설계:
1. **왼쪽 메뉴는 전체화면에서 숨긴다**(렌더는 유지, `display:none`이 아니라 지도가 덮는 현재 방식에 맞춰 `inert`+가림). 숨긴 메뉴의 상태(열림/접힘·현재 항목)는 보존되어 전체화면을 닫으면 그대로 돌아온다. 숨김 이유: 전체화면의 목적이 지도를 크게 보는 것이기 때문이다.
2. **전체화면에서의 자료 전환은 기존 "지도 데이터" select를 그대로 쓴다**(문구만 수정). 동작은 `selectMapData`(`main.tsx:122–127`)로 이미 검증돼 있다(전체화면 유지 + 포털 이동).
3. **전체화면에서 상세를 열고 싶으면 전체화면을 닫는다**(지금과 동일, 이 단계에서 새 경로를 만들지 않는다). 계획서 2절의 "전체화면에서도 자료 전환·조회·후보·복귀 가능"은 이미 충족된다고 보고 같은 위치에서 유지하는 것으로 해석한다. **결정 사항 3**으로 확인받는다(전체화면에서도 상세 select를 넣는 요구가 있는지).
4. native 전체화면과 fallback(`mapOverlay`) 둘 다 같은 select 경로를 쓰며 그 포털 대상이 `.app` 루트임을 바꾸지 않는다. 왼쪽 메뉴가 `.app` 안에 있는 한 호스트 문제는 생기지 않는다.
5. 전체화면 종료 시 초점은 전체화면 버튼으로 돌아가는 기존 동작을 유지한다.

### 4-3. 건드리지 않는 것

- 조회 입력 한 벌(상단), 지도·그래프, 상세 본문 내용, 오른쪽 보조 영역(3단계), 상권 서비스(4단계), 계산·로더·`public/data`.
- `useEffect(()=>setAnalysisDetail(null),[tab,view])`(`main.tsx:83`): 자료/서비스 전환 시 열린 상세를 닫는 지금 동작을 유지한다. 왼쪽 자료 버튼도 같은 효과를 받으므로 "상세가 열린 채 자료 전환"은 일어나지 않는다. **결정 사항 5**에서 확인(원하는 동작인지).

### 6-4. 수직 메뉴에 `centerY` 검사를 쓰지 않는 규칙

- 가로 그룹(상단 주제 4개, 모드 2개)은 **centerY 차이 ≤ 1px**와 높이 동일을 검사한다.
- 세로 그룹(왼쪽 자료 4개, 보기 N개)은 **left(x) 정렬·폭 동일 ≤ 1px, 높이는 같은 위계의 최소값 이상**을 검사한다. centerY는 항목마다 다르다(수직 배치이므로 정상). 이 검사를 가로 탭과 같은 함수로 재사용하면 **항상 실패**하므로 함수를 `uniformity(group, 'horizontal'|'vertical')`처럼 방향 인자로 나눈다.
- 줄바꿈 때문에 높이가 달라지는 항목은 "같은 위계는 같은 크기"를 깨는 것으로 오판하지 않도록, 높이 기준을 **최소 높이 이상 + 같은 그룹의 한 줄 항목끼리 동일**로 둔다.
- 항목 수 단언을 먼저 한다(자료 4, 보기 9/7/7/6). 0개 그룹이 통과하면 안 된다.
