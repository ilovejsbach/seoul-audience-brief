# 버스 정류장·노선 분석 기획

확인일: 2026-11-18 · W24 · 교통 2차 기획만. W23 지하철 조사·구현과 분리한다.

## 1. 핵심 결론 3줄

1. 정류장·노선별 승하차와 시간대 자료는 공개돼 있다. 첫 범위는 **전체 위치 목록 + 월별 시간대 요약 + 선택 정류장·노선 상세**가 적절하다.
2. 승하차 횟수는 고유 사람 수나 차내 혼잡률이 아니다. OD·혼잡도 공개 자료도 있지만 버스 분리·기간·산식 확인이 남고, 승객 성별·연령은 미확인이다.
3. 일별 원본 한 달이 목록상 약141MB다. 지하철 1차 검수 뒤 보관 기간·분할·별도 호스팅 예산부터 정하고 버스 구현을 시작한다.

## 2. 자료 지도 표

공식 **목록·설명 페이지**만 읽었다. 아래 기간은 목록에서 확인한 범위이며 파일 내용의 완전성·연속성을 검증한 범위가 아니다. 등록일과 자료 시작일을 혼동하지 않는다. ‘미확인’은 이번 조사로 확정하지 못했다는 뜻이다. 공간·시간 표와 제공 조건 표는 같은 ID로 연결한다.

서울 버스정보시스템의 공개 진입 페이지 [bus.go.kr](https://bus.go.kr/)는 제목만 확인되고 본문이 읽히지 않았다. 이를 자료 없음으로 판정하지 않았다. 대신 서울 [버스운행정보 묶음](https://data.seoul.go.kr/dataList/19/literacyView.do)과 공공포털의 공식 명세로 위치·노선 경로·실시간 연계의 존재를 확인했다. 실제 `ws.bus.go.kr` 서비스는 호출하지 않았다.

D의 좌표 설명에는 **WGS84와 EPSG-5179가 함께 적혀 있어 서로 맞지 않는다.** 표준ID·ARS·A/B 예외·앞자리0을 문자열로 보존하고, 후속 표본의 좌표 범위와 명세를 대조해 좌표계를 확정해야 한다. F의 정류장 순서 파일만으로 실제 도로 경로를 확보했다고 보지 않는다. 정류장 직선 연결은 ‘정류장 연결선’으로 표시하고 실제 노선선은 경로 좌표가 검증된 경우에 쓴다.

H의 정류장ID4자리/역사ID9자리 설명은 D/F의 코드 체계와 별개로 마스터 연결을 검증한다. 일부 월 ZIP가 매우 작게 표기돼(예:2024-12 25.49MB) 목록의 존재만으로 자료 완전성을 보장하지 않는다.

성연령·OD·혼잡 관련 상세 근거와 대체 불가 사유는 [독립 자료 확인](od-evidence.md)에 기록했다. 기후동행카드 등록자 연령은 탑승객 연령이 아니며, 주변 생활인구 성연령으로 승객 비율을 채우지 않는다.

## 3. 규모와 축소 전략

### 기존 사이트 여유와 원본 외삽

[W18 보고](../w18-pages-deploy-limits/REPORT.md)의 기존 dist는 **555,347,631B(555.35MB)**다. 당시 기준은 e7422c1이며 이번 새 빌드·공개 배포 실측이 아니다. 독립 검토자가 현재 로컬 public/data를 읽기 전용으로 다시 센 값은464파일·553,123,082B로 W18 합계와 같지만, 전체 내용 해시·최신 공개 일치를 뜻하지 않는다.

W18에서 공식 문서로 확인한 사이트1GB와 현행 Git 배포 경로의100MiB 파일 차단을 적용한다. **별도 Pages 파일100MiB 한도를 확인한 것은 아니다.** 50MiB 초과는 Git 경고다. 브리프의 파일100MiB는 현 배포 경로의 실질 제약으로 취급한다. 이번 외부 요청 범위에 GitHub가 없어 공식 한도를 새로 조회하지 않았고 W18의 확인일을 유지한다.

1GB를 보수적으로1,000,000,000B로 계산하면 남은 공간은 **444.65MB**다. 내부800MB 목표를 적용하면244.65MB이며 이는 공식 한도가 아닌 운영 여유 제안이다. 기존 형식의 연간 성장492.14MB는 W18 외삽상 교통 없이도 약1.047GB에 닿는다. W18의 ‘교통 초기100MB+월30MB’는 가정이며 버스 실측으로 쓰지 않는다. 보관 바이트·다운로드 전송·브라우저 메모리를 서로 구분한다. 상세는 [구조·한도 독립 검토](architecture-notes.md).

| H OD 월ZIP12개월 | 251.47MB×12 = **3,017.64MB** | ZIP인 상태부터 큼. 해제 후 크기는 미확인. 일ZIP와 월ZIP 중복 적재 금지 |

위 값은 목록의 MB를10진으로 놓고 한 달을12배 한 **기획 외삽**이다. 실제 파일 검증·연평균·배포용 JSON 크기가 아니다. ZIP과 평문CSV는 같은 압축 수준이 아니며 합산해 압축률을 추정하지 않는다. A의 한 달140.85MB와 H의251.47MB는 표기 단위가 MB/MiB 어느 쪽이어도100MiB를 넘는다. 잘게 나누면 단일 파일 문제는 풀어도 총량은 줄지 않는다.

### 정류장·노선·기간을 사용한 행 수 모델

`S=유효 고유 정류장`, `N=유효 노선`, `L=노선당 양방향 전체 정류장 순서 수의 평균`, `B=실제 노선×방향×정류장 순서 조합`, `D=일수`, `M=월수`, `H=시간 구간`으로 둔다. **S와 N의 실제 수는 미확인**이다. 2022 노선마스터1199행이라는 [과거 목록](https://www.data.go.kr/data/15099373/fileData.do?recommendDataYn=Y)을 현재 운행 노선 수로 쓰지 않는다.

산수 예시만으로 S=10,000, N=800, L=50, B=40,000, D=365, H=24, M=12를 가정한다. 실제 서울 버스 개수라는 뜻이 아니다. 방향·회차 중복을 포함하는 B 정의를 먼저 맞춰야 하고 전체 곱 S×N으로 대체하지 않는다.

| 형태 | 행 수 산식 | 위 가정의 행 수 |
|---|---|---:|
| 노선·정류장 일합계 | B×D | 14,600,000 |
| 일×시간을 긴 표로 저장 | B×D×H | 350,400,000 |
| 월×시간을 긴 표로 저장 | B×M×H | 11,520,000 |
| 월마다 시간대 열을 넓게 저장 | B×M | 480,000행 + 시간대별 승하차 열 |
| 노선을 합친 정류장 월×시간 | S×M×H | 2,880,000 |

행을 넓게 바꾸면 행 수가 줄어도 시간대 숫자가 사라지는 것은 아니다. 행당 바이트·압축률은 미확인이므로 위 행 수를 곧바로 파일 용량이라고 쓰지 않는다. OD는 실제 공개 쌍 E×기간×시간으로 예산을 잡고 희소 목록으로 저장한다. S² 밀집 행렬은 실제 제공량 예측이 아니다. 성연령 공동 교차표가 확인되기 전에는 성×연령 배수를 넣지 않는다.

**권고 조합:** 전체 정류장·노선의 가벼운 위치/검색 목록 → 월 시간대 요약 → 선택 노선·정류장·기간 상세. 화면상 점 묶기는 화면 정리이며 데이터를 삭제하는 축소와 구분한다. 일별 수년·시간별 상세·OD 전체는 별도 데이터 저장소와 필요시 서버 쿼리를 전제로 재예산한다.

버스 예산은 `전체 목표 − 최신 배포 묶음 − 기존 성장 − 지하철 예산 − 전환 여유`로 계산한다. 값이 음수이거나90일 전망에서 내부800MB를 넘으면 신규 적재 전에 축소·호스팅 분리를 결정한다. 이 문턱은 운영 제안이다. W17의 주제 첫 응답20MB·3초·메모리300MB도 제안 목표이며 버스 실측 통과가 아니다.

### W20 안의 위치와 재사용

상단 **교통**, 왼쪽 **자료: 지하철 / 버스**. 버스 안의 정류장/노선은 분석 대상 선택이고 최상단 주제를 늘리지 않는다. 왼쪽 보기에서 지도·시간대·기간 비교·OD를 고른다. 중앙 상단 조회 바 한 벌에 기간·대상·방향·승차/하차를 두고 긴 추가조건은 팝오버로 연다. 지도/상세를 오갈 때 같은 조건·카메라·선택을 유지한다.

중앙은 현재 지도 또는 상세 한 가지, 우측은 선택 값·같은 조건 후보 최대3·유효 범위와 가까운 출처/도움말이다. 메인에 모든 그래프를 쌓지 않는다. 지원하지 않는 성연령·OD 조합은 비활성 사유를 알리고 이전 결과를 남기지 않는다. W20의 좌200/우300, 접힘64/0 배치를 출발점으로 한다. 양쪽 펼친 실제 중앙 결과 폭은1365에서831px,1920에서1386px다. 긴 노선명·중첩점·OD 선의 실제 가독성은 추후 PC 실데이터 검사 대상이다. 모바일은 보류한다.

| 지하철과 공통으로 쓸 것 | 버스 전용으로 확인할 것 |
|---|---|
| 단일 조회 상태·기간 비교·지도 선택/복귀·시간대 차트 틀·후보·범례·결측/미지원·출처·취소/캐시·키보드 접근 | 표준ID/ARS/TPSS 마스터 연결, 같은 이름 반대편 정류장, 방향·분기·회차·정류장 순서, 폐지/이설·개편 유효기간, 경로 좌표·자정 이후 영업일 |
| 자료 설명서와 지연 로더의 공통 계약 | 자료별 시간·모집단·코드·단위 어댑터. 지하철 환승역 묶음이나 기존 동 면 채색 로직을 그대로 강제하지 않음 |

후속 영향 화면은 교통 진입·좌측 자료·지도·상세·기간 비교·후보·출처다. 적용 규칙은 R01(질문), R04~07(위계·주/보조·조회·가독성), R13(상태), R18~19(의미·원값), R20(검증)이다. W17 등록부·공통 로더는 제안이며 구현 완료로 보지 않는다. 최소 계약에는 자료ID/스키마/출처/라이선스/기간·영업일/공간코드·경계버전/지표·단위·지원차원/null·비공개/파일bytes·hash·encoding/커버리지를 담는다.

### 지하철과 버스를 합칠 수 있는 조건

같은 사람이 지하철에서 내려 버스를 타면 두 수단에 다시 잡힌다. 승차+하차까지 더하면 한 여정이 여러 번 잡힌다. 교통카드 범위·현금 제외·기간·공간·시간 구간·환승 처리·결측·운행사 포함 범위도 서로 다를 수 있다. 따라서 단순 합을 고유 이용자·통행자·지역 방문자라고 표시하지 않는다.

모집단과 기간·공간·지표 정의가 맞고 소스 중복을 제거한 경우 **두 수단 승차 건수 합계**로는 계산할 수 있다. 환승이 중복되는 이용 사건의 합임을 밝힌다. 사람/여정 단위의 통합은 허용된 환승 연결 자료와 중복 제거 기준이 있어야 한다. K의 통합 OD에 버스·지하철 개별 OD를 다시 더하지 않는다. 주변 생활인구도 이 합산에 넣지 않는다.

| 5 서버·혼잡·OD | 임의 조건 집계가 정적 조각으로 응답/메모리 목표를 못 맞추거나 빈번한 갱신·권한 분리가 필요. OD 수단·환승·비공개와 혼잡 산식 검증 | 요청 시 서버 집계·캐시·쿼리 제한. 성별·연령별은 같은 모집단의 해당 표를 각각 확보하면 추가하고, 성×연령 결합은 공동 교차표 확보 시에만 추가 |

API 키가 필요한 자료는 발급 대상·한도·보관 담당을 정한다. 키를 public/JS/Git에 넣지 않는다. 키가 배치 처리에만 필요하면 비공개 환경에서 집계한 공개 허용 결과를 정적으로 제공할 수도 있어, **키 필요와 런타임 서버 필수는 같은 조건이 아니다.** 이번에는 신청·키 사용·로그인을 하지 않았다.

후속 R20 수용 기준은 기능 E2E(점→노선→곡선→비교→복귀·빠른 조건 변경·실패 복구), 독립 원자료 대조(승하차 합·분모·ID·좌표·OD 수단/환승), PC1365×768/1920×1080 실제 화면(중첩·긴 이름·축·대비·균등 버튼·잘림·키보드·복귀), 전송/해제/파싱 메모리다. 구현 뒤 공개 배포가 승인되면 공개 파일·화면도 새로 확인한다. 과거 W20·기존 제품 검사로 대체하지 않는다.

### 필요한 사용자 결정

1. 첫 질문: 정류장 수요·노선 방향별 수요·계절 변화·실제 차내 혼잡·OD 중 우선순위. 권고는 정류장/노선 수요와 월 시간대다.
2. 포함 범위: 서울 시내·마을·광역과 경기/인천 유입 중 어디까지, 범위 밖 승하차·OD 처리.
3. 기간·정밀도: 최근12개월 월 요약부터 시작할지,24개월 계절 비교와 일별 상세까지 보관할지.
4. 축소 허용: 행정동/상권 요약의 손실, Top K를 화면 표시만 줄일지 실제 자료도 제한할지.
5. 운영: 지하철 이후 표본 착수 시점, 외부 호스팅/서버 비용 상한, 키 관리·정기 갱신 담당. 지금 결정을 요구하는 승인이 아니라 후속 착수 결정 목록이다.
