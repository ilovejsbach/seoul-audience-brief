## 2. 상태 소유자와 재마운트 방지

**소유자:** 현재 `App()`이 모든 상태(`mode`, `tab`, 날짜·시각·지역·후보 `compare`, `analysisDetail`, `marketOpened`, `view`, `visited`)를 갖는다(`main.tsx:66–80`). 상권 조건·후보·카메라는 `MarketExplorer` 내부 상태이고, 이 컴포넌트는 `marketOpened` 이후 `hidden`으로만 가려진다(`main.tsx:165`). 그대로 둔다.

**왕복해도 유지되는 이유와 지켜야 할 규칙(2부 필수):**
1. `AppShell`은 항상 같은 위치·같은 컴포넌트 타입으로 렌더한다. 서비스별로 **다른 루트 요소로 바꾸지 않는다**(헤더 안의 자식만 조건부).
2. `{children}`(= `<main>` 내용)의 구조·`key`를 바꾸지 않는다. 컴포넌트를 렌더 함수 안에서 새로 정의하지 않는다.
3. 지역/상권 작업공간은 `hidden`으로만 숨긴다(지금 방식). 조건부 렌더(`&&`)로 바꾸면 안 된다. 조건부로 지우는 것은 지금처럼 `Hero`뿐이다.
4. `mode`는 `App` 상태로 남고 서비스 전환으로 **절대 쓰지 않는다**. 모드 버튼은 지역 서비스에서만 보일 뿐이다.
5. `visited`(참/거짓)를 `lastService`(`'region'|'market'|null`)로 바꾼다. 이어보기 = 그 서비스로 `setView`만. 지역 이어보기는 기존 `tab`을 유지한다(기존 `launch`처럼 탭을 덮어쓰지 않는다).
6. 지도 전체화면 중이면 전환 전에 기존 `leaveMapFullscreen()`을 먼저 호출한다(`openMarket`·`goOverview`가 이미 하는 방식 재사용).

**지금도 유지되지 않는 것(1b에서 바꾸지 않고 정직하게 기록):** `useEffect(()=>setAnalysisDetail(null),[tab,view])`(`main.tsx:77` 부근) 때문에 서비스를 바꾸면 열려 있던 지역 상세 팝업·본문은 닫힌다. 조건·후보·모드·지도 카메라는 유지된다. 왕복 검사에서 "상세가 열린 채 복귀"를 합격 기준으로 쓰지 않는다. 또 `LayoutControls`의 비율 상태는 지금은 시작 화면 왕복에서 75%로 리셋되는데(툴바와 함께 마운트 해제), 새 구조에서는 더보기에 **항상 마운트**해 유지한다(좋아지는 변화, 테스트로 확인).

## 4. 상권 헤더 slot adapter

현재: `<div id="market-header-slot">`(`main.tsx:164` 끝)가 헤더 안에 있고 `MapWorkspace`가 `createPortal(workspaceHeader, #market-header-slot)`으로 제목(h1)·메뉴·지역 정보 토글·화면 배치·**"지역 분석 지도" 돌아가기 버튼(`MapWorkspace.tsx:124`, `onClose`)**을 넣는다. `MapWorkspace.tsx:16–17`은 slot이 나타날 때까지 `MutationObserver`로 찾는다.

설계:
- `AppShell`이 **같은 id의 slot**을 서비스 줄 자리에 계속 제공한다(`hidden={service!=='market'}`). 주제 막대는 그 위 줄로 추가될 뿐이라 `MapWorkspace` 코드는 slot 찾기 외에 변경하지 않는다(1b). 즉 어댑터 = "slot id·위치 계약 유지".
- 상권 줄의 "지역 분석 지도" 버튼은 **1b에서는 그대로 둔다**(기능 유지). 주제 메뉴 "지역 분석"이 같은 동작(상태 보존·전체화면 종료·키보드 복귀)을 한다는 것을 테스트로 먼저 확인하고, 중복 버튼 제거는 4단계(상권 셸 통합)로 넘긴다. 지역 쪽 "상권 지도"(`workspaceMapSwitch`, `mapWorkspaceEntry`)는 주제 메뉴가 대신하므로 **1b에서 제거**(복구 경로 있음).
- `AnalysisToolbarFrame`(`:9–24`)은 지금 "헤더 안에 툴바가 있으면 툴바 높이 0"으로 중복 차감을 피한다. 헤더 높이 측정을 `AppShell`로 옮길 때 같은 규칙을 지켜서 **`--app-header-height`가 두 번 정해지거나 두 번 빼지지 않게** 한다(측정 위치를 한 곳으로).
- `integrated-analysis-header.css:3–46`은 `.integratedAnalysisHeader/.integratedMarketHeader`와 `.integratedBrand`·`#market-header-slot`에 의존한다. 클래스 이름은 유지하고 새 막대용 규칙만 `app-shell.css`에 추가해 옛 규칙의 파급을 줄인다.

## 5. 상단 메뉴 구성

- 주제 4개(`TopicNav`): **지역 분석 / 상권 분석 / 교통(예정) / 부동산(예정)**. 폭·높이 동일(R04 가로 그룹, 시연 4·분석 6 글자 한도 유지). 예정 2개는 `disabled`, 클릭해도 아무 일도 없고 **네트워크 요청 0**(테스트로 확인).
- 시작 화면에서는 어느 주제도 `aria-pressed=true`가 아니다.
- **분석용/시연용 전환은 지역 서비스에서만 보인다.** `hidden`이 아니라 렌더하지 않는다. 상권·시작 화면에서는 DOM에 없다.
- sticky: 앱 루트는 이미 `100dvh` 열 구조이고 헤더는 `flex:none`이라 서비스 화면에서 사실상 고정이다. 시작 화면은 `main`이 스크롤되므로(`viewport-workspace.css:15–16`) 헤더가 안 움직임을 테스트로 확인하고, 명시적으로 `position:sticky;top:0;z-index`를 `app-shell.css`에 둔다. **주의:** `viewport-workspace.css:15–16`은 옛 히어로의 aria-label(`광고 입지 분석 시작`, `광고주 시연 시작`)을 `:has()`로 잡아 `overflow:auto`를 준다 → 새 히어로의 aria-label로 바꾸지 않으면 시작 화면이 잘린다(누락 위험).
- **더보기**(`MoreMenu`): 단추 하나, 키보드 Enter/Space·Esc·바깥 클릭·초점 복귀. 메뉴는 닫혀도 DOM에 남긴다(`LayoutControls`의 75% 비율 상태가 닫을 때 초기화되면 안 되므로). 항목: ① 브리핑 인쇄(`window.print`) ② 시작 화면 ③ (지역 시연일 때만) 근거 정보 보기/접기 ④ **고급 배치**(= 기존 `LayoutControls` 화면 배치: 비율 55/67/75/85·초기화75%·자석 도킹 안내) — 지역일 때만. 옛 `analysisHeaderMore`의 "버튼을 누르면 details를 닫는" 동작은 `LayoutControls`를 해칠 수 있어 가져오지 않는다. "출처·해석 기준"과 "도움말"은 현재 그런 기능이 **없으므로 만들지 않는다**(목업에만 있음).
