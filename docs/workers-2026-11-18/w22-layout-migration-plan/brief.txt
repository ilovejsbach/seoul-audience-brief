할 일
계획 문서를 아래 내용으로 쓴다. 이 작업은 계획만 세운다. src는 수정하지 않는다.
1. 현재와 목표 대응표
   - 현재 화면 요소(헤더, 자료 탭, 보기 select, 상권 헤더, 조회 바, 우측 패널, 상세 팝업·본문, 전체화면, 배치 설정 등)가 목표 레이아웃의 어디로 가는지 정리한다.
   - 각 요소에 유지 / 이동 / 통합 / 제거 중 하나를 표시하고, 근거가 되는 파일과 줄을 적는다.
   - 기존 기능이 사라지지 않는지 확인한다. 상세 25항목, 후보, 조건 보존, 팝업↔본문, 전체화면, 인쇄, CSV, 상권 공간 탐색이 대상이다.
2. 단계 분할
   - 각 단계는 따로 커밋하고 배포할 수 있어야 한다. 단계가 끝날 때마다 서비스가 정상 동작해야 한다.
   - 권장 순서는 아래와 같다. 근거가 있으면 바꿔도 된다.
     - 0단계: 결정 기록. DEVELOPMENT_REQUIREMENTS에 넣을 REQ 문구와 규칙 개정 후보를 제안한다(문서 수정 자체는 1단계 작업으로 둔다).
     - 1단계: 앱 셸. 상단 고정 주제 메뉴와 서비스 라우팅을 만들고, 히어로를 교체한다. 상권 모드 상속 문제(I04)도 이 단계에서 해결한다.
     - 2단계: 좌측 메뉴. 자료와 보기를 옮기고, 접기를 만들고, 시연용 기본 접힘을 적용한다.
     - 3단계: 우측 보조 패널을 통합하고 접기를 만든다.
     - 4단계: 상권 분석 작업공간을 같은 셸에 맞춘다.
     - 5단계: 마감. 남은 문구 수정(I03 매출 이름, I05 비교 이름, I08, I09), I11 폭 맞춤, 표시설정 잘림(I01)을 새 구조에서 다시 확인한다.
   - 주제 등록부(w17 제안)는 1–2단계에서 자료·보기 목록에 최소 형태로 도입할지 판단해 적는다. 과잉 설계는 피한다.
   - 데이터 로딩 개선(w18의 선로딩 중단)은 레이아웃과 독립된 단계로 분리할지 판단해 적는다.
3. 단계별로 아래를 적는다.
   - 바뀌는 파일
   - 예상 위험
   - 지켜야 할 불변식: 조회 결과 수치 불변, 조건 보존, 데이터 계약
   - 검증 방법

   - 되돌리기 방법
