할 일
1. 현재 IA 실측
   - 로컬 Vite(127.0.0.1:4187 또는 npm run dev)를 PC 1365×768과 1920×1080으로 연다.
   - 모든 진입점과 메뉴를 실제로 눌러 아래 나무 구조를 만든다.
     시작 화면 → 서비스 → 모드 → 자료 탭 → 보기(지도/상세 분석 각 항목) → 더보기·팝오버·작업창
   - 각 노드에 다음을 적는다.
     - 이름(화면 표기)
     - 위치
     - 위계 수준
     - 같은 위계끼리 표기·크기가 일치하는지
     - 조건 유지 여부(이동 후 기간·지역·자료가 유지되는지)
     - 돌아가는 경로
   - 주요 노드는 스크린샷으로 남긴다.
   - 결과물: ia-current.md(나무 구조 + 표)와 스크린샷 폴더
2. 수직 축 점검
   - 두 서비스 각각에 대해 표로 정리한다.
     - 행: 기간 단위(일/월/분기/연, 전년 동기), 화면(지도/상세/비교/시연), 분석 축(시간대·성별·연령·요일·업종·후보)
     - 칸: 지원, 일부 지원, 미지원
   - 같은 기능이 서비스마다 다른 이름이나 위치에 있는 불일치를 찾는다.
   - 메뉴 깊이 때문에 기능이 숨겨진 곳을 찾는다.
   - 특히 행정동 추정매출이 지역 분석 탭에, 상권 매출이 상권 작업공간에 나뉘어 있는 구조가 사용자에게 혼란을 주는지 근거를 들어 판단한다.
3. 수평 축 점검
   - 지하철역(점 단위), 버스 정류장·노선(점과 선), 부동산(단지·필지)을 추가한다고 가정한다.
   - 지금 구조에서 메뉴를 어디에 붙여야 하는지 판단한다.
     - 자료 탭이 4개에서 7개 이상으로 늘어날 때 버티는지
     - 공간 단위가 다른 주제를 같은 지도 틀에 넣을 수 있는지
   - 공통으로 다시 쓸 틀이 무엇인지 정리한다. 후보: 기간 선택, 지도, 상세, 비교, 시연, 출처.
   - 주제별로 달라질 수밖에 없는 것이 무엇인지 정리한다.
4. 문제 목록과 제안
   - 각 문제는 아래 형식으로 적는다.
     - 증거(스크린샷·코드 줄)
     - 영향(현재 사용성 / 미래 확장)
     - 심각도
     - 관련 규칙 ID
   - 목표 IA 제안 1~2안을 낸다.
     - 각 안은 나무 구조로 그리고 장단점을 적는다.
     - 현재에서 목표로 가는 단계별 이전 계획을 적는다.
     - 지금 바로 할 것과 수평 확장 직전에 할 것을 구분한다.
   - 화면 재구성보다 현재 공간·가독성·동작 개선이 우선이라는 요구서 원칙을 지킨다. 큰 재구성은 비용과 위험을 함께 적는다.
5. 자기 반박 검토
   - 근거 없는 주장이 없는지 확인한다.
   - 사용자의 시연 목적("광고주와 현장에서 비교하며 결론을 만든다")과 충돌하지 않는지 확인한다.
   - 데이터 계약(서로 다른 주기·대상을 섞어 해석하지 않음)을 어기는 통합 제안이 없는지 확인한다.
