# 현재 IA 실측

2026-11-18 · 소스 e7422c1, 로컬 Vite 127.0.0.1:5173의 실제 Orca UI 조작·스크린샷·DOM 실측과 독립 Codex 코드 검토를 합쳤다. 사용자 확정은 **지역 분석만 분석/시연 두 모드, 상권 분석은 모드 없음**이다. 두 PC(1365×768·1920×1080)와 지역 두 모드에서 4자료·25상세를 선택하고 지도 복귀를 확인했다(100진입). 상권도 두 PC에서 지역 분석용/시연용 각각을 거쳐 메뉴와 3상세·서비스 복귀를 확인했다. 진입 전 지역 모드를 상권의 제품 모드로 세지 않는다.

## 읽는 방법과 관측 한계

- L0 시작, L1 서비스, L2 서비스 안의 모드, L3 자료/보기, L4 선택 메뉴·팝오버·상세 항목, L5 해당 모듈 안의 옵션이다. 이는 사용자에게 설명할 논리 위계이며, 현재 화면이 이 순서대로 배치돼 있다는 뜻은 아니다.
- JSON의 `controls`는 숨김 DOM을 거르지만 모달 뒤의 inert 배경과 화면 밖·클립된 자식까지 포함할 수 있다. `text`에 select option이 나온다고 모든 항목이 동시에 펼쳐졌다고 보지 않는다. **모달에서는 현재 `detailNavigationSelect`와 닫기/본문 전환만 활성 상세 증거로 읽는다.** 뒤쪽 지역 탭·조회 입력은 같은 화면에서 조작 가능한 노드로 세지 않는다.
- 실제 선택 상태 확인, 닫고 지도 복귀, 조건 동일, 카메라/후보 보존은 서로 다른 판정이다. 5절은 기본값 위주의 조건 동일을 확인했다. 이후 비기본 조건 왕복은8절/roundtrip-results.json에 별도로 추가했다. 모든 조합과 카메라 좌표 보존은 증명하지 않는다.
- 원자료 수치 대조·모든 초점/오버/대비·전체화면·인쇄·모바일은 이 IA 검토에서 전수 검증하지 않았다. 7개 자료를 실제로 강제 추가한 실험도 하지 않았다.


`추정매출` 탭의 본문은 행정동 매출이다. 시작카드/접근가능 제목에 ‘행정동’을 이미 쓰지만 자주 보는 탭에서는 줄여 쓴다. 상권 서비스의 자료 `추정매출`과 원본·공간·업종범위가 다르다. 이는 이름찾기 후보 문제이며 실제 오선택률은 측정하지 않았다.

## 5. 기본 조건의 실제 전후 비교

16개 PC 조합(4자료×분석/시연×두크기)의 map→returned 스냅샷에서 id가 있는 INPUT/SELECT 값을 직접 비교했다. 모두 동일했다. 아래는1365에서 비교에 사용한 값이며1920값도 측정JSON에 있다. 원자료 수치나 임의 조건조합은 이 표의 대상이 아니다.

아래는 대표값 표다.

| 자료 | 채집 전후 비교값 | 결과 | 증거 |

`자치구`는 커스텀 버튼이라 값 필드에 실제 코드가 없다. 스크린샷/본문에는 기본 서울전체가 보이지만 임의 구·동 선택의 코드 왕복 유지까지 이 비교로 증명하지 않는다. 후보 목록·지도 transform은 현재 JSON에 없으므로 코드의 상태 유지 의도와 부모의 추가 실제 조작을 나눠 기록해야 한다.

- mapWrap 폭1304.5px, 열 너비 `1100.84px 187.656px 0px`.
- 열린 mapDisplaySettings는 `position:absolute`, `grid-column:3`, `grid-row:3`, 폭 **2px**, offsetParent는 mapWrap.
- 현 서비스 전체가 불능인 것은 아니지만 지도 표시 설정 접근이 막힌 현재 기능 결함이다. 부모가 **P1**로 분류했다. 큰 IA 개편보다 먼저 해결할 국소 문제로 남기며 이번 점검에서는 수정하지 않는다.

원인 추적은 [코드·문서 독립검토](./code-ia-review.md)의 보충 절을 따른다. 실제 모달 배경 inert와 별개로, 이 설정은 열려 있어도 가용폭이 사라지는 문제다.

## 8. 추가 왕복·메뉴 관측

지역 생활인구의 기준일을 2026-11-01, 시각12시, 20–39세·남성으로 바꾸고 송파구를 골랐다. 기본조건 검사와 구분해 `*-supplement-*` 근거로 남겼다. 조회창 띄우기→상단복원, 추이 팝업→본문→팝업→닫기, 지도 전체화면→닫기, 다른 자료→생활인구, 지역 모드 변경, 상권→지역 복귀, 시작→이어보기에서 같은 입력이 남는지 대조했다. 지원하지 않는 조건을 상권으로 자동 복사하는 검사/제안은 아니다.

- 지도 전체화면은 실제 Enter 키로 열고 닫았다. 별도 지도 데이터 선택이 나타났고 조회 입력이 함께 이동했다. [1365 전체화면](screenshots/1365-supplement-fullscreen.png).
- 지역 조회창 배치의 띄우기와 상단 조회 바를 실제 선택했다. [1365 띄우기](screenshots/1365-supplement-query-floating.png). 우측 고정·드래그·투명도 모든 값은 미검사다.
- 추이의 **보조 분석**, **그래프 옵션**과 그 안의 **축 설정 / 계산 방법과 결측 처리 / 적용된 축과 표시 기준**을 열었다. 그래프 옵션에는 실제값/기준대비증감/기준100, 기준시점, 축범위·초기화, 재생간격, 위치크기초기화가 있다. [1365 그래프 옵션](screenshots/1365-supplement-graph-options.png). 각 설정의 모든 값 적용은 미검사다.
- 시작의 지역4자료 카드와 시연 시작의 **브리핑 자료 선택→4자료**, 이전 분석/시연 이어보기를 실제 클릭했다. [시연 시작](screenshots/1365-supplement-presentation-start.png), [자료 선택](screenshots/1365-supplement-presentation-choices.png). 시작으로 돌아간 뒤 자료를 고르는 동작과 기존 조건으로 이어보는 동작을 구분했다.
- 더보기 시작/인쇄, 생활인구 시간 빠르게 이동·비교지표, 지도 출처·탐색 도움, 조회창 배치도 열었다. 인쇄·파일다운로드·외부원본 링크는 실행하지 않았다.

추가 검사 도중 로딩 완료 전 순위 클릭, 브랜드의 장식문자 포함, 기존 동 선택 상태와 배치 메뉴 펼침 상태에 대한 잘못된 가정 등 **검사 스크립트 문제**가 있었다. 자료 대기·이름 포함검색·실제 자치구 선택지로 서울 전체를 먼저 선택·배치 메뉴의 현재 펼침 상태 확인 방식으로 보완했다. 실패 호출은 browser-actions.jsonl에 남겼고 성공한 후속 JSON/스크린샷과 구분했다. 이 오류를 제품 결함으로 세지 않았다. 반면 표시설정 잘림은 실제 Enter 재현까지 확인한 제품 결함이다.
