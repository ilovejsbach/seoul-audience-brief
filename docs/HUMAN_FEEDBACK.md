# 휴먼 피드백 분석과 재발 방지

대상: 이 대화의 데이터 조사 시작부터 2026-11-16 최신 헤더·조회 배치·설명 압축 요청까지. 따옴표 인용은 사용자의 실제 문장 중 짧은 부분이며 맞춤법을 일부러 교정하지 않았다. ‘최신 요청 요지’는 요구를 정규화한 것으로 원문 인용과 구분한다. 질문·제안은 확정 요구와 구분한다. 이는 구현 완료 보고가 아니다.

## 불만의 중심

사용자는 단순히 화면을 작게 만들라고 한 것이 아니다. **왜 이 화면을 보는지에 맞춰 주정보를 크게 보여주고, 조건을 한 곳에서 바꾸며, 상세를 본 뒤 편하게 돌아오는 분석 도구**를 원한다. 반복 불만은 기능 부족보다 동일 정보의 중복, 우선순위 역전, 일관되지 않은 화면 틀, 클릭 이후 연결 단절, 검수의 신뢰성에서 나왔다.

## 결정의 흐름과 폐기된 전제

1. **자료 우선**: 파일 기반 시연부터, 데이터 확대에 맞춰 장기 백엔드를 후속 검토한다. 처음부터 서버 확장을 크게 만드는 것은 현재 우선순위가 아니다.
2. **지도와 비교**: 구·동과 상권 자료를 구분하고, 시간·대상 선택이 지도·수치·그래프에 연결되어야 한다. 기존 지역별 퍼널은 필수 구조가 아니라고 사용자가 명시했다.
3. **공간과 위계**: 설명·범례·옵션을 줄이고 주정보가 남은 창을 사용한다. 모든 기능을 없애는 것이 아니라 필요시 여는 구조다.
4. **창 도구**: 크기·위치·도킹·플로팅 요청은 작업 편의를 위한 것. 최신 요구는 기본 상단 조회 바도 필요하면 동일 호스트를 플로팅/우측 자석 도킹으로 옮기고 다시 상단으로 복원하는 것이다. 이전의 상단 이동 금지 전제는 폐기한다. 모든 설명까지 이동 창으로 만드는 해석은 여전히 과도하다.
5. **두 트랙**: 시연은 실무 도구와 별개 장난감이 아니라 같은 분석에서 현장 비교에 집중한 표현이다. 과거 번호식 시연 순서·별도 숨김 CSS는 현행 근거가 아니다.
6. **상세 이동**: 하단 펼침보다 팝업, 이후 팝업/본문 교체 선택을 요청했다. 후보 비교까지 같은 콤보에 넣고 복귀를 유지한다.
7. **조회 통합**: 여러 차례 재설명 끝에 최종 뜻은 명확하다. 상단 조건 자리에 실제 입력을 놓아 표시와 편집을 겸한다. ‘폼은 남기고 요약칩만 합침’은 잘못된 해석이다.
8. **고정 프레임**: 모든 창의 바깥 최대 크기는 브라우저 창에 맞춘다. 내부의 피치 못할 스크롤은 허용하지만 주그래프를 찾으려고 페이지를 내리게 해서는 안 된다.
9. **최신 요구**: 보조 그래프가 번갈아 읽혀도 되는 경우 큰 한 장으로 전환한다. 비교 자체가 목적인 두 선·두 값까지 무조건 숨기는 정책은 아니다.
10. **공통 헤더 압축**: PC 공통 root 헤더와 자료/보기 탐색 두 행은 한 행으로 통합한다. 중복 부제/context를 없애고 자료4개의 균형을 유지한다. 모드·부가 기능은 더보기로 정리하되 현재 자료·모드는 알아볼 수 있게 하며 좁은 화면의 한 행 강제는 하지 않는다.
11. **설명의 위치**: 생활이동 기준/집계/날짜 해석은 집계 옵션 가까운 동적 툴팁, 자료설명·출처는 관련 결과 가까운 작은 설명 도구로 압축한다. 상시 전체폭 박스/footer를 없애는 것이며, 단위·기간·분모·결측·날짜 한계를 없애는 뜻이 아니다.
12. **상권의 같은 원칙 적용**: 제품 root 헤더+상권 작업공간 제목/action을 한 행으로 줄이고, 지도 지표·건수·공간 경로·결과 도구도 목적을 유지해 압축한다. 일반4자료의 이동 조회 바를 상권에 복사만 하는 것은 위험하다. 기존 정보 패널·본문·우측 도킹 충돌을 검토한 뒤 범위별로 구현·실행을 판정한다.

최신 요청을 정본과 요구 문서에 연결한 것은 설계 정합화다. 실제 UI 조작·배포 확인은 별도 기록이며, 구현자가 소스를 수정했다는 사실만으로 이 요구들의 완료를 선언하지 않는다.

## 재발 방지: 구현 전 다섯 질문

- 이 문장이 이미 결정된 요구인가, 제안인가? 이미 명확하면 사용자에게 재질문하지 않는다.
- 바꾸는 것이 값의 범위인가, 표시 방법인가, 다른 질문의 상세인가? 서로 다른 위계를 하나의 거대 옵션창에 섞지 않는다.
- 줄이려는 정보가 중복인가, 해석에 필수인가? 단위·기준·모집단·결측 사유는 접근 가능해야 한다.
- 이 공통 클래스/상태/포털을 어느 화면·모드가 소비하는가? 스크린샷 밖에도 영향이 있다.
- 현재 코드·현재 실행·공개 배포 중 어디까지 확인했는가? 과거 성공을 현재 품질로 표현하지 않는다.

## 검수 실패에서 배운 것

거대 지도 설정 아이콘, 좁은 창의 143px 지도, 숫자 중간 줄바꿈, 일반 추이 시간축 잘림은 빌드 성공으로 발견되지 않았다. 화면 크기별 주정보 면적, SVG 선택자 범위, flex/detail/포털 높이와 실제 축 노출을 독립적으로 봐야 한다. 현재 지적의 처리 상태는 [디자이너 감사](uiux-designer-audit.md)와 [세션 기록](SESSION-WRAPUP-2026-11-16.md)을 따른다. 이 문서는 그 오류가 모두 수정됐다고 주장하지 않는다.
