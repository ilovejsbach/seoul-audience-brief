### 화면 검사 2건의 최초 실패 원인

최초 분석/시연 두 검사는 금액의 `title`을 `25,036,425,038,435원`으로 예상했다. 기존 `exactNumber`의 실제 출력은 단위 앞에 공백이 있는 `25,036,425,038,435 원`이다. 금액 자체는 같았으며 **검사 스크립트의 기대 문자열 오류이고 제품 수치 결함이 아니다.** 해당 지점에서 멈췄으므로 최초 실행의 뒤쪽 여정은 미실행이었다.

제품의 출력 함수를 바꾸지 않고 작업 전용 검사 기대값을 실제 계약에 맞췄다. 복귀 버튼의 실제 접근 이름 `← 지도로 돌아가기`도 검사 locator에 정확히 반영했다. 최초 실패 JSON·화면·trace는 `playwright-first-format-failure*`로 보존했다. 제한 환경에서 처음 서버를 열지 못한 EPERM은 별도 환경 차단이며, 권한 허용 후 로컬에서 실행했다.

다른 작업자의 `tests/e2e/`, 루트 `playwright.config.mjs`, `package.json`, `package-lock.json`을 수정하지 않았다. 기존 검사 목록은 행정동 commerce를 포함하지 않아 작업 산출물 폴더에 별도 spec/config를 두고 기존 npm 명령에 config만 지정했다.

```sh
npm run test:e2e -- --config docs/workers-2026-11-17/w6-dong-sales-impl/playwright.config.mjs
```

## 한계와 감독자 인계
