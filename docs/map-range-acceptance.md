# 지도 색상 범위·범례 의미 수용 기준

2026-11-15 · 독립 감사 · R11/R18/R20. 이 문서는 구현자의 계산 함수를 가져오지 않고 준비 원자료 열을 직접 합산해 만든 기대값과 검수 기준이다. 소스 구현·브라우저 실행 완료 보고가 아니다.

## 목적과 불변 조건

- 규모를 읽는 지도는0 포함 자동 범위를 기본으로 유지할 수 있다. 변화가 작은 두 시점은 같은 최솟값·최댓값으로 색상 대비를 확대한다. 기준 지도와 비교 지도의 자동/수동 범위가 따로 바뀌면 같은 색의 의미가 달라지므로 금지한다.
- 증감·순이동은0 중심 대칭 범위를 유지한다. 양·음 범위를 따로 조여 색이 부호나0을 잘못 나타내지 않는다. 양수만 관측된 증감 지도도 음수 쪽 공간과0 기준의 의미는 유지한다.
- 수동 범위는 표시 설정이다. 실제값·차이·지표 단위·순위·선택 지역·차트·후보·CSV를 바꾸거나 범위 밖 지역을 제거하지 않는다. null/비공개/미연결은0 또는 최저색으로 바꾸지 않는다.
- 범위 밖 값은 경계 색에 포화한다. 상한/하한을 넘은 관측값 개수와 같은 끝 색에 실제 다른 값이 섞임을 알린다. 툴팁과 정확 상세는 범위에 잘린 숫자가 아니라 원값을 읽는다.
- 축약 범례는 작은 색상 막대+범례 버튼으로 제공하고, 정확한 경계·단위·0·결측·수동 범위·포화 의미는 툴팁에서 확인한다. 마우스·클릭·키보드로 읽고 Esc/외부 선택으로 닫는다. 큰 설명을 상시 지도 아래에 늘어놓지 않는다.

## 원자료 계산 방법

화면 함수나 색상 정규화 도우미를 import하지 않았다. Python json으로 파일을 읽고 `Decimal(str(row[column]))`을 합산했다. 비교 값은 둘 다 관측됐을 때만18−12를 계산했다. 범위 밖 개수는 `value<low`, `value>high`이며 경계값과 같은 값은 범위 안이다. 색상 구간은 하단 첫 구간만 양끝 포함, 이후는 직전 경계 초과·현재 경계 이하로 판정한다.

구현 후 독립 소스 검토와 부모의 실제 브라우저/공개 화면 검수는 별도 기록이 필요하다. 이 문서만으로 실행 통과를 주장하지 않는다.

## 통합 소스 독립 검토

2026-11-15 현재 작성 중인 소스의 연결을 확인했다. 아래는 정적 검토이며 브라우저 실행 통과와 구분한다.

- `useMapRange`는 원자료 배열을 수정하지 않고 별도의 적용 범위·입력 초안·오류 상태를 관리한다. 빈값/비유한수/역전/음수 규모 하한/비대칭 증감을 거부한다. 잘못된 입력은 마지막 적용 범위를 유지한다.
- 입력 초안의12유효자리 반올림은 큰 금액 경계를 바꾸는 위험이 있어 원수치 문자열로 수정됐다. 소수 입력step과scope전환 초안 재설정도 보완됐다.
- `DistributionComparison`은 두 시점 합집합에 한 범위를 사용한다. 증감은 별도 대칭 범위 상태이며 양·음·0·결측 색을 구분한다. 시간 변경은 범위를 유지하고 공간 도형 집합 변경은 초기화한다.
- `MapCanvas`는 색상 정규화만 새 범위를 사용하고 원값·지도 접근성 레이블은 보존한다. 전입전출/이동의순이동 지표는 관측값 부호뿐 아니라 지표 종류로 대칭 모드를 전달한다.
- `MarketExplorer`의 중복 수동 범위 입력을 보기 설정 한 곳으로 통합했고, 직접 지정 시 같은 값 간격임을 선택 상태·설명·범례에 표시한다. 색상 구간을 다시 선택하면 직접 범위를 초기화하고 자동 분류와 맞춘다.
- 범례는 기존 설명 팝오버의 포털·읽기·Esc·동시 열림 방지 규칙을 재사용한다. 이전 일반/분포 범례의i너비 규칙이 작은 그라데이션 막대를 덮지 않도록 별도 범위 선택자를 두는 사항을 지적했다.

실제 브라우저에서는 여기에 더해 데이터 선택→범위 변경→색상·범례·원값 대조→시간 변경→오류→초기화→상세/후보 복귀를 순서대로 확인해야 한다. 기존 범례용 버튼 이름·DOM·창 이동 검사도 새 툴팁 계약에 맞춰 갱신해야 하며, 선택자 실패를 데이터 의미 통과로 대신하지 않는다.
