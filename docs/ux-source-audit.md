# 화면 목적에 따른 UX 소스 감사

기준: 2026-11-14 / 현재 소스. 이 문서는 소스 기반의 독립 검토다. **브라우저에서 직접 실행한 E2E 결과가 아니며**, 시각적 잘림·사용자가 실제로 느끼는 난이도는 별도 실행 검사와 대조해야 한다. 코드는 수정하지 않았다.

## 업무 목적과 화면 목록

| 화면·상태 | 광고주가 이 화면을 보는 이유 / 판단 질문 | 필요한 정보 | 조작 → 기대 결과 → 다음 행동 | 현재 구현의 틈 |
|---|---|---|---|---|
| 분석용 시작 | 어떤 자료로 입지·시간·소비 수요를 확인할 것인가? | 자료의 의미·기간·공간 단위, 권장 출발점 | 자료 또는 목적 선택 → 해당 질문에 맞춘 초기 화면 → 후보 탐색 | 자료 카드의 제공 범위는 명확하다. 그러나 목적별 버튼도 같은 자료별 화면의 동일 첫 단계로 진입한다. |
| 시연용 시작 | 광고주에게 어떤 근거를 어떤 순서로 설명할 것인가? | 브리핑 순서, 현재 자료·지역, 이어보기 조건 | 시작 → 지역 탐색 → 시간 비교 → 후보 근거 | 생활인구부터 시작하는 구조. 이전 시연의 조건은 시작 화면에서 요약되지 않는다. |
| 생활인구 지역 탐색 | 어느 구·동에 타깃 체류 규모가 큰가? | 날짜·시간·연령·성별·지역 단위·현재 선택 | 조건 변경 → 지도·순위·수치 동시 갱신 → 후보 또는 추이 | 조건은 지도 밖. 지도만 보면 값의 정의는 읽을 수 있지만 조건을 바꾸기 어렵다. |
| 생활이동 지역 탐색 | 어느 시각에 어느 방향의 이동이 집중되는가? | 유입/유출, 출발/도착 기준, 한 시간/누적/하루 구분 | 방향·집계 선택 → 해당 이동량 → 상대지역 확인 | 조건 수가 많고 전체화면에서 접근할 수 없다. 하루 지도와 아래 시간대 추이가 다른 기준이다. |
| 전입·전출 지역 탐색 | 주거 기반이 유입되는 지역인가, 빠져나가는 지역인가? | 전입·전출·전입−전출, 연도, 구·동 단위, 제공 범위 | 지표 전환 → 지도 방향·순위 변화 → 장기 추이 | 전입/전출/순이동 선택은 존재하지만 지도 밖이며 전체화면에서는 없다. |
| 행정동 추정매출 | 인구 후보가 실제 소비 규모와도 맞는가? | 분기·시간 구간·제공 업종 범위·단위 | 구→동 → 시간 구간 확인 → 소비 규모 추이 | 상권 단위 화면과 명칭·진입점 연결이 약해 어느 화면에서 더 세분화할지 불명확하다. |
| 지도 전체화면 | 넓은 지도에서 지역 간 분포를 집중 비교할 수 있는가? | 핵심 지표 전환·조건 요약·지역 선택·범례 | 지표 전환 → 지도 색·값 → 지역 상세 | 확대/색상 조절은 내부에 있으나 판단의 핵심인 전입/전출·타깃·기간은 외부에 있다. |
| 지역 팝업 | 이 지역을 더 조사하거나 후보로 담을 이유가 있는가? | 현재 값·정의·선택 상태·다음 목적지 | 상세 또는 후보 추가 → 명확한 다음 화면 | 동일 '상세 분석'이 구=동 지도, 동=추이, 생활이동 구=추이로 다르게 동작한다. |
| 시계열 추이 | 언제 규모가 크고 변화가 얼마나 있는가? | 현재 시점·비교 기준·실제값/증감/지수·축·기간 | 시점 또는 기준 변경 → 해석 가능한 변화 → 지도/후보 | 서로 다른 비교 기준 선택기가 화면 여러 곳에 분산된다. 직접 축과 변환값을 켜면 설명량이 많다. |
| 두 시점 분포 | 어느 지역에서 인구가 증가·감소했는가? | 공통 눈금, 기준·비교 시간, 증감 정의 | 두 시간 선택 → 분포 또는 증감 → 지역 상세 | '비교 시간'이 전역 선택 시간까지 바꾼다. 시간별 분포 전용 영역만 바뀐다고 예상할 수 있다. |
| 후보 비교 | 2~3개 지역 중 어느 곳을 제안할 것인가? | 동일 조건의 후보값·차이·후보 유지 정책·선정 이유 | 추가/제거 → 동일 조건 비교 → 상세/브리핑 | 일반 대시보드는 구 변경시 후보가 초기화될 수 있고 별도 상권 화면은 지역을 바꿔도 후보가 남는다. |
| 조회 조건 저장 | 지역/타깃/시간이 다른 가설을 비교할 수 있는가? | 저장 범위·비교 가능성·재적용 효과 | 기준안 저장 → 다른 조건 저장 → 차이 확인 | 첫 안 삭제시 다음 안이 기준으로 승격된다. 지역 후보 비교와 다른 저장 모델이며 세션만 유지한다. |
| 상권 중심 지도 | 어느 구체적 상권이 업종·타깃 소비 수요에 맞는가? | 상권 단위·업종·분기·주변분포·지리 조건 | 메뉴 조건 → 상권 선택 → 상세/후보/추이 | 일반 지도와 탐색 체계가 다르며 진입 버튼은 단순 '지도 중심 조회'. |
| 자료 설명/내려받기/인쇄 | 근거를 검토·설명·공유할 수 있는가? | 원본 출처·한계·조회 조건·저장 범위 | 설명 열기/표 저장/인쇄 → 재현 가능한 근거 | 자료별·화면별 설명 위치와 표 내려받기 범위가 다르다. 일반 후보 비교의 저장·공유는 별도 제공되지 않는다. |

## 개선점과 실행 검증 질문

우선순위: P1=판단을 막거나 서로 다른 결과를 같은 의미로 오해하기 쉬움, P2=반복 조작·학습 비용 또는 브리핑 설명 부담, P3=보조 편의. 아래 '확정'은 코드의 동작/구조가 확정이라는 뜻이며 실제 화면의 체감 평가는 별도다.

### UXS-01 / P1 / 핵심 조건이 지도에서 사라짐 — 구조 확정
- **목적**: 전입/전출을 오가며 주거 기반 변화 방향을 비교한다.
- **필요 → 현재**: 지도 옆에 전입/전출/순이동 선택이 필요하다. `ExtraDashboard.tsx:88`의 `.controls`에만 있고 `MapPanel` 내부에는 없다. `main.tsx:83`의 생활인구 타깃·성별·날짜도 동일하다. `MapCanvas.tsx:10` 전체화면에는 자료 종류와 닫기만 포함된다.
- **재현**: 전입·전출 → 전체화면 → 순이동을 보려 시도. 선택란을 찾을 수 없고 전체화면을 닫아 위로 이동해야 한다. 시연용은 `세부 조건 보기`도 열어야 한다.
- **개선**: 지도 안에 자료별 '핵심 조회 조건'을 유지한다. 전입·전출은 3지표+연도, 생활인구는 시점+타깃 요약과 '조건 변경'. 외부 폼을 복제하기보다 같은 상태를 조절하는 압축 조건 영역으로 제공한다.
- **E2E 의미 판정**: 지도만 열린 상태에서 전출→순이동 전환 가능, 조건명·범례·색·지역 값·상세 제목이 같은 지표로 변하고 음수는 0 중심 대칭색인지 확인한다.

### UXS-02 / P1 / 목적별 진입이 질문에 맞는 화면으로 좁혀주지 않음 — 구조 확정
- **목적**: '시간대별 이동 변화 분석'을 골랐으면 흐름부터 판단한다.
- **근거**: `Hero.tsx` 목적별 버튼은 `onLaunch(tab, label, 'analysis')`; `main.tsx:76`의 `launch`는 모두 `presentationStep=0`, 같은 자료 화면을 연다. `scenario` 상태는 화면 목적의 초기 조건·포커스로 사용되지 않는다.
- **개선**: 지역 분포 목적은 지도, 시간 변화 목적은 추이, 장기 거주 변화 목적은 순이동 연간 추이에 초기 포커스를 맞춘다. 선택된 목적을 화면 제목·다음 행동에 이어준다.
- **E2E**: 목적 카드를 클릭한 첫 화면에서 그 질문의 그래프/지표가 바로 보이는지, 자료 카드 경로와 달리 초기 강조가 있는지 확인한다.

### UXS-03 / P1 / 생활이동 하루 지도와 시간대 추이가 다른 집계 — 동작 확정, 오해 가능성 검증 필요
- **목적**: 하루 이동 규모와 시간 집중도를 구별하여 집행 시점을 정한다.
- **근거**: `ExtraDashboard.tsx:94` 하루 모드의 지도는 일자 전체, 추이는 시간대별이며 시점을 클릭/재생하면 `setAccumulation('hour')`. 이 설명은 지도 바깥 문단이다.
- **개선**: 지도에는 '하루 합계', 추이에는 '하루를 나눈 시간대별 이동량'을 계속 표시한다. 그래프 점 클릭이 지도 집계를 전환한다는 동작을 클릭 전 안내하고 변경 후 명시한다.
- **E2E**: 하루 지도→추이 선택시 집계 변경과 실제 KPI가 대응하는지, 지도 제목·집계 선택값이 함께 변하는지 확인한다.

### UXS-04 / P1 / 후보를 담은 뒤 지역을 바꾸면 후보가 사라지는 정책 차이 — 동작 확정
- **목적**: 서로 다른 구의 지역을 조사한 뒤 같은 기준으로 최종 후보를 비교한다.
- **근거**: `main.tsx:66` 및 `ExtraDashboard.tsx:65`의 지역 변경은 `setCompare([])`를 실행한다. `MarketExplorer.tsx`는 후보 코드를 지역 필터와 별도로 유지하고 전체 지역에서 값을 계산한다.
- **개선**: 지역 후보를 조사 범위와 분리하여 유지한다. 공간 단위가 달라 비교 불가능하면 삭제 대신 '현재 비교 범위와 다름' 표시·분리 보관 또는 변경 전에 결과를 설명한다.
- **E2E**: 마포구 후보 추가→다른 구 조사→후보 수/이름이 어떻게 되는지, 사용자가 삭제를 예상·복구할 수 있는지 확인한다.

### UXS-05 / P2 / '상세 분석'이 목적지를 구분하지 않음 — 구조 확정
- **목적**: 지역 선택 후 동 분포를 볼지 시간 추이를 볼지 결정한다.
- **근거**: `Navigation.tsx:6` 버튼명은 모두 '상세 분석 →'. 실제 `main.tsx:85`, `ExtraDashboard.tsx:91`에서 구=지도, 동=추이, 생활이동 구=추이로 분기한다. 힌트는 작은 별도 문장이다.
- **개선**: 버튼을 구의 경우 '동별 분포 보기', 동은 '시간대별 추이 보기' 또는 '연도별 추이 보기'로 구체화한다. 자료가 없는 구 연도는 동 지도 진입 대신 제공 범위를 설명한다.
- **E2E**: 버튼 문구와 도착 화면 제목이 일치하며 이미 선택된 구/동을 재클릭해도 같은 목적지로 일관되게 가는지 확인한다.

### UXS-06 / P2 / 주거 변화의 핵심 용어가 '순유입' 검색 의도와 다름 — 구조 확정
- **목적**: 주거 기반이 늘고 줄었는지 빠르게 이해한다.
- **근거**: 선택란은 '순이동', 주요 설명에는 '전입−전출'이 있지만 처음 탐색하는 사용자는 순유입과 같은 개념인지 추론해야 한다(`ExtraDashboard.tsx:88`).
- **개선**: '순이동(전입−전출)'로 표시하고 양수='순유입', 음수='순유출'을 범례와 선택값 근처에 표시한다. 데이터 용어는 유지한다.
- **E2E**: 순이동의 음수 지역을 고른 사용자가 '유입 없음'이 아닌 순유출이라고 해석할 근거가 즉시 보이는지 확인한다.

### UXS-07 / P2 / '지도 중심 조회'가 상권 전용이라는 정보가 없음 — 구조 확정
- **목적**: 행정동 인구 후보를 더 작은 상권 소비 수요로 좁힌다.
- **근거**: `main.tsx:44,80` 버튼은 항상 `MarketExplorer`를 연다. 거주 이동 지도도 같은 방식으로 볼 수 있다고 예상하기 쉬운 일반명이다.
- **개선**: '상권 단위 지도'로 명명하고 행정동 매출 화면에서 '상권 단위로 자세히 보기'를 연결한다. 전환시 선택 구/동을 넘기면 반복 탐색을 줄인다.
- **E2E**: 일반 추정매출에서 마포구 선택→상권 화면 진입시 구가 유지되는지, 처음부터 다시 찾아야 하는지 확인한다.

### UXS-08 / P2 / 비교 기준 시간이 세 군데에서 독립적 — 구조 확정
- **목적**: 어느 시점 대비 증가했는지 일관된 근거로 설명한다.
- **근거**: `TrendExplorer.tsx`의 `baseline`, `DistributionComparison.tsx`의 `baseHour=12`, `TimeComparison.tsx`의 `chosen/fallback`이 별도 상태다. 하나를 바꿔도 다른 기준은 그대로다. 분포의 '비교 시간'은 반대로 전역 현재 시간(`onSelectHour`)을 바꾼다.
- **개선**: 독립성이 의도라면 각 그래프에 '이 그래프의 기준'을 지속 표시한다. 브리핑 목적에서는 공통 기준시점을 한 번 정해 적용하는 선택지를 제공한다. 전역 시간을 바꾸는 컨트롤에는 '현재 선택 시간'이라고 표시한다.
- **E2E**: 추이기준06시→분포기준/두시점기준의 값·문구를 대조하고 사용자가 같은 차이를 보고 있다고 오해하지 않는지 확인한다.

### UXS-09 / P2 / 후보 버튼의 활성 상태가 실행 가능성과 다름 — 소스 확정, 체감 검증 필요
- **목적**: 현재 지역을 후보에 추가하고 실제 선택 상태를 확인한다.
- **근거**: 일반 `TrendExplorer`의 비교 버튼은 후보가 3개여도 비활성화하지 않는다. 콜백 `shortlist/toggleCompare`는 3개일 때 조용히 아무 변경도 하지 않는다. 생활인구의 비교 버튼 문구는 항상 '선택 지역 후보로 비교하기'로, 이미 선택한 후보를 누르면 제거된다(`main.tsx`, `TrendExplorer.tsx`). 상권 drawer의 '이미 후보에 담긴 상권'도 버튼 자체는 활성일 수 있다.
- **개선**: '후보 추가/해제' 상태를 문구·pressed로 나타내고 한도 도달시 비활성화 또는 즉시 결과 알림을 제공한다.
- **E2E**: 후보 3개→추이에서 4번째 추가, 이미 담은 지역→동일 버튼 클릭. 숫자뿐 아니라 버튼의 약속과 실제 추가/해제가 맞는지 확인한다.

### UXS-10 / P2 / 상권 탐색과 일반 지도 조작 관례가 다름 — 소스 확정, 사용성 검증 필요
- **목적**: 익숙한 지도 조작을 유지하며 상권까지 세분화한다.
- **근거**: `MapCanvas.tsx`는 휠 확대·축소와 배율·100%에서 축소 비활성화가 있다. `MarketExplorer.tsx`는 휠 리스너·배율 표시가 없고 축소 버튼이 최소 배율에서도 활성이다.
- **개선**: 지도들에 같은 확대·축소/배율/원래범위/휠 도움말 규칙을 적용한다. 전체화면 가능 여부도 일관되게 한다.
- **E2E**: 일반 지도에서 배운 휠/100%/초기화 동작을 상권 지도에서 반복했을 때 같은 결과인지 확인한다.

### UXS-11 / P2 / 상권 선택은 키보드로 지나치게 긴 경로 — 구조 확정
- **목적**: 키보드 사용자도 후보를 빠르게 선택한다.
- **근거**: `MarketExplorer.tsx:46`의 모든 상권 path에 `tabIndex=0`. 전체 범위에는 약 1,650개 지오메트리가 있다. 일반 지도도 25구/동 path가 개별 tabstop이다.
- **개선**: 상권 지도는 1개 진입점과 방향키 이동 또는 검색·순위 목록 중심 선택을 제공한다. 지도 밖 다음 컨트롤로 건너뛰는 방법을 제공한다.
- **E2E**: Tab으로 지도 진입→다음 도구로 이동하는 데 필요한 키 수, 포커스 표시와 선택 지역 이름을 확인한다.

### UXS-12 / P2 / 검색·조건 해제 복구가 분산됨 — 구조 확정
- **목적**: 여러 조건으로 좁힌 뒤 결과가 없으면 빠르게 돌아온다.
- **근거**: 상권 검색은 입력 즉시 `filteredFeatures`와 camera를 재계산한다. 무결과 화면은 '선택 조건에 해당하는 상권이 없습니다'만 표시한다. 일괄 조건 초기화·필터 chip 해제는 없다(`MarketExplorer.tsx`).
- **개선**: 적용 조건 요약과 개별 해제, '검색어 지우기/지역만 초기화/모든 조건 초기화' 중 원인에 맞는 복구를 제공한다. 검색중 지도가 계속 자동 맞춤되는지 E2E로 확인한다.
- **E2E**: 구+동+유형+검색어로 무결과→원인 조건 하나를 해제하는 경로와 소요 조작 수를 기록한다.

### UXS-13 / P2 / 시연 2단계의 정보량이 한 장의 결론을 넘을 수 있음 — 시각 검증 필요
- **목적**: 광고주가 집행 시점에 대한 하나의 설명을 즉시 이해한다.
- **근거**: 시연 step1에는 `TrendExplorer`·`DistributionComparison`·`TimeComparison` 등이 함께 남는다. `.dashboardContent`는 약 `100dvh-285px`의 내부 스크롤이며 추이 패널 자체는 축·변환·사실·차트·재생·다음행동을 모두 갖는다(`layout-standard.css:5`, `theme-overrides.css`).
- **개선**: 시연 기본은 '선택 지역의 시간 변화 + 핵심 값 + 다음'에 집중하고 비교 지도/축 조절은 필요시 펼친다. 같은 데이터 기반은 유지하되 한 장의 판단 질문을 분명히 한다.
- **E2E**: 화면 제목·선택 값·그래프·다음 행동이 첫 뷰에 함께 보이는지, 내부/외부 두 스크롤을 번갈아 써야 하는지 실제 화면에서 확인한다.

### UXS-14 / P2 / 수치의 읽기 단위가 화면별로 다름 — 구조 확정, 시각 검증 필요
- **목적**: 지역 간 소비 규모 차이를 브리핑 중 빠르게 읽는다.
- **근거**: 일반 매출 KPI/순위/후보는 `Math.round(...).toLocaleString` 원 단위 전체 숫자. 상권 상세에는 '약 n억/만'을 병기하지만 상위5개 순위는 다시 원 단위 긴 숫자다. 시간 그래프 Y축도 전체 원 숫자(`ExtraDashboard.tsx`, `MarketExplorer.tsx`, `TrendExplorer.tsx`).
- **개선**: 매출은 억/만 단위를 차트·순위·주요 KPI에 일관되게 표시하고 정확값은 툴팁·표·내려받기로 보존한다. 원 단위와 축약 단위 선택은 화면 전체에 적용한다.
- **E2E**: 긴 값의 줄바꿈·열 정렬·Y축 너비, 1위와2위의 차이를 읽는 데 불필요한 자리수 계산이 필요한지 확인한다.

### UXS-15 / P3 / 저장 의미와 기준안 자동 승격의 발견성 — 구조 확정
- **목적**: '20–39세 여성18시' 등 광고 가설을 저장해 비교한다.
- **근거**: `ScenarioWorkbench.tsx`는 접힌 details 안에 있고 세션 한정 안내가 바닥에 있다. 첫 안 삭제 후 다음 안이 자동 기준안이 되며 차이는 모든 행에서 다시 계산된다.
- **개선**: 버튼 가까이에 '새로고침 전까지만 보관'을 표시한다. 기준안 변경은 명시 선택 또는 '기준안이 바뀌었습니다' 알림을 강조한다. 지역 후보와 조건 비교의 목적을 제목에서 구분한다.
- **E2E**: 기준안 삭제→남은 차이가 새 기준으로 바뀜을 사용자가 알아차릴 수 있는지, 새로고침으로 초기화됨을 사전에 설명받는지 확인한다.

## 개선 순서 제안

1. **지도를 보면서 질문을 바꿀 수 있게 한다**: UXS-01(지표/기간), UXS-05(구체적인 다음 목적지), UXS-06(순이동 정의).
2. **비교 근거의 일관성을 지킨다**: UXS-03(시간 집계), UXS-04(후보 유지), UXS-08(비교 기준), UXS-09(활성 버튼의 실제 결과).
3. **화면별 판단 시간을 줄인다**: UXS-02(목적별 시작), UXS-07(상권 진입), UXS-12(무결과 복구), UXS-13(시연 한 장), UXS-14(숫자 단위).

개선 효과의 판정은 '버튼이 눌리는가'가 아니라, **사용자가 질문에 필요한 조건을 화면을 벗어나지 않고 찾고 → 결과의 지표·기간·단위를 이해하고 → 비교 또는 상세로 이어갈 수 있는가**로 해야 한다.

## 추가: 광고주 판단 목적에 맞춘 데이터 구분

일중 유입과 정주 기반은 서로 다른 광고 수요다. 같은 지도 위에 놓을 수 있어도 하나의 인구 지표로 합치거나 빼서 해석해서는 안 된다. **'누가 거주하는가 → 어느 시간에 머무는가 → 어디에서 들어오고 나가는가'**를 별도의 질문으로 유지한다.

| 광고주 판단 목적 | 답하려는 질문 | 우선 사용할 자료 | 화면에서 함께 보여야 하는 조건 | 가능한 비교 | 지금 자료만으로 확정하면 안 되는 해석 |
|---|---|---|---|---|---|
| 거주민 기반 검토 | 생활권 안에 반복 구매의 기반이 되는 주민 수요가 있는가? | 주민등록 거주인구가 확보되면 정주 규모, 전입·전출은 연간 이동 변화의 보조 근거 | 주민 수의 기준일·공간 단위·연령·성별, 전입전출 연도·정의 | 같은 거주인구 자료의 지역별 규모·구성비; 같은 전입전출 자료의 전입/전출/순이동 및 연도별 방향 | 전입−전출만으로 현재 주민 수, 주민 전체 증감, 고유 전입자 수를 확정할 수 없다. 출생·사망·행정구역 변경 등도 다르다. |
| 주간·야간 체류 검토 | 후보 지역에 목표 연령·성별이 어느 시간에 많이 머무는가? | 내국인 생활인구의 시간별·행정동별·연령별·성별 추계 | 날짜·시간·지역·연령·성별·공개/비공개 상태 | 같은 자료·날짜·공간 단위의 두 타깃 비교; 같은 타깃의 주간/야간 또는 두 시간대 비교 | 생활인구가 실제 광고 도달 인원, 외부 방문자, 통행량, 하루 고유 방문자라는 해석은 금지한다. |
| 이동 수요 검토 | 다른 지역에서 언제 들어오고 어디로 나가는 이동이 많은가? | 생활이동의 유입·유출 이동 건수, 출발지·도착지 자료 | 자료일자·출발/도착 시각 기준·집계 방식·지역 범위·반복 이동 포함 가능성 | 같은 시간 기준·집계 방식에서 유입/유출 비교; 방향별 상대지역 비중; 시간대별 이동 집중 비교 | 이동 건수의 합을 서로 다른 사람 수나 광고 순도달로 해석할 수 없다. 유입−유출을 현재 체류 인구 변화로 단정할 수 없다. |
| 주거 기반 장기 변화 | 주민 수요의 기반이 유입 방향인가, 유출 방향인가? | 연간 전입·전출·순이동, 성별 세분 자료가 확보되면 같은 연도·정의로 비교 | 연도·지역 단위·성별·출처·구/동 제공 범위 | 전입−전출의 순이동, 같은 정의의 장기 추이, 확보된 성별별 방향 | 연령별 원자료와 집계 범위는 아직 미확정이다. 성별 원자료 확보만으로 연령×성별 교차 분석을 약속하면 안 된다. |
| 상권 소비 수요 검토 | 체류·이동 후보가 업종의 소비 규모와도 맞는가? | 제공 업종의 상권 추정매출, 별도 상권 유동인구 | 분기·업종·상권 경계·시간/연령/성별 등 한 가지 세부 기준·원본 단위 | 동일 자료·기간·업종·공간 단위의 후보 간 상대 규모 및 분기 변화 | 서로 다른 연도의 생활인구와 매출을 나눠 구매전환율로 만들 수 없다. 주변분포를 곱해 '20대 여성의 저녁 매출'을 만들 수 없다. |

### 현재 진행 중인 범위와 화면의 약속

- 생활인구의 **연령·성별 두 타깃 비교**는 별도 구현이 진행 중이다. 구현 후에도 같은 날짜·시간·지역·집계 정의를 유지해야 한다. 두 그룹이 겹치면 단순 합계가 고유 인원으로 해석되지 않게 표시해야 한다. 이 감사에서는 구현 완료나 E2E 통과를 주장하지 않는다.
- 전입·전출의 **성별 세분 자료는 별도 확보 작업 중**이다. 원본의 기간·공간 단위·성별 합계 일치 여부를 확인한 후 선택지를 노출한다. 연령별 제공 여부는 아직 미확정이며 회색 비활성 옵션으로 가능한 기능처럼 암시하지 않는다.
- 주민등록 거주인구를 확보하지 않은 화면은 전입·전출만으로 '정주 인구 규모'를 표시하지 않는다. '거주지 이동 흐름'이라고 명시하고, 정주 규모 자료의 필요성을 데이터 확보 항목으로 남긴다.

### 허용 산식과 금지 산식

| 산식·방법 | 판정 | 화면에 필요한 설명 |
|---|---|---|
| 동일 정의·기간·단위의 전입 − 전출 | 가능 | 연간 순이동. 양수는 순유입, 음수는 순유출. 현재 주민 수 자체가 아니다. |
| 같은 생활인구 자료의 타깃 A − 타깃 B | 가능 | 동일 날짜·시간·지역 조건의 추계 규모 차이. 그룹 중복 가능성과 공개값 조건을 함께 표시한다. |
| 같은 생활인구 타깃의 시간 B − 시간 A | 가능 | 시점별 체류 추계 차이. 실제 이동 경로나 유입·유출 인원은 아니다. |
| 특정 타깃 생활인구 ÷ 같은 조건 전체 생활인구 | 조건부 가능 | 분자·분모가 같은 모집단·시점·공개 범위일 때 구성비로 표시한다. 전체 합계에 비공개값이 있으면 계산하지 않는다. |
| 생활인구 − 주민등록 거주인구 = 외부 방문자 | **금지** | 모집단·기준 시점·추계 방식이 다르다. 그 지역 주민이 외부에 있는 시간도 있어 차이가 외부 방문자가 되지 않는다. |
| 시간별 유입 이동량의 합 = 하루 고유 유입 인원 | **금지** | 반복 이동과 동일인의 여러 기록이 포함될 수 있다. '이동 건수 합계'로만 설명한다. |
| 생활이동 유입 − 유출 = 해당 시간의 체류 인구 증가 | **금지** | 출발/도착 기준·집계 경계와 생활인구 추계가 다르다. 체류 인구의 잔액 계산으로 사용할 수 없다. |
| 다른 기간 인구 ÷ 매출 또는 매출 ÷ 인구 = 구매전환율 | **금지** | 구매자 수·광고 노출·동일 모집단이 확보되지 않았다. 서로 다른 자료는 나란히 보는 보조 근거로만 사용한다. |
| 성별 비중 × 연령 비중 × 시간 비중 = 교차 타깃 규모 | **금지** | 주변분포만으로 교차분포를 만들 수 없다. 교차 원자료가 확보된 경우에만 별도 제공한다. |

### 목적 기반 E2E의 추가 판정 질문

1. **거주민 기반**: 전입/전출 화면의 사용자가 이 값이 현재 거주민 수인지, 연간 거주지 이동인지 제목과 단위만으로 구별할 수 있는가?
2. **주간 체류**: 두 타깃을 골랐을 때 동일 날짜·시간·지역 조건이 유지되고, 어느 그룹이 더 큰지와 자료 없음 여부를 지도·차트·수치에서 같은 의미로 읽을 수 있는가?
3. **이동 수요**: 출발 시각/도착 시각 또는 한 시간/누적/하루 전환 후 그 기준이 결과 바로 옆에 계속 보이며, '건'을 '명'으로 읽게 만드는 문구가 없는가?
4. **장기 거주 변화**: 성별 옵션의 선택 가능 범위와 실제 데이터 제공 기간이 일치하는가? 미확보 연령이나 교차 타깃에 대한 숫자를 추정해 제시하지 않는가?
5. **상권 검증**: 인구 지도에서 상권 매출로 이동해도 서로 다른 기간·정의가 명확히 보이는가? 비교용 보조 지표를 하나의 전환율이나 광고 성과로 오해하도록 배치하지 않았는가?
