2026-11-15 · 독립 평가 · R01/R03/R05/R06/R12/R13/R14/R15/R16/R18/R20/R21.

이 문서는 새 조회 옵션의 의미와 사용자 경험을 검사할 기준이다. 구현자의 소스 반영, 독립 원자료 대조, 부모가 수행할 실제 브라우저 검사를 구분한다. 이 문서를 작성했다는 이유로 새 UI를 실행 통과했다고 표시하지 않는다.

## 판단 질문과 상태 구분

사용자는 ‘어느 자료·기간·지역·대상으로 이 결과를 보고 있는가’를 읽고, 한 가지 조건을 바꿨을 때 예상한 결과를 확인하려 한다. 시연 중에는 현재 결과를 유지한 채 조건만 잠깐 열어 편집해야 한다.

| 상태 | 의미 | 바뀌어야 하는 결과 | 지켜야 하는 것 |
|---|---|---|---|
| 조회 범위 | 지도에 남겨 두는 구·동·상권 이름·유형의 교집합 | 지도 대상·순위·결과 수·CSV | 후보 목록·팔레트·수동 색상 범위·기간 |
| 현재 분석/선택 대상 | 상세·추이로 읽는 특정 지역 또는 상권 | 상세 값·추이·선택 표식 | 나머지 지도 도형·후보·조회 범위 |
| 표시 설정 | 팔레트·색상 구간·수동 범위·축·배치 | 채움색·표현·공간 배치 | 원값·집단·시점·후보 |
| 현재 조건 요약 | 위 조회 상태를 읽고 해당 입력에 접근하는 진입 | 조건 편집/해제 후 실제 결과 | 필수 기간·자료를 실수로 제거하지 않음 |

현재 범위를 설명하는 작은 버튼은 새 기능 메뉴가 아니다. 편집과 해제는 다른 행동이며, 조건을 지워도 다른 독립 조건·후보·색상 설정을 함께 지워서는 안 된다. 구를 해제할 때 동을 함께 해제하는 것은 부모·자식 의존성이라 예외가 아니라 명시할 계약이다.

## 독립 원자료 기대값

[data/tableau-query-fixtures.json](../data/tableau-query-fixtures.json)은 앱의 필터 함수나 준비 스크립트를 호출하지 않고 별도 Python 반복문으로 만들었다. 저장된 경계 속성은 ‘지도에 선택 가능한 상권’의 기준이고, 통계 값·관측/결측은 공식 CSV를 직접 읽어 대조했다. 파일 경로와 SHA-256을 보관한다.

| 조건 | 경계 상권 수 | 관측/결측 | 관련 유형 선택지의 건수 |
|---|---:|---:|---|
| 전체 | 1,650 | 1,648 / 2 | A1,090 · D249 · R305 · U6 |
| 이름 홍대 | 10 | 10 / 0 | A4 · D4 · R2 · U0 |
| 홍대 + 마포구 | 9 | 9 / 0 | A3 · D4 · R2 · U0 |
| 홍대 + 마포구 + 서교동 + 발달상권 | 2 | 2 / 0 | 유형 자체를 빼면 A2 · D2 · R2, 합계6 |
| 홍대 + 마포구 + 관광특구 | 0 | 0 / 0 | 유형 자체를 빼면 A3 · D4 · R2, 합계9 |
| 공덕 + 마포구 | 4 | 4 / 0 | A2 · D1 · R1 · U0 |
| 홍대 + 성북구 + 골목상권 | 1 | 1 / 0 | 홍대부중 |
| 이름 `  홍 대  ` | 10 | 10 / 0 | 정규화한 홍대와 동일 |

구 선택지 계산은 구를 바꾸면 동이 전체로 해제되는 실제 동작에 맞춰 **구와 그 자식 동 조건을 함께 제외**한다. 동은 동 자신만, 유형은 유형 자신만 제외하고 나머지 조건을 유지한다. 단순히 현재 결과의 고유값만 보여주면 다른 구·유형으로 바꿀 길이 막히므로 잘못이다.

선택지 건수는 경계 상권 개수다. 통계가 결측인 상권을 선택지 수에서 제거하거나 그 값에0을 넣지 않는다.0건의 현재 선택은 해제할 수 있어야 하고, 선택되지 않은0건 항목의 비활성 여부와 이유가 실제 동작과 일치해야 한다.

정확값 대조: 원본 CSV의20262 / 상권3001494 / 총유동인구는 **8,284,977명**이다. 원본 이름의 인코딩 표기와 화면 경계의 이름은 구분하며 코드를 기준으로 연결한다.

## 실제 브라우저에서 수행할 여정

1. **조건 읽기→편집→복귀**: 닫힌 조회창에서 기간 버튼으로 입력을 열고 실제 입력에 초점이 도달한다. 값을 바꾸면 지도·순위·핵심값·추이·CSV가 함께 갱신되고 닫은 뒤 요약이 현재 조건을 읽는다.
2. **시연 상세 편집**: 그래프·후보·보조 화면에서 조건 편집을 눌러도 지도 화면으로 강제 이동하지 않는다. 숨은 지도 밑에 창이 열리거나 초점만 이동해서는 안 된다. 편집 후 현재 결과의 화면을 유지한다.
3. **개별 해제**: 홍대+마포+유형 조건에서 검색만 해제하면 구·유형·기간·후보·수동 색상 범위·팔레트는 유지한다. 유형만 해제, 동만 해제, 구와 자식 동 해제를 각각 검사한다.
4. **종속 선택지**: 위 독립8사례에서 지도 대상 수·표시 건수·관련 선택지 수를 대조한다. 구를 바꿨는데 이전 구의 동이 남지 않아야 한다.
5. **0건 복구**: 홍대+마포+관광특구에서0건은 자료 결측이 아니라 조건 교집합의 무결과다. 유형만 해제하면9개가 즉시 복구되고 다른 조건은 유지한다.
6. **검색형 선택**: 구·동·유형의 검색창을 열고 부분 이름을 검색해 선택한다. 원래 native select의 값과 요약도 같아야 한다. 화살표/Enter/Esc/외부 클릭/초점 복귀, 검색 무결과에서 입력 수정·취소를 검사한다.
7. **지도 선택과 범위**: 상권을 클릭하면 상세·추이가 선택 대상을 읽고 조회 지도는 유지한다. 확대/이 지역만 보기는 명시적 행동에서만 한다. 선택 해제는 조회 조건·후보를 지우지 않는다.
8. **카메라**: 지도 이동/확대 뒤 검색어를 연속 입력하고 유형을 변경해 카메라가 임의 초기화되지 않는지 확인한다. ‘조회 범위 맞춤’은 현재 결과의 도형을 맞추고 결과 수·조건은 유지한다.
9. **후보**: 서로 다른 구의 후보를 담고 공간 필터를 바꿔도 남아 있다. 후보값은 같은 자료·기간·분석 기준의 각 후보 코드로 읽는다. 최대3개와 해제는 유지한다.
10. **상권 주변분포**: 시간대17–21시에서 성별로 바꾸면 ‘시간×성별’로 계산하지 않고 분석 기준 하나를 바꾼다. 전체로 해제하면 같은 자료·분기·공간 조회를 유지한다.
11. **생활인구**: 연령과 성별의 실제 교차 조회는 유지한다. 연령만 해제하면 성별·지역·시각이 유지되고, 성별만 해제하면 연령이 유지된다. 날짜 응답 가드와 비공개 처리도 유지한다.
12. **거주지 지원 범위**: 연령은2025 자치구, 성별은2021–2025 구·동만 고를 수 있다. 미지원 과거 연도나 동에서 연령으로 바꿀 때 선택 변경 이유를 안내하고 실제 지원 조건으로 한 번에 정리한다. 성별×연령 교차를 만들지 않는다.
13. **생활이동**: 도착/출발·한시간/누적/일계가 조건 요약에서 읽힌다. 일계의 시각 조작은 비활성이고, 호버로 현재 집계 방식이 바뀌지 않는다.
14. **초기화 역할**: 배치 초기화, 지도 맞춤, 지역·검색·유형 해제, 직접 색상 범위 초기화가 각각의 범위만 바꾼다. 저장 조건 기능을 새 메뉴와 중복 생성하지 않는다.
15. **레이어와 모드**: 시연 기본 조건창 닫힘→열기→닫기/Esc, 분석 고정/띄움, 전체화면 전환·자료 전환을 검사한다. 다른 화면의 이전 창이 남거나 같은 입력ID가 둘 이상 나타나지 않아야 한다.

## 시각·접근성 위험과 판정

- 요약은 시연에서 여러 줄의 큰 배너가 되지 않아야 한다. 네 개를 넘는 조건을 접더라도 출발/도착·시점·누적/일계의 핵심 의미는 가까이에 남긴다.
- ‘나머지 조건’ 안에 편집·해제 버튼이 있다면 단순 tooltip 역할을 쓰지 말고 상호작용 가능한 팝오버/대화상자 역할을 사용한다.
- 검색 팝오버가 스크롤 부모에 잘리지 않아야 하며 전체화면 안에서도 접근 가능해야 한다. 검색창이 원래 입력을 덮고 닫을 수 없게 되어서는 안 된다.
- 검색 옵션 수가 줄어도 현재 선택을 읽고 해제할 수 있어야 한다. 자동 변경은 이유를 알리고, 검색어만 바꿨는데 다른 독립 조건이 조용히 초기화되는 동작을 허용하지 않는다.
- 고정/이동 형태를 위해 같은 controls를 복제하면 중복ID와 서로 다른 상태가 생기기 쉽다. 한 입력 상태 원천을 유지한다.
- 현재 값이 없는 원인은 통계 결측·미지원·실제0·공간 교집합0건으로 구분한다. 버튼 활성 여부만으로 의미 통과를 선언하지 않는다.

## 현재 평가 상태

독립 fixture 작성과 통합 소스 의미 검토를 완료했다. 관련 선택지의 자기 조건 제외와 구→동 종속 해제, 이름·유형 변경 시 카메라 유지, 명시적인 범위 맞춤, 후보 보존, 상권 주변분포 단일 기준, 거주지 지원 연도·단위 제한은 소스에서 확인했다. 실제 demographic JSON의 성별 2021–2025 구·동, 연령 2025 구 범위도 대조했다.

검색 입력에서 첫 ArrowUp 이동 결함은 구현 담당이 수정했다고 보고했다. 실제 UI의 초점·복귀·시연 상세 편집·공개 화면은 이 평가 에이전트가 실행하지 않았으므로 통과로 판정하지 않는다. 부모의 실제 실행 결과와 구분해서 최종 갱신한다.

## 자석 배치·단일 창 추가 수용 기준

영향 규칙은 R03/R05/R06/R10/R14/R16/R20이며 조회 옵션·선택 정보·순위와 상권 작업공간을 대상으로 한다. 창의 배치 변경은 조회 조건이나 통계 계산이 아니라 표시 설정이다.

| 검사 | 기대 결과 |
|---|---|
| 좌우 자석 영역 | 제목을 잡고 작업공간의 좌우 끝 56px 안으로 이동하면 해당 쪽 도킹 예고만 보이고, 놓았을 때 확정한다. 가운데·범위 밖에서는 도킹하지 않는다. 세로 범위 밖에서도 도킹하지 않는다. |
| 취소 | 포인터 취소·활성 화면 변경은 예고를 지우며 마지막 예고 위치에 창을 확정하지 않는다. 드래그 중 버튼·입력 조작이 시작되지 않는다. |
| 지도 최소 폭 | 고정된 모든 창을 제외한 실제 지도 중심 영역이 540px 이상일 때만 도킹한다. 옵션 하나만 뺀 폭을 보고 다른 고정 창을 빠뜨리지 않는다. 539px과 540px 경계를 각각 확인한다. |
| 충돌 | 같은 쪽에 조회·선택·순위 창을 연속 도킹해도 서로 겹치거나 소실되지 않는다. 하나가 이동·플로팅되는 규칙이면 안내와 실제 결과가 일치해야 한다. 반대쪽 합계 폭도 최소 지도 폭을 지킨다. |
| 해제·재열기 | 고정 창 제목을 끌면 같은 창이 플로팅으로 바뀐다. 접기→재열기는 마지막 유효 배치를 유지하며 화면 밖에 숨지 않는다. 조회·선택·순위별 입력과 창은 하나씩만 존재한다. |
| 크기 조절 | 좌우 도킹은 지도 쪽 경계선을 끌어 조절하고 방향키도 동일한 방향 의미로 동작한다. 플로팅은 가로·세로를 조절한다. 각 최소·최대 폭과 지도 최소 폭을 넘지 않으며 긴 제목과 정확값은 잘리지 않는다. |
| 좁은 화면 | 창들을 도킹할 공간이 없으면 강제 고정하거나 글자를 줄이지 않는다. 떠 있는 창의 제목·닫기·크기 조절은 화면 안에 남고 지도는 계속 사용할 수 있다. |
| 전체화면 | 전체화면 내부에서 열리는 창은 전체화면 포털에 있어야 한다. 불가능한 도킹 버튼은 이유와 함께 비활성 처리하고 나왔을 때 유효 배치로 돌아간다. |
| 비활성 화면 | 자료·장면 전환 뒤 이전 창·드래그 예고·키보드 이벤트가 새 화면을 가리지 않는다. 숨은 화면의 창을 키보드로 조작할 수 없어야 한다. |
| 값 보존 | 이동·도킹·크기 조절·배치 초기화 전후 같은 지역·시각·세분·후보·선택·색상 범위를 유지한다. 예: 20262 상권3001494 유동인구 8,284,977명은 배치와 무관하게 동일하다. |
| 초기화 범위 | 배치 초기화는 창 위치·폭·높이·도킹만 초기화한다. 조건 해제나 지도 조회 범위 맞춤과 혼동하지 않는다. |
| 배경 투명도 | 플로팅 배경만 50–100%로 조절하며 기본100%다. 글자·숫자·입력·버튼의 opacity는1을 유지한다. 부모 창 전체 opacity로 내용을 흐리게 처리하지 않는다. |
| 투명도 복귀 | 도킹 중 표면은100%로 고정한다. 다시 떼면 해당 창의 이전 플로팅 배경값을 복원한다. 조회·선택·순위 창끼리 값이 뜻하지 않게 동기화되지 않는다. |

현재 추가 기능은 구현 중이다. 이 절은 독립 수용 기준이며 실제 화면·공개 실행 통과 기록이 아니다. 중간 소스에서 다음 사항을 담당에게 전달했다.

- MapPanel의 포인터 취소를 놓기 확정과 분리해야 한다.
- MapPanel/MapWorkspace의 좌우 끝 판정은 세로 범위뿐 아니라 가로 작업영역 안 조건도 검사해야 한다. 바깥쪽 전체가 자석 영역이면 안 된다.
- MapWorkspace에서 두 플로팅 창의 위치는 각각 저장해야 한다. 하나의 `dragPosition`을 공유하면 다음 창을 옮길 때 먼저 옮긴 창이 원래 위치로 돌아갈 수 있다.

MapWorkspace의 고정 창 합산 후 지도540px 기준, 같은 쪽 충돌 시 기존 창을 플로팅으로 전환하는 구조, 취소 시 예고 해제는 중간 소스에서 확인했다. 수정 완료 여부와 실제 드래그·초점·값 보존은 통합 후 재검사한다.

재검토에서 MapWorkspace의 패널별 위치 저장과 작업영역 안쪽 자석 판정 수정을 확인했다. 지원 창 공통 기능에서는 작업공간이 아닌 자식 지도패널의 옵션 배치를 읽어야 예약폭을 정확히 뺄 수 있는 점, 다른 고정 지원 창의 폭도 합산해야 하는 점, 우측 순위 경계선의 방향키 방향을 반대로 적용해야 하는 점을 추가 전달했다.
